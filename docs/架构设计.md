# 架构设计

最后更新时间：2026-09-06

## 产品主链路

```text
手机 Web / 巡检任务
        ↓
rosbridge 受限网关 / carcar_inspection 状态机
        ↓
Nav2 Waypoint Follower ─────→ opennav_docking（低电或任务结束）
        ↓                                  ↑
Nav2 规划与控制                    D435 + AprilTag + 充电状态
        ↓
四轮麦克纳姆底盘接口
        ↓
Rosmaster 控制板：电机闭环、编码器、IMU、电池电压
```

## 包职责

| 包 | 当前职责 | 下一项改造 |
|---|---|---|
| `rosmaster_vendor` | 原厂 V3.3.9 Python 库，不改写 | 只在厂商协议变化时更新 |
| `carcar_base` | 当前可运行的 `cmd_vel`、控制板速度反馈积分、IMU、电压和诊断 | 保留为最小可用/回归入口 |
| `carcar_hardware` | `ros2_control` 串口 Hardware Component；目前四路仅为测试级原始状态/PWM | 接成四个标准轮关节，供麦克纳姆控制器使用 |
| `carcar_description` | 四轮模型、URDF、传感器静态 TF | 本轮按实测修正雷达、IMU、D435 和外廓 |
| `carcar_lidar` | RPLIDAR A1 Humble 驱动和独立测试 | 加入正式 bringup |
| `carcar_navigation` | SLAM、AMCL、Nav2 和 Waypoint Follower 配置 | 等里程计/TF通过后标定参数 |
| `carcar_algorithms` | 可复用视觉与感知算法 | 后续容纳桩位姿适配，不承载任务状态机 |
| `carcar_inspection` | 巡检、低电回充、告警、数据上报 | P2 后实现 |
| `carcar_bringup` | 各层启动编排 | 不承载协议、算法或业务逻辑 |

测试节点不得由正式 bringup 隐式启动；底盘串口始终只有一个所有者。

## TF 所有权

```text
map                         slam_toolbox 或 AMCL 唯一发布
└── odom                    首先由轮式里程计唯一发布；后期可选状态估计器
    └── base_footprint
        └── base_link       robot_state_publisher（URDF）
            ├── 四个 wheel_link
            ├── imu_link
            ├── laser_frame
            └── camera_link                     本项目只维护安装外参
                ├── camera_depth_frame          RealSense 驱动维护相机内参/内部 TF
                ├── camera_color_frame
                └── 对应 optical_frame
```

坐标遵循 REP-103：车体 X 向前、Y 向左、Z 向上；光学坐标由 RealSense 驱动发布，不在
URDF 重复伪造 D435 内部 TF。`base_link` 位于四轮轮心矩形中心且与轮轴等高，
`base_footprint` 位于其正下方地面。静态 TF 必须来自实测安装位，不允许用视觉占位值验收。

## ROS 接口边界

- 运动命令统一为 `geometry_msgs/Twist` 或 `TwistStamped`，只允许一个选定的速度仲裁出口。
- 导航使用唯一的 `nav_msgs/Odometry` 和唯一 `odom -> base_footprint`。
- 雷达发布 `sensor_msgs/LaserScan`；D435 使用官方驱动的 `Image`、`CameraInfo` 和
  `PointCloud2`；电池发布 `sensor_msgs/BatteryState`。
- Web 只通过业务服务/动作和白名单状态话题访问机器人；持续速度命令必须有超时，浏览器
  松手、切后台或断线立即归零。

## 关键决策

1. 正式底盘是四轮麦克纳姆，不再继续双轮差速方案。
2. 优先复用本机已安装的 `mecanum_drive_controller 2.53.3`，不自行重写运动学和里程计。
3. 控制板 `set_car_motion()` 作为现阶段可用链路；正式 `ros2_control` 适配完成后再切换，
   旧入口保留为回归工具。
4. 2D 雷达负责建图/定位和主要避障；D435 先服务自主充电近场视觉，不扩大为 3D SLAM。
5. Web 放在导航和回充稳定之后，避免 UI 掩盖底层状态不可靠的问题。
6. 状态估计分阶段推进：先验收纯轮式里程计，IMU 只发布不融合；基础导航稳定后，
   `robot_localization` 第一版只融合四轮里程计与校正后的 `gyro_z`，不使用 IMU 姿态、
   线加速度或磁力计。Madgwick、加速度和磁力计只在后续分别验证，不同时引入。

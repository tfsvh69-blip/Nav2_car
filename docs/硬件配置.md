# 控制板与串口配置

## 驱动来源

原始资料位于 `ROS控制板相关资料/py_install_V3.3.9.zip`。其中 `Rosmaster_Lib` 已原样解压到 `src/rosmaster_vendor/Rosmaster_Lib`，由 colcon 安装，不需要执行资料中的 `sudo python3 setup.py install`，也不会污染系统 Python。

底层库打开串口时固定使用 115200 波特率；ROS 参数 `serial_port` 默认是厂商建议的 `/dev/myserial`。

## 上车前检查

```bash
ls -l /dev/myserial
python3 -c "import serial; print(serial.__version__)"
groups
```

ROS 2 Humble 应使用 Ubuntu 22.04 的系统 Python 3.10。若终端启用了 Conda，先执行 `conda deactivate`，避免 CMake 误用 Conda Python 而找不到 ROS 系统依赖。

### VS Code 与 Python 解释器

当前 Jetson 的 ROS 2 Humble 解释器固定为：

```text
/usr/bin/python3
```

Windows 路径（例如 `F:\conda\env\python.exe`）不能在 Jetson/Linux 上使用。当前项目已在 `.vscode/settings.json` 固定系统解释器，并关闭 Python 扩展自动激活 Conda 环境。修改设置后，在 VS Code 中按 `Ctrl+Shift+P`，执行 `Developer: Reload Window`，再新建终端并验证：

```bash
cd /home/jetson/luhao/my_nav_carcar
command -v python3
python3 --version
python3 -c "import catkin_pkg, rclpy; print('ROS Python 环境正常')"
```

预期解释器为 `/usr/bin/python3`，版本为 Python 3.10。Conda 没有被删除，需要使用时可显式执行 `conda activate base`，使用完执行 `conda deactivate`。

命令中的 `/home/jetson/Desktop/your_script.py` 是示例占位路径，系统不会自动生成该文件。只能把它替换成真实存在的脚本路径；检查路径时使用：

```bash
ls -l /实际路径/脚本名.py
/usr/bin/python3 /实际路径/脚本名.py
```

若串口实际为 `/dev/ttyUSB0`，可先临时覆盖参数：

```bash
ros2 launch carcar_bringup robot.launch.py serial_port:=/dev/ttyUSB0
```

用户通常需要属于 `dialout` 组，修改组后应重新登录：

```bash
sudo usermod -aG dialout "$USER"
```

推荐最终用 udev 按 USB 设备的 VID/PID/序列号建立稳定的 `/dev/myserial` 软链接，不要长期依赖可能变化的 `ttyUSB0` 编号。先用以下命令查询真实属性，再编写本机规则：

```bash
udevadm info --attribute-walk --name=/dev/ttyUSB0
```

## 关键配置

编辑 `src/carcar_base/config/base.yaml`：

- `car_type`: X3=1、X3 Plus=2、X1=4、R2=5。
- `holonomic`: 麦克纳姆/全向底盘为 `true`，差速底盘为 `false`。
- `max_linear_*`、`max_angular_z`: ROS 侧二次限速，必须不超过原厂库范围。
- `command_timeout`: 指令失联自动停车时间。
- 电压上下限：只用于近似电量百分比，需按实际电池规格设置。

首次通电必须架空轮子，先发极低速度指令，确认正方向、急停方式与超时停车有效后再落地测试。

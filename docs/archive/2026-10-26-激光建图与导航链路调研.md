## 1. 先对齐当前输入与处理对象

本车是 RPLIDAR A1 二维雷达，驱动输出 `/scan`（`LaserScan`），建图使用 SLAM Toolbox，导航使用 AMCL 和 Nav2；D435 另有深度点云避障支路。用户本轮已明确：问题散点存在于建图网页二维地图，保存后仍在，因此本轮重点是激光生成的二维地图资产及弱特征错位。它与深度相机三维体素去噪是不同问题。

仓库证据：雷达入口见 [lidar.launch.xml](../../src/carcar_lidar/launch/lidar.launch.xml)，建图参数见 [slam_toolbox.yaml](../../src/carcar_navigation/config/slam_toolbox.yaml)，基础地图层见 [nav2.yaml](../../src/carcar_navigation/config/nav2.yaml)，深度层见 [nav2_depth_stvl_experimental.yaml](../../src/carcar_navigation/config/nav2_depth_stvl_experimental.yaml)。这些是配置事实，不证明某一现场时刻实际加载了哪个入口。

深度链确有 CPU PCL VoxelGrid 代码：[obstacle_voxel_grid.hpp](../../src/carcar_camera/include/carcar_camera/obstacle_voxel_grid.hpp) 对标障点做降采样，没有设每体素最少点数；清障射线不经过该函数。但联合会话从在线域 31 读回 `depth_cloud_filter` 的 `voxel_grid_enable=false`、`temporal_confirm_enable=false`，输入为 `/inspection/navigation/points`。所以必须区分“代码支持 PCL”与“在线已经启用 PCL”。离群点实验另有影子入口，不能由文件存在推断正在接管导航。

同次在线参数读回显示：全局 Nav2 包含 `static_layer, obstacle_layer, depth_stvl, inflation_layer`，本地包含激光、深度和膨胀层；深度 STVL 局部/全局配置衰减 2 s/5 s、标记开、清障关。因此深度配置已经接导航，但输入经过巡检状态门控；有插件不等于任意时刻相机点云都被放行。深度支路不参与当前二维 SLAM 建图，不能解释为此次保存地图散点的直接输入来源。

## 2. 地图旧障碍在导航时怎样处理

| 数据所在位置 | 固定版本机制 | 对本项目的含义 |
|---|---|---|
| 地图文件与 `static_layer` | StaticLayer 从 `/map`、可选地图更新消息取数据，再写入合成代价图 | 普通激光清障不会改 PGM，也不会自行编辑静态地图 |
| 激光 `obstacle_layer` | 先沿有效观测射线清空本层经过的格子，再标记新的障碍；默认合并方式为 `Maximum` | 本层能撤销自己之前的动态标记，但自由格不能压低静态层已有的障碍代价 |
| 旧 `VoxelLayer` | 依赖三维射线清障，普通体素没有按等待秒数自动过期的机制 | 新输入没有旧噪点，不等于旧占用立刻消失 |
| STVL | 用时间衰减管理体素；配置了有效清障视场时还可加速衰减 | 可管理深度障碍记忆，不会修复地图文件中的错误障碍 |
| `inflation_layer` | 围绕上游障碍生成距离相关代价 | 假障碍本体即使只有一格，也可能扩大成规划不愿经过的一片区域；应查障碍来源 |

依据：Nav2 1.1.20 [StaticLayer](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/plugins/static_layer.cpp)、[ObstacleLayer](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/plugins/obstacle_layer.cpp)、[CostmapLayer 的 Max 合并](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/src/costmap_layer.cpp)、[VoxelLayer](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/plugins/voxel_layer.cpp)、[STVL 2.3.4 说明](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/2.3.4/README.md)。上述行为适用于对应层；是否在实际运行必须核对实际插件和参数。

当前基础全局层顺序是 `static_layer → obstacle_layer → inflation_layer`，本地层没有 `static_layer`；在线 STVL 入口另加入深度层。同次在线读回激光 `combination_method=1`，即 Max。因此“保存地图中的假障碍仍挡住全局规划，局部激光看起来是空的”与该架构并不矛盾。Nav2 的清空代价地图服务也不承担编辑地图资产的职责。

**未看见与看见自由空间不同。** 清障需要新鲜、坐标变换可用、射线实际穿过旧障碍所在位置的有效观测。视场外、遮挡后方、超出清障距离、丢帧和无效测距都不能直接视为空地。本项目基础激光清障距离是软件配置的 3 m，不是已经证明所有材质、角度下都可靠的量程。`inf_is_valid` 上游默认 false，当前基础 YAML 没有显式设置；启用它之前须区分驱动真正无回波的 `+Inf` 与滤波剔除的 `NaN`，不能把未知测距统一变成清障射线。[对应回调及默认值](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/plugins/obstacle_layer.cpp)

建图模式则不同：SLAM 持续整合观测并重新输出占用地图，有机会修正占用判断；旧观测和位姿图仍参与结果，不能承诺再扫一次就会把旧障碍或错位整体消掉。AMCL 只估计车在既有地图中的位置，不修正地图几何。

## 3. 三组有工程价值的候选

### 3.1 二维雷达前端：原始输入、Speckle、Shadow 逐项对照

优先复用 `laser_filters`，保留原始 `/scan`，先输出单独候选话题，不直接接管运动。ROS Index 当前列出 Humble 的 `2.0.10`、BSD、维护状态 `MAINTAINED`；选型以固定标签 `2.0.10` 核对，不能直接抄 rolling 参数。[Humble 发布信息](https://index.ros.org/p/laser_filters/)、[固定包元数据](https://github.com/ros-perception/laser_filters/blob/2.0.10/package.xml)

- `LaserScanSpeckleFilter`：按邻近束距离或邻域半径判别稀疏离群读数，输入输出仍是 LaserScan，适合当前二维雷达接口。[固定实现](https://github.com/ros-perception/laser_filters/blob/2.0.10/include/laser_filters/speckle_filter.h)
- `ScanShadowsFilter`：根据相邻束形成的几何角度识别边缘拖尾、遮蔽效应候选；不能据此承诺处理玻璃、镜面或所有多径。[固定实现](https://github.com/ros-perception/laser_filters/blob/2.0.10/include/laser_filters/scan_shadows_filter.h)

本项目判断：第一轮比较“原始 / 仅 Speckle / 仅 Shadow”，路线、速度、地图分辨率与采样保持一致。检验空地伪点数量、真实细腿保留率、远距离墙角连续性、处理延迟与建图重影；不能只按散点更少选优。滤波太强会删掉真实小障碍及对扫描匹配有用的角点。候选还必须保留消息时间戳、角度序列及无效值语义，并验证安全链消费哪路数据。

不建议为了二维雷达噪点先把 LaserScan 转三维点云再转回来：既有原生库已经提供相关能力，额外投影增加时间与有效值语义的维护面。这是对当前接口的工程取舍，不是 PCL 能力不足。

### 3.2 建图栅格化：证据次数与占用比例逐项对照

SLAM Toolbox `2.6.10` 的 `src/slam_mapper.cpp` 默认声明 `min_pass_through=2`、`occupancy_threshold=0.1`。`getOccupancyGrid()` 将它们传给 `CreateFromScans()`，用于从已处理扫描生成二维地图，不是扫描匹配前端去噪开关。[固定 ROS 参数声明与调用](https://github.com/SteveMacenski/slam_toolbox/blob/2.6.10/src/slam_mapper.cpp)

Karto 统计光束经过栅格的 `pass` 计数与终止命中栅格的 `hit` 计数；有效命中端点会额外增加 pass 与 hit。`UpdateCell()` 先要求严格 `pass > min_pass_through`，再用严格 `hit/pass > occupancy_threshold` 判占用，否则自由；次数不足保留未知。这不是“连续三帧看见才算障碍”，单帧多束也能贡献计数。[固定 Karto 实现](https://github.com/SteveMacenski/slam_toolbox/blob/2.6.10/lib/karto_sdk/include/karto_sdk/Karto.h#L5833)

提高 `min_pass_through` 同时推迟自由与占用判定，可能增加未知格；提高占用比例门槛会减少低命中比例的障碍，也可能消掉细腿、远处或边缘。两者影响还依赖分辨率、轨迹和观测次数。它们只能改变占用判定，不能修正已经错位的位姿图。候选验收应保持 5 cm 分辨率，先读回实际参数，再分别对照默认与一个有依据的改值，记录误占用面积、未知面积、最小真实结构保留率和重建耗时；不在本轮直接部署改值。

### 3.3 地图层：二维去小簇与三维记忆分别验证

Nav2 `DenoiseLayer` 在 `1.1.20` 已存在，不应笼统写成“仅新 ROS 可用”；该文件为 Apache-2.0。它按二维 4/8 邻接去小障碍组，默认组大小阈值 2；适合在障碍层之后、膨胀之前做候选对照。它不编辑 PGM，也不清空 STVL/VoxelLayer 内部三维记忆，并可能删除真实细腿投影。[固定实现](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/plugins/denoise_layer.cpp)

STVL 固定 `2.3.4`、LGPL-2.1，提供体素时间衰减与视场内衰减加速；作者报告零售、仓库等公开应用，但不是本项目实车验收或认证。[官方说明](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/2.3.4/README.md)

待讨论取舍：本次已确认是保存地图散点，Denoise 只适合作为导航合成图的候选补充；生产地图发布前仍应检查原地图与真实细结构，生成独立候选副本并保留原图，不能因显示更干净就覆盖地图及位姿图。深度 STVL 另按“目标在场持续保留 / 撤障后释放 / 遮挡及掉线不误放行”验收。不能靠加快衰减掩盖输入假点。局部/全局记忆时间不等于墙钟下严格的删除时限，还受更新周期与再次观测影响。

## 4. 弱特征错位应保留当前 SLAM 逐层改进

SLAM Toolbox 2.6.10 已有扫描匹配、Ceres 图优化和回环，不是缺少一个 ICP/PCL 开关。回环是“确认回到已知区域后把多段观测联合校正”；它依赖正确数据关联，不能保证修好所有已经错叠的地图。仓库 `do_loop_closing=true`，且已有 3 m/6 m 范围候选与 Cauchy 候选，后续应复用这些分离入口，不同时叠加。

1. **先固定航向、时间与实际有效量程。** 先排查纯轮式转角、打滑、雷达安装 TF、激光扫描时间和数据迟延。是否扩到 6 m 用同路线重复对照；远处出现可辨认墙角才可能增加约束，更多噪声或重复墙线未必有帮助。
2. **保留有依据的地图更新。** 栅格化参数单独按 3.2 节对照；原始扫描、位姿图和输出地图一起留存，避免只清理图片后丢失真实成因。
3. **把输入健康与几何可信度分开。** 话题新鲜只证明数据在到达。长平行墙、空旷区或重复门口会导致多个位姿都能解释扫描；应结合方向分布、匹配连续性、真实回访偏差、必要的独立航向信息评估。发现不可信时停止运动、暂停将新扫描写入地图，保留最后可信检查点；恢复后须避免大段空白里程计把新扫描硬接回旧图。该门控为待实现/待验收的项目方案，不能宣称已具备完整退化检测。
4. **鲁棒损失只处理部分错误约束。** 2.6.10 的 Ceres 插件支持 None/Huber/Cauchy，后两者固定尺度 0.7；它们减小不一致残差的影响，无法补出走廊方向缺失的几何信息，也可能削弱有效大修正。[固定求解器](https://github.com/SteveMacenski/slam_toolbox/blob/2.6.10/solvers/ceres_solver.cpp)
5. **剩余不可观测性再增加真实约束。** 可辨认的固定地标、可信航向等需按既有底层门槛逐项引入；雷达扫描平面必须真的能观测该地标。轮式基线未验收前不接入 IMU；后续只先评估校正的陀螺 Z，遵守本项目既有顺序。

FAST-LIO2 面向三维 LiDAR 与 IMU 紧耦合里程计，官方输入要求、时间同步与逐点时间等假设不同；当前 A1 LaserScan 不是它的直接替换输入。它不作为本次三选一候选，也不能把改换算法名作为现有地图错位的修复。[官方项目说明](https://github.com/hku-mars/FAST_LIO)

## 5. 面向成品的地图与任务业务边界

待产品访谈决定的候选是“稳定定位底图 + 动态避障层 + 受控地图更新”。底图保存建筑结构；临时人、车、箱子留给动态层；长期环境变化在专门维护会话中采集，生成候选版本，完成质量检查及固定路线回归后才发布，支持回滚。原始数据、位姿图、占用图、参数和巡检点绑定地图版本。这是建议，尚未批准为唯一产品模式。

SLAM Toolbox 提供保存/加载位姿图、多会话继续建图和定位模式；但 2.6.10 README 对删除旧节点的 true lifelong 实现明确标为高度实验，相关源码也放在 `experimental` 下，且文件头许可证声明与主包 LGPL 不同。不能据此直接承诺无人审核的在线地图长期修改已经成熟，也不能将整个仓库统一按主包许可证处理。[固定版能力与限制](https://github.com/SteveMacenski/slam_toolbox/blob/2.6.10/README.md)、[实验文件声明](https://github.com/SteveMacenski/slam_toolbox/blob/2.6.10/src/experimental/slam_toolbox_lifelong.cpp)

持续重定位、正常导航重规划与改图是三个业务：重定位改车的位置估计，重规划改路径，改图改环境资产。永久障碍的撤销应由多次可见的自由空间证据、定位可信度和维护审核决定，不能根据一次“没有回波”删除。地图变形/坐标变更后，原巡检点与禁行区须复核；不能只换地图图片就继续沿用所有目标。

建议的阶段验收项是：原始数据与图层可追溯；散点来源能复现；输入去噪不降低最低目标检出；受控撤障释放可量化；弱特征异常能及时停止污染地图；候选地图能回滚；固定路线重复定位、导航、取消、停车、到点采集和失败恢复通过。具体阈值应依据车速、制动距离、场地通道与最小障碍规格确定，本文不把候选阈值写成已达成的产品指标。

## 6. 深度支路的相关资料边界

已有 [2026-10-01 深度调研](2026-10-01-深度离群点与清障机制调研.md) 对 PCL 半径离群点、VoxelGrid 和 RealSense 滤镜作了比较。PCL `RadiusOutlierRemoval 1.12.1`（BSD）按三维邻点数量去孤立点；VoxelGrid 单纯降采样会保留只有一个点的体素。它们处理深度云，不能消掉已经存进二维激光地图的散点。[固定 ROR](https://github.com/PointCloudLibrary/pcl/blob/pcl-1.12.1/filters/include/pcl/filters/radius_outlier_removal.h)、[固定 VoxelGrid](https://github.com/PointCloudLibrary/pcl/blob/pcl-1.12.1/filters/include/pcl/filters/voxel_grid.h)

本轮仅新增调研文档，未部署上述候选，未覆盖既有地图和参数，未改变当前巡检/导航业务。后续实施仍须在对应测试编号下登记离线与实机结果。

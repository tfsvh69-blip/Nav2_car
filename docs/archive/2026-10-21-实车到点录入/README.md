# APP-001-R7 实车到点录入的软件验收

2026-10-21用户纠正默认流程：先下发候选停车目标让车导航过去，再依据实车结果调整位置／车头与俯仰，最后试拍保存。R6静止入口不能代替这条链路。本轮实现此流程并更新网页；**以下导航到达、坐标偏差和照片结果均来自隔离域227替身，不是实机运动验收**。完整有效操作见[手册35.6](../../操作手册.md#356-先导航到点再按实车结果录入app-001-r72026-10-21)。

实现：新增单点到达／取消接口和独立`enable_goal_navigation`开关；复用现有Nav2、94档回位、深度新鲜度和图层重建门槛，按请求去重。到达成功还须确认停车；取消／断网页保持停车，未确认取消则锁停。候选目标与实车定位估计分开记录，参考照片包含本次导航目标／请求编号；改变候选坐标后，前端要求重新导航。整轮任务默认开关及独立执行规则不变。新增／修改车端逻辑为C++，Launch为XML。

网页：准备车辆、录入巡检点、安排巡检、任务进度、照片与记录；初始定位表单与候选目标表单分开。主流程按选目标、导航、实车微调试拍、保存组织，到点后按钮引导到相机区。规划草图、遥控、草稿和外部上传状态收在次要入口。参考照片独立于正式巡检照片，均可直接查看下载，不把车端保存说成外部上传成功。

验证证据：

- [最终目标包构建](goal-build-complete.txt)及[报警修复构建](goal-alarm-build.txt)通过，保留既有GCC ABI说明和libdatachannel头文件警告。
- [最终巡检回归](goal-inspection-tests-accepted.txt)：17项核心和12项控制台用例，共29项通过；含真实Chromium、单点到达、取消后再导航、断开网页取消、默认关闭、旧图层不能放行及原整轮巡检／最终停车。
- [新单点专项](goal-focused-tests.txt)：6项通过。其中目标X=1.30m、替身实际X=1.33m，断言保存1.33m并另存1.30m候选，验证没有用目标冒充实车反馈。
- 浏览器实际点击：地图草稿／任务读回、确认行驶姿态、下发1.30m目标、改为1.35m后重新导航、调角新帧确认、保存及打开“照片与记录”解码参考图；平板与手机无页面异常或横向溢出。截图为[平板](tablet.png)、[手机](phone.png)，测试地图20×20格／0.1m每格、白色空闲，灰色RGB来自32×24均匀替身图像，不是相机现场画面。截图缩放不代表物理精度。
- [网关回归](goal-mapping-tests-final.txt)：28项逻辑与13项HTTP，共41项通过，包含同端口`/inspect/`本地HTTP／WebSocket和原8080转发行为。网页6项单测及生产构建通过；XML及Launch参数展开、JS语法和差异检查通过。

失败与修正保留：[首次结果](goal-inspection-tests-first.txt)、[第二次完整结果](goal-inspection-tests-final.txt)。首次浏览器因旧共享HTTP默认8081上游读到了实机网页，在选择testmap时即失败，未发硬件操作；修正为当前控制台端口，HTTP／WebSocket前缀在本端口直接重写，避免单工作线程自转发死锁。首次新单点用例还发现顶层缺参考照片索引，已由主停车位的参考同步到返回点位，并增加缺字段断言以避免测试直接崩溃。

完整回归两次发现导航故障三秒报警分别触发3／2轮，而单项可通过。根因为报警截止时间在“待终态检查”和“输出清理”之间跨越，清零截止时间后下一帧把同一故障当首次报警。现在单独锁存本次报警已启动标志；[专项连续三次](goal-alarm-repeat.txt)均通过，随后完整回归通过，不把前两次失败改写为成功。

实机交付：控制台与STANDBY网关已正常重启加载新版本，R6底盘／相机／雷达／模型／定位进程保留，原地图／点位／参数／系统定义不变。运行中保持`enable_goal_navigation=false`、`enable_navigation=false`，无本轮非零速度或新的舵机初始化。真实定位待初值、扫描新鲜度未通过；用户此前只确认静止隔离条件，尚待落地／动力／现场状态确认。外部云端、本次实车到点、实体角度／回位、实际定位误差、物理停车与整轮巡检均未验收。

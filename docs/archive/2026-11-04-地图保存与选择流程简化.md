# NAV-018-MAP-SAVE-DEMO-001：地图保存与选择流程简化

2026-11-04用户反馈建图效果不好但希望保存，页面出现“审核并发布／标记未通过／启用已发布地图”，巡检地图下拉看不到新图。本轮将 demo 的操作收敛为保存、查看、巡检选择载入；不删除既有地图，不修改历史诊断事实，不代发实车运动。

## 根因与原始证据

用户工程 `20261104_103644_7f59cba3` 的 `complete/grid_saved/graph_saved` 均为 true，map.yaml、map.pgm、graph.posegraph、graph.data 四项资产 SHA256 全匹配，文件已完整保存。该轮发生定位／地图质量异常，manifest 的 diagnostic_only=true，publication.status=diagnostic。

旧巡检目录复用 navigation_map_visible，只显示 legacy 或 published，完整 candidate 和 diagnostic 全被隐藏。只读 C++ 复现读取该真实工程得到完整性通过、目录不可见并退出1；巡检HTTP仅返回9张旧图。地图文件保存成功与人工审核／导航资格被绑成一个操作门槛，是截图中不能继续操作的直接原因。任务结束后实时地图清空，旧网页又没有保存文件预览入口，因此显示空白。

保存本身已有原子新目录与资产校验，本轮继续使用，不重写SLAM或地图存储。Nav2 1.1.20官方将保存和加载分为独立接口，SLAM Toolbox 2.6.10同时保存栅格和可续建位姿图；两者均不要求本项目额外的人工发布工作流。来源：[Nav2 1.1.20](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_map_server/README.md)、[SLAM Toolbox 2.6.10](https://github.com/SteveMacenski/slam_toolbox/blob/2.6.10/README.md)。保留现有依赖与许可证，不新增第三方依赖。

## 最终行为

- 建图页面只提供“已保存地图”选择与预览、“刷新列表”和“前往巡检”，移除审核输入、发布、拒绝和单独启用操作。保存终态统一说“地图已保存”。
- 正常完整地图保存后即可在巡检选择载入，兼容历史 candidate/published/legacy；新正常保存记录为 saved，不再要求人工审核。旧审核接口仅保留兼容，页面不依赖。
- 完整异常地图同样列出，明确标注“建图异常，可查看”，允许配置模式查看和编辑点位；其真实车辆准备及导航仍拒绝，保留质量原因。没有把诊断资产改成正常或伪造发布通过。
- 新增受控只读PNG预览接口，校验工程ID、资产哈希与图片引用根路径，不改变实时地图、定位、任务或运动。历史预览显示 map 坐标系、每格厘米数和比例尺，不叠加旧车辆、路径或激光。
- 巡检后台每秒检测目录变化并缓存未变资产，控制循环仅读快照，不承担位姿图SHA计算。建图页待命列表每5秒更新，保留人工选择，优先显示本次新保存地图。前往巡检会带入选择，不自动载入或准备车辆。
- 迟到图片、快速切图、新任务切换、缺失／损坏文件均有对应反馈；文件完整和导航资格分别表达。

新的位移基准只在首个有效编码器到达后建立，不比较“未测量的零坐标”。单独测试先延迟编码器1.5秒、首次读数x=1米，静止3.5秒保持健康；随后真实模拟位移0.2米且不产生新扫描接纳，仍进入FAULT。原0.15米／3秒等保护门槛未放宽。

run7后的计时修正：3秒从真正跨过0.15米位移门槛开始，静止／原地调头不预先消耗等待窗口；发生新接纳、回环或未达到门槛时重新核对基准。新增断言先红：静止等待后跨过门槛的0.4秒内不应误锁；随后持续无新接纳，3秒后仍必须FAULT。原始／过滤扫描及编码器的0.5秒新鲜度和近场保护不变。遥测补足轮式基准、当前轮式坐标、位移及等待秒数，便于区分初始化、节流和真实拒绝。

run10日志分别出现follow_path及compute_path_to_pose应答超时，不能误记为规划路径不可达。按本机Nav2 1.1.20的`bt_action_node.hpp`及`bt_action_server_impl.hpp`核对，`default_server_timeout`单位为毫秒，默认20；新组合改为1000，覆盖内部Action握手及取消响应等待。传感器0.5秒、手动运动签发300毫秒、取消终态5秒、进展30秒及探索／返程预算不变。实际读回在`rpc_timeout_readback.txt`；插件和速度读回在同目录对应文件。

中断检查在STARTING期间发送Ctrl+C，脚本明确失败为“操作者中断隔离测试”并回收自己创建的网关、软件房间和浏览器，18098不再监听；随后能独立启动下一轮，证据为`interrupt_check/`。这是预期中断，不是正常闭环成功。部分失败录包含QoS兼容警告，不宣称每轮所有话题都全程录制；通过依据为真实HTTP事件、ROS状态、Action终态与保存校验。

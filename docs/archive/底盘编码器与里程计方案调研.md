# 四轮麦克纳姆控制与里程计方案

最后更新时间：2026-09-07

## 结论

正式目标已由早期双轮差速修订为四轮麦克纳姆。用户明确选择 Rosmaster X3
控制板内置闭环：ROS 发送车体 `vx/vy/wz`，控制板固件完成麦克纳姆分配和
编码器 PID。历史直接 PWM 及 Jetson 侧四轮 PWM PI 只保留回归。

本机 `mecanum_drive_controller 2.53.3` 仍保留为后备调研结果，但它输出四个独立
轮速，当前 V3.3.9 控制板 API 未暴露四轮独立闭环目标，因此不接入当前正式链路。

## 已确认输入

| 参数 | 当前值 |
|---|---|
| 轮半径 | `0.030 m` |
| 轮宽 | `0.031 m` |
| 前后轮心距 | `0.120 m` |
| 左右轮心距 | `0.185 m` |
| 控制器运动学参数 `x+y` | 初始几何值 `0.060 + 0.0925 = 0.1525 m`，地面标定后修正 |
| 左前 | M1，机械正转命令符号 `+1` |
| 右前 | M3，机械正转命令符号 `+1` |
| 左后 | M4，机械正转命令符号 `-1` |
| 右后 | M2，机械正转命令符号 `-1` |
| 编码器 | 四路累计计数、独立反馈、约 25 Hz 已确认；精确 count/rev 待测 |

## 当前软件现状

- `carcar_base` 已能调用控制板 `set_car_motion(vx, vy, wz)`，并读取控制板回传速度、IMU、
  编码器和电池电压；该入口已选为正式底盘。
- `MOTOR-006` 的后轮反转是因为当前 M2/M4 端口轮位与原厂 X3 定义互换。
  启用固件闭环前先交换两个整套插头，不从软件强行反号。
- `carcar_hardware` 的四轮模式目前只暴露原始 `encoder_count`、`encoder_velocity` 和测试级
  `motor_pwm`，还不是导航可用的四个标准轮速度接口。
- `nav2.yaml` 已按全向模型预置，但当前 `/wheel/odometry` 尚未完成独立的地面尺度验收，
  所以不能因配置文件存在就认定 Nav2 已可用。

## 最小实现路径

1. 断电交换 M2/M4 整套电机+编码器插头，使轮位符合 X3 原厂约定。
2. 用 MOTOR-007 隔离入口先架空验证一次前进短脉冲，任一轮异常立即断电。
3. 架空通过后再落地验收前进、左横移、逆时针旋转和 `0.3 s` 超时停车。
4. 使用控制板回传的车体速度建立纯轮式里程基线；关闭其他里程计 TF 发布者。
5. 用直行 1 m、横移 1 m、旋转 360° 校准有效半径和转动几何，只调到满足室内导航，
   不追求实验室级轮胎模型。
6. 第一版只使用四轮反馈发布正式里程计与 `odom -> base_footprint`，IMU 继续独立发布，
   不接入状态估计器。
7. 纯轮式里程计和基础导航稳定后，`robot_localization` 第一版只接入四轮里程计与经过
   零偏、单位、坐标轴和符号校正的 `gyro_z`；IMU 姿态、线加速度和磁力计全部关闭。
8. 只有上一阶段实测稳定且确有收益时，才分别评估线加速度、Madgwick 和磁力计，不在
   同一轮调试中一次性加入。二维地面导航默认不融合线加速度。

## 验收门槛

- 三种车体动作方向正确，松开命令后在超时内停车。
- 四轮状态时间戳新鲜，静止时速度回零，断开编码反馈时停止输出并报错。
- 同一路面重复 1 m/360° 测试的误差足以让 Nav2 局部规划稳定，不以单次完美数值为目标。
- `map -> odom -> base_footprint -> base_link -> sensors` 全链路无断裂和重复发布。

早期双轮差速研究和测试过程继续保存在[测试记录](../测试记录.md)，仅作为历史，不再指导实现。

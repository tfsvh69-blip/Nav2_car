# APP-001-R12：网页单点失败与图层修复

日期：2026-10-25，北京时间。完整构建、测试、观察、停止与恢复统一见[手册35.10](../../操作手册.md#app-001-r12-operation)，当前结论见[测试记录](../../测试记录.md#app-001-r12)。这里保存原始证据，不作为独立操作入口。

## 现场目标失败

网页请求`830649954367978b184ff2d2c2fb2697`已进入Nav2，目标约为`(-4.573,-1.047,1.628)`，yaw单位为弧度。14:21:50从定位估计`(-1.26,-0.12)`开始规划；三次规划均报告`Starting point in lethal space`，14:22:07返回ABORTED。不是网页未提交，也不是上位机排队超时；本次没有生成全局路径／局部跟随路径。

用户随后确认：刚才提交初始定位时，标的不是实车当时实际所在位置。当前估计点在保存图格子`(97,174)`，静态图灰度为0（黑色占用），全局代价图像素为红色高代价。软件定位检查通过不构成实物位置正确的证据；须现场重新标真实位置与车头，不能修改目标或关闭障碍层掩盖起点问题。

Nav2曾请求受控倒车恢复，日志中的该段轮式位移为0；这只证明该记录中的反馈推算，未以日志替代实物运动观察。失败后`motion_held=true`、目标inactive；本轮诊断未重发导航、初值、角度或速度命令。

## 网页缺陷与回归

实际代价图接口有颜色，全局37111个可见像素、局部529个可见像素。根因是`App.vue`的主地图`draw()`只画底图／标记，图层绘制误放在`planDraw()`，因而状态有数据而主录入画面没有代价区域；同样会漏画成功生成的路径。

先在现有真实浏览器回归中增加两张非空代价图和两条路径的隔离ROS替身数据，逐项断言主canvas的实际像素及勾选隐藏，原版在第一项4秒超时。随后提取共用`drawNavigationLayers()`，主地图与规划页复用；修复后浏览器完成全部像素断言和原有平板／手机导航、调角、保存流程。

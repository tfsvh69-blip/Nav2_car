# 自动建图折返、抽搐与快照故障诊断

日期：2026-10-30，NAV-018-R23。已完成取证，并在原授权范围内局部修复输出误归零与扫描时间配准；算法／核心流程方案待阶段确认。构建与离线回归结果见文末追加。未启动硬件、未发送实车目标；原始录包、地图、既有未提交改动与系统配置均保留。完整复核入口见[操作手册39.18](../操作手册.md#nav-018-r23-operation)。

## 1. 已确认的三项问题

| 问题 | 实际证据 | 结论边界 |
|---|---|---|
| 减速时抽搐 | 平滑器线速度相邻消息最大变化0.010m/s；最终速度出现约50ms的非零／零交替；真实监督器隔离反例连续两次失败，每次约2秒 | 已复现软件误归零，不能把软件命令变化等同于实测车体加速度，也不能排除其他机械问题 |
| 到点不连续 | 10次成功到点至下一次实际目标派发，间隔2.199～14.239秒，合计59.360秒 | 已确认目标空窗；包含选点、等待地图及快照停车，尚未逐项分摊全部耗时 |
| 最后突然故障 | 11:24:42目标成功后停车保存快照，11:24:48几何校验失败进入FAULT；用同一地图和阈值、将位姿推进至扫描时刻后，31帧全部由拒绝变为通过 | 此轮拒绝存在时间错配的可复现解释；不是全场地图质量或恢复可靠性的验收 |

“观测目标”是车辆导航经过的点；“可信检查点”是恢复用的地图／位姿图快照。两者在程序中不同。当前实现把两者通过“成功到点且距上次快照≥30秒”关联，并在连续运行90秒时主动停车。因此，现行策略没有实现用户所要求的连续扩图。

本轮所查录包中的栅格自由面积从约8.615m²增加到66.592m²；这是SLAM栅格统计，受地图校正影响，不是真值覆盖率。它说明本轮确实增加了已知空间，不能据此登记探索高效、无重复或全场覆盖通过。

## 3. 抽搐：平滑后的输出被异步反馈比较重新置零

`supervisor.cpp`最终出口在防撞反馈与当前输入同向、但反馈幅值略大时，将该分量直接设为零。防撞反馈经过独立话题，正常就可能晚一拍；减速时，旧反馈大于新输入不代表防撞模块实际放大了速度。

|---|---:|---:|
| 1793330682.144668 | 0.103847 | 0.103370 |
| 1793330682.192426 | 0 | 0 |
| 1793330682.242747 | 0.099062 | 0.093496 |
| 1793330682.292698 | 0 | 0 |
| 1793330682.343065 | 0.096091 | 0.087577 |

同一窗口平滑输出连续减速。隔离真实监督器测试持续输入0.06m/s，并回传晚一拍的同向0.07m/s；程序持续输出零，期望的“保持不超过0.06且不误停车”断言失败。`gate-red.log`与`gate-red-repeat.log`两次结果相同。该反例验证实际监督器调用链，没有用独立重写的门控函数代替生产逻辑。

本轮局部修复：同向反馈只裁剪到当前输入幅值；反向、真正防撞零输出、传感器过期、取消／故障等继续按原规则归零。增加真实监督器回归覆盖减速迟到反馈、零防撞、反向反馈及正常防撞减速；原输入零与超时门保持。没有取消最终安全门或延长底盘超时。验证结果见文末。

本轮最终`/mapping/cmd_vel`最大录包接收间隔约64.3ms。该证据有利于把当前反复误归零与历史0.3秒底盘断流区分，不能排除所有通信、调度或物理反馈问题。

## 4. 最后故障：位姿与扫描时间错配

直接状态链：EXPLORING → 11:24:42.744 STOPPING → 11:24:43.194 CHECKPOINTING → 11:24:48.445 FAULT。最后一个Nav2目标在11:24:42.653已成功，故障原因原文保留为：

> 近期检查点生成失败，保持停车保存证据：检查点当前激光与栅格残差／重叠不通过，拒绝提升可信检查点

`recovery.cpp`保存完成后，对当前`scan_`和最后`pose_`直接评分，没有把它们配到同一时间。SLAM接纳有移动门槛；停下后仍有新扫描，但`/pose`可能继续保留上一次被接纳扫描的时刻。冻结入图后直接查询当前时刻的`map→base_footprint`也可能因SLAM TF停止更新而外推失败，不能仅改成“取最新TF”就认为已经修好。

在1793330688.2437975这一录包时刻，最后`/pose`已约7.137秒未更新。用同一轮式TF推进到扫描时刻，位姿推算修正约0.09595米。两种输入都调用原生产评分器：

| 指标 | 原最后SLAM位姿 | 按轮式TF推进至扫描时刻 | 原阈值 |
|---|---:|---:|---:|
| 有效抽样回波 | 77 | 77 | ≥50 |
| 平均残差 | 0.129385m | 0.014880m | ≤0.10m |
| 支持覆盖比例 | 0.883117 | 1.000000 | ≥0.80 |
| 命中比例 | 0.584416 | 0.987013 | ≥0.70 |
| 自由射线冲突 | 0.009740 | 0.012987 | ≤0.08 |
| 校验结果 | 拒绝 | 通过 | 不变 |

同一窗口31帧：原方法0/31通过，时间对齐后31/31通过。`trace-propagated.json`与独立重跑结果一致。这是对实际录包的离线单变量验证，不是实车恢复通过，也没有宣称原快照请求在生产程序中已修复。

本轮局部修复：在原冻结快照事务内，使用`pose_at_scan`通过精确历史轮式TF获取扫描时刻位姿；时间顺序、坐标系、两时刻轮式TF及结果有限性必须有效，不回退到最新TF。每次收到SLAM位姿即保存对应时刻轮式TF，若话题先到则由定时器重试精确时间查询；停车很久也不会因该历史端滑出缓存而误拒绝，缓存必须与当前位姿时间／坐标系严格匹配。未取得的历史或当前扫描时刻TF仍拒绝。原事务代次及冻结门保持，几何失败追加全部评分数值。直接调用该生产函数重放31帧仍全部通过。后续完整连续快照方案还须明确跨坐标代次限制及更完整的配对元数据；此轮没有放宽几何阈值或改变失败停车流程。

## 5. 折返与到点停顿：现行探索能力边界

已核对当前实现：

- `Explore::makePlan`遇活动目标即返回；没有提前准备下一安全目标或连续路径。
- 成功后必须等更新地图，再等周期选点；当前生产`planner_frequency=1Hz`。监督器完成operation后自动输出零。Nav2 1.1.20的单点控制成功路径本身也会发布零命令。
- 前沿评分沿用`距离权重×最近距离×分辨率−收益权重×前沿格数×分辨率`。当前距离权重0.001、收益1.0，方向惩罚0.8；跨簇排序仍很容易由前沿长度主导。前沿长度是未知收益的代理量，不能等价为从该观测点实际能新增的地图面积。
- 已访问点只保留半径0.40米、冷却60秒的有限记忆，未建立持续的区域访问／新增信息台账；闭环后为坐标安全清理旧代次记忆也会降低跨阶段连续性。不能直接删除这一坐标安全处理。
- 本轮10次成功到点后的目标派发空窗合计59.360秒；最短2.199秒，最长14.239秒。0.3秒是诊断工具的空窗观察阈值，不是新增生产参数或充分的“不停车”验收标准。

以上确认当前结构不具备连续探索路线能力；要把每次南北切换归因于某个候选得分，仍需保存同一时刻所有候选、真实可达路径代价、收益、访问状态及选择原因。不能仅凭方向变化判断一次折返错误：穿门、绕障、探索支路都可能需要回到已知空间。

## 7. 待批准的实施阶段与验收

两项局部缺陷沿用既有建图授权完成修复。依据仓库AGENTS.md“重大修改按关键阶段确认”，探索依赖替换及核心流程重构需要确认总体方案和后续关键阶段，不能把本报告视为阶段B／C已获批准。

1. **阶段A：本轮已完成两项局部缺陷修复与离线验收。** 修复最终输出同向反馈误归零、快照扫描／位姿时间对齐；记录完整几何失败分数。原制动／碰撞零输出、超时、取消、净空、IMU观察路线保持。原真实监督器红测变绿且安全反例通过；31帧历史对照锁定，时间／坐标不符、未取得的历史和当前TF缺失仍拒绝。正式构建与50项回归结果见下节；不改探索算法，不发实车目标。
2. **阶段B：连续探索的核心流程与候选依赖。** 固定评估上述Apache-2.0排序模块，先用录包和走廊／相连房间软件场景比较原方案；以真实可达代价、可观测未知收益、稳定区域记忆及有限前瞻选点。在临近当前点之前准备下一段有效路径，复用Nav2多点／路径更新，不以完成一个独立单点再启动另一个作为连续通过的实现。按地图版本、坐标代次和请求ID处理迟到结果；没有已验证续接路径时安全停车。快照更新应独立安排，现行30秒到点停车／90秒主动停车策略须一并评估；若要保证更长不停顿，必须先解决一致快照或明确可接受的维护停顿，不能只删除停车而保留旧快照年龄约束。验收包含覆盖增长、重复访问比例、目标空窗、最终速度变化、取消／障碍／断流和快照失败分级；与原版使用相同场景、速度、预算，不能只跑插件单测。
3. **阶段C：部署与受看护实车复验。** 软件阶段通过后另行确认加载新版及实车范围；默认0.10m/s，从短段连续过点、停车与回位开始，之后独立进行走廊／房间重复轮次。记录实物抽搐、地图几何与覆盖、停车距离、故障恢复和返程；未达到安全续接条件不承诺全程不停。

可恢复方式：局部修改仅涉及同向幅值裁剪、快照位姿配准及对应测试；恢复时只反向应用本轮补丁，不以git reset覆盖用户其他改动。重构前另存未提交工作区的独立快照与目标二进制。新算法保留独立实验入口、原explore_lite和原地图／录包；离线阶段无系统配置更改。阶段B不通过就保留原入口及失败证据，不部署未经验证的替换。

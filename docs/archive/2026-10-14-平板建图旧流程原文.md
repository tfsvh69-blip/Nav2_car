## 33. 平板随行建图（NAV-017）

### 33.1 范围、画面与安全边界

终端归属：本章ROS与维护命令在车上Jetson执行，预备电脑用于SSH，平板用于浏览器。电脑新开的终端仍在电脑上，未登录车端前不要直接执行Jetson工作目录命令；原局域网SSH入口沿用第19节。

适用：当前小米平板6、小车与电脑都连接“小泽WiFi”，操作者随车、始终看得见车辆，仅在现有WiFi覆盖内的同一楼层走廊、房间和大厅低速人工建图。终端负责出发前的新建/续建选择；网页负责实时看图、遥控、任意位置续建提示与保存。2026-10-14用户取消本阶段热点工作，热点资产仅保留备用。平板兼容、实际覆盖、实物方向、相机帧率、起步和停车距离必须由现场反馈确认。

地图来自雷达与纯轮式里程计，统一在`map`坐标系俯视显示；黑色占据、白色空闲、灰色未知，5 cm/格，双指缩放只改变显示比例。白色只反映激光扫描平面的观测，不代表各高度都无障碍。红点为当前激光经TF转换后的投影，蓝色车位图标是软件估计和朝向示意，不是实物外廓或定位真值；黄色箭头为人工续建初值。RGB独立窗口是相机前方透视视场，640×480是像素数，不是物理范围，不能与俯视地图逐像素对照。地图约3秒更新，车位/扫描预览目标10/5 Hz，视频目标5～6 FPS；分别显示年龄，动画顺畅不等于匹配质量合格。

本入口无Nav2、AMCL、STVL、IMU融合或自动避障；SLAM仍使用软件截取的3 m激光，不是雷达硬件极限。大厅无固定结构或重复走廊匹配异常时先停车，不直接放大参数。所有旧底层入口保留。本次底盘仅订阅`/mapping/cmd_vel`，旧键盘公共`/cmd_vel`不进入该底盘。

初始零速、松手/换档/保存/断联/后台/视频过期停车，重连后重新使能。慢档命令上限0.05 m/s、0.10 rad/s，常档0.10 m/s、0.20 rad/s，均为独立试验参数。门控20 ms检查、0.20 s授权和既有底盘0.30 s看门狗只是软件保护，不是物理停车距离/硬实时保证。异常运动直接断开12 V轮动力；退出网页不能代替确认车轮停止。底盘启动会发送S1=94，支架可能旋转，须先清空扫掠空间并观察实物，不能把命令94当实际角度。

#### 33.3.1 只接RGB相机到现有网页（不启动底盘）

本入口用于软件预览已运行、平板页面可达后，单独查看D435真实RGB画面。当前只读检查相机未被占用后再启动；禁止与RealSense Viewer、其他相机入口或33.4整套入口同时运行。它只打开相机和JPEG压缩节点，使用RGB-only候选640×480/6 Hz；不打开底盘/雷达串口、不发S1、不启深度/点云/STVL。视频窗口是相机前方透视图，640×480表示像素数，窗口大小不改变镜头视场；地图仍为空是因为没有雷达/里程计，不代表视频故障。

下面在Jetson独立终端执行，加载与网页相同的域31/localhost环境，记录独立日志及PID，只更新相机运行指针。预期启动RealSense与RGB压缩两节点；该终端持续运行是正常现象，日志在下一组观察。重复启动前先停止本入口。失败Ctrl+C停止并查日志，不操作驱动/USB电源；退出后至少等5秒，原网页服务继续保留。

### 33.5 平板操作、保存与场地验收

平板保持连接“小泽”，打开`http://192.168.5.11:8080`（以33.3实际读回地址为准），建图限定在原WiFi有效覆盖内。静止数据有效后，在确认安全的空地接通轮动力，先慢档使能，短暂按住一个方向、松手并确认实物停止；每次松手后重新使能。之后分别验收前进、后退、原地转向，再验常档。网页上的速度为命令值，不当实际速度。分别记录松手、关页面、锁屏、断WiFi、视频断流、网关退出后的最终零速时刻、编码器停稳与尺量停车距离。必须先完成架空/静止阶段，再由现场看护进行地面故障试验；异常直接断12 V轮动力，不用人作障碍。

确认两档停车与显示可靠后，再逐段走走廊—房间—大厅边缘并回到已建区域，观察红点贴墙、墙体无明显重影和回环一致性。5分钟提醒不会突然停车；选择安全位置点击“停车并保存地图与工程”。保存期间禁行，结果明确指出成功目录或失败；完成后保持停车，重新使能才能继续。每次建立新的时间戳目录，不覆盖旧地图。两类文件和运行参数读回全部成功才写完整清单；部分失败目录不允许续建。

误删后只需恢复热点配置时，下组读取工具输出的删除前备份，恢复其对应原文件并让NetworkManager重新加载；需要sudo，会写回该热点配置但不激活热点，当前原WiFi保持。备份路径可从上述输出或桌面维护记录查到，不要输入创建前的目录归档。命令先拒绝覆盖已存在文件，并追加本次恢复记录；预期连接列表重新出现`carcar-mapping`且不自动连接。失败停止检查，不再次切换网络；恢复后不要直接继续旧维护流程，先核对已归档状态。此过程不会在屏幕显示密码，也不要把备份内容发到聊天。

```bash
(
set -e
cd /home/jetson/luhao/my_nav_carcar
read -r -p '输入删除前热点备份的完整路径：' mapping_profile_backup
case "$mapping_profile_backup" in
  /etc/NetworkManager/system-connections/*.backup) ;;
  *) echo '路径不是同目录热点文件备份，停止'; exit 1 ;;
esac
mapping_profile_file=${mapping_profile_backup%.backup}
mapping_profile_file=${mapping_profile_file%.*}
sudo test -f "$mapping_profile_backup"
sudo test ! -e "$mapping_profile_file"
sudo tee -a /home/jetson/Desktop/系统配置维护记录.md > /dev/null <<EOF

## MAPPING-RESTORE-$(date +%Y%m%d_%H%M%S_%N)：恢复误删的热点配置

涉及文件：$mapping_profile_file
目的与机理：从同目录完整备份恢复文件并交由NetworkManager重新加载，不激活网络。
修改前：该热点文件不存在；修改后：与 $mapping_profile_backup 完整内容一致，权限0600，密码不展开。

EOF
```

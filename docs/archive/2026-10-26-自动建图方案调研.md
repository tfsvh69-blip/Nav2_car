# 陌生环境自动建图方案调研

核对日期：2026-10-26。性质：一手仓库、固定提交及源码调查，供产品方案讨论；未安装探索节点、启动硬件或修改运行参数，没有本车实机通过结论。只选择两项 C++ 运行候选，并将一个 Python 实现作为算法参考。星数、演示视频、作者自述和 CI 文件存在均不等于本车可靠性或工业认证。

## 1. 需求与研究范围

本轮目标是在陌生室内环境，由上位机一键发起、车辆自行寻找可到达的未知区域并建图，无需持续遥控。当前约束是 A1 二维激光、纯轮式 Odom、Jetson、ROS 2 Humble 与 Nav2；相机深度暂不参与导航，RGB 只承担预览、调角和拍照。该约束不表示在线深度层已经完成关闭，切换实施需另行验证。

SLAM 负责根据观测和运动估计“车在哪里、周围是什么”；探索器负责决定“下一步去哪里才能增加可用地图”；Nav2 负责规划和执行到该目标的运动。三个候选探索实现都不能代替现有 SLAM 的弱特征退化保护，也不能凭探索完成事件保证地图几何正确。此前二维地图散点、静态层清障和弱特征问题见[激光链路调研](2026-10-26-激光建图与导航链路调研.md)。

本文的项目适配、科研基础和产品验收部分由主代理继续补充；以下先固定可复用实现的事实与来源。

## 3. 主候选 A：m-explore-ros2 / explore_lite

### 3.1 输入、目标选择与输出

`Costmap2DClient` 读取配置的二维 `nav_msgs/OccupancyGrid`、可选增量 `OccupancyGridUpdate`，用 TF 取得机器人在地图坐标系中的位置；配置示例把输入设为 `map`。探索器不直接读取 A1 `/scan`，它消费 SLAM/Costmap 的结果，通过 `NavigateToPose` Action 发目标，另发布前沿标记与 `explore/status`。[输入实现](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore/src/costmap_client.cpp)、[配置示例](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore/config/params.yaml)

前沿是已知自由区域旁边的未知区域边界；源码用广度优先搜索聚合前沿，过滤过短小簇，再按距离代价与前沿大小收益排序，选第一个非黑名单簇的质心。该“距离”不是调用 Nav2 求出的完整可执行路径代价，质心也不天然保证有足够车体净空；凹形边界或门口等场景须验证目标能否落在可达自由空间。`orientation_scale` 虽有参数声明，当前前沿代价公式不使用它。[搜索与代价公式](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore/src/frontier_search.cpp)

### 3.2 暂停、取消、抢占与完成的真实语义

- 节点就绪后立即开始探索，没有完整产品会话启动门槛；`explore/resume` 的 Bool 支持停止/恢复。
- 发送新候选使用 Nav2 `NavigateToPose`，同一目标仍活跃时保持；目标变更可能触发 Nav2 抢占。回调用 active goal UUID 忽略旧目标终态。
- `stop()` 发 `async_cancel_all_goals()` 并停调度定时器，未等待取消响应及导航终态就发布暂停状态；这会取消同一 Action 服务上的全部目标，要求独立导航所有权，不能与巡检/人工单点竞争。
- 没找到前沿，或所有前沿均进入黑名单，都会发布 `EXPLORATION_COMPLETE`。地图边界错误、机器人落在图外等原因也可能使搜索返回空列表，不能将该消息直接解释为全部可通行场地已测完。
- 可选返回初始位姿；“探索完成”消息在返起点之前发送，返程失败只有有限状态处理，不能当成自动回到起点已经成功。

以上来自[固定探索主循环](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore/src/explore.cpp)与[状态消息](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore_lite_msgs/msg/ExploreStatus.msg)。

Humble 的重要差异：最新提交虽然题为不拉黑被抢占目标，但源码按 Nav2 版本分支；Humble 没有新版结果 `error_code` 字段，`ABORTED` 仍无条件把当前前沿拉黑。不能由提交标题推断本车所有抢占情况都已解决。普通无进展也会拉黑，后续需由上层区分暂时受阻、真实不可达和故障，避免漏图被报成成功。[固定结果处理及兼容宏](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore/src/explore.cpp)、[构建版本判断](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore/CMakeLists.txt)

### 3.3 ARM64 适配与维护代价

探索节点依赖常规 ROS 2/Nav2、TF、地图消息与自带 `explore_lite_msgs`，构建配置未要求 CUDA、学习模型或 x86 专属指令。Jetson ARM64 源码构建具有接口上的适配基础，但本轮未编译，不能写成已经通过。单车无需启用 `multirobot_map_merge`；README 对 SLAM Toolbox 的“实验分支”说明主要针对多机器人地图合并，不等于单车探索必须更换 SLAM。

收益是实现小、逻辑直观、改造范围可控，适合作为可解释基线；代价是要补启动/停止闭环、目标安全位置、结果分层和产品完成判定。需要关注地图更新是否持续、TF 新鲜度及 Action 所有权；它没有替本项目建立完整质量与安全监督。[包依赖](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore/package.xml)、[构建文件](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/explore/CMakeLists.txt)、[许可证](https://github.com/robo-friends/m-explore-ros2/blob/326cf8a0b487c34246bb8f3326afbcd69576dc60/LICENSE)

## 4. 主候选 B：frontier_exploration_ros2

### 4.1 接口与选择策略

该项目提供独立 C++ 核心库、ROS 节点、只读调试观察器、可选 RViz 插件和 `ControlExploration` 服务。运行节点输入二维地图、全局/局部 Costmap、TF，输出 `NavigateToPose` 目标、可选前沿/选择目标标记与完成事件；上位机可通过类型化控制服务开始、停止或预约控制。[核心接口](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/include/frontier_exploration_ros2/frontier_explorer_core.hpp)、[控制服务](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/srv/ControlExploration.srv)

前沿使用 WFD 风格提取，结合代价图寻找可用目标点，以 MRTSP 代价矩阵排序，可选 greedy 或候选数/视界受限的动态规划，逐个下发。它并非把整条探索路线一次交给车执行；动态地图变化后会重新决策。地图预处理得到内部 decision map，不等于修好了 SLAM 位姿图或批准地图资产；薄障碍、门口和未知边缘尤其要对照原图检查。[前沿和目标生成](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/src/frontier_explorer_core_frontiers.cpp)、[decision map](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/src/decision_map.cpp)、[排序](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/src/mrtsp_ordering.cpp)

### 4.2 控制、抢占与完成

- 支持 `autostart=false` 冷待命；停用探索时停止地图/Costmap处理，控制服务仍可用。比启动即动更容易接当前上位机会话。
- Action 反馈、结果和取消回调绑定 dispatch id，迟到结果不覆盖新目标状态。停止只取消当前持有的 goal handle；若发送中尚未接受，记录取消请求，接受后再发取消。
- 取消被接受后继续等导航终态；控制服务的 `accepted` 是接受控制请求，不是物理停车确认。源码有 STOPPING 轮询，但未发现完整的停机总超时和硬件停车保证，仍需本项目门控兜底。
- 活跃目标的信息收益耗尽或受阻时可重选；部分重选直接发替换目标，走 Nav2 原生抢占，其他路径显式取消。需要覆盖同目标重复、旧结果迟到、拒绝、抢占及急停测试。
- 可选失败抑制有失效时间；“当前前沿全部暂时抑制”与“没有前沿”分开处理，前者不会发布完成事件。无可用候选时有等待后续地图更新的路径，但前沿提取及过滤阈值仍可能遗漏小区域。
- 完成事件是 `std_msgs/Empty`，在判断前沿耗尽时发布，可早于返回起点；没有本项目会话 ID、未覆盖区域、失败原因、地图质量和保存成功证明，上位机不能直接把它当最终交付成功。

依据：[目标调度、取消与终态](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/src/frontier_explorer_core_dispatch.cpp)、[ROS Action 与控制服务适配](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/src/frontier_explorer_node.cpp)、[Humble结果字段兼容](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/include/frontier_exploration_ros2/nav2_compat.hpp)。

### 4.3 本车不能照搬的默认值

作者的验证说明以 TurtleBot3 Waffle Pi、360°/12 m二维雷达为参照。打包参数启用前沿地图预处理与目标抢占；`goal_preemption_lidar_range_m=12.0` 是信息收益估计的虚拟传感器量程，不是向驱动下发的雷达量程，也不是本车可靠测距。当前本项目建图基线只使用 3 m，另有未转正的 6 m 候选，直接照搬会错误评估未知区收益。

打包配置还有 `goal_preemption_complete_if_within_m=0.5` 的接近即完成快捷路径，可能在 Nav2 未报到达时取消当前前沿；`max_linear_speed_vmax=0.50` 等参数用于评分估计，不会直接命令车速，但必须与本车速度能力相符。正式评价要区分声明默认值、打包 YAML 覆盖值与在线读回，不能只看 README 参数表。[固定打包参数](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/config/params.yaml)

### 4.4 ARM64 适配与维护边界

核心为 C++17、常规 ROS 2/Nav2 依赖，未要求 CUDA 或学习模型；可选 RViz 插件需要 Qt，车端无须启用 GUI。构建依赖对 ARM64没有明显架构专用阻碍，但本轮未运行本机编译/性能测试，Jetson CPU占用、峰值内存、地图扩大后的延迟仍待验。[构建和导出库](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/CMakeLists.txt)、[依赖](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/package.xml)、[许可证](https://github.com/mertgulerx/frontier_exploration_ros2/blob/11864e4ac6789dc81fd71bad51e43339c01deca2/LICENSE)

收益是把控制面、目标状态机、暂时失败与调试观察器分开，适合评估较完整的上位机接缝；代价是算法/参数更多，固定提交较新，README 中“可靠”“适合真实环境”等宣传不构成证据。本轮只确认有近期开发、发布和测试源码，不确认长期维护承诺、Humble CI通过、本车实机或工业案例。

## 5. 参考 C：第三方 Nav2 WFD

此项目适合理解“自由区/未知区边界→双层广度优先搜索→前沿簇中心→导航”的算法。当前代码是 Python；依据本仓库新增执行逻辑统一 C++ 的约定，本轮不把它新增为车端运行入口，也不因本次研究而扩大语言授权。

固定源码读取 `/map` 与 `/odom`，向名为 `FollowWaypoints` 的 Action 发点；每次选离当前位姿**最远**的前沿中心，并非最近前沿。它从 `/odom` 直接拿位姿与 map 栅格比较，没有正确表达本项目所需的 map/odom TF转换；主入口还含固定初始位姿和示例路点。源码的 `cancel_goal()` 是辅助函数，没有完善的外部控制与取消反馈链；探索递归调用中的结果状态没有完整分层，前沿为空只记日志，不提供产品完成判据。[固定主实现](https://github.com/SeanReg/nav2_wavefront_frontier_exploration/blob/07473294204663473fd6ae058729c4bba71b6074/nav2_wfd/wavefront_frontier.py)

它使用 NumPy，但 package.xml 对该依赖是注释项；还有 ROS 早期接口用法，不能承诺 Humble直接构建运行。依赖理论上可用于 ARM64，不等于这个节点已经适配本车。即使移植 C++，仍须维护完整产品控制与错误语义，因此本轮只作算法阅读和离线参考。[包元数据](https://github.com/SeanReg/nav2_wavefront_frontier_exploration/blob/07473294204663473fd6ae058729c4bba71b6074/package.xml)、[根许可证](https://github.com/SeanReg/nav2_wavefront_frontier_exploration/blob/07473294204663473fd6ae058729c4bba71b6074/LICENSE)

## 6. 本轮候选取舍

建议实际对照限定为 **m-explore-ros2 的小型 C++ 基线**与 **frontier_exploration_ros2 的 C++ 增强候选**。前者便于定位失败原因，后者已有更多会话与暂时失败处理接缝；尚未选定生产默认。WFD 仅用来核对算法与建立简单可解释对照，不新增第三套运行主线。

三维探索需要三维传感器、地图和运动/传感模型，当前二维 A1 与“深度不导航”的约束无法直接满足；强化学习探索还引入训练、场景迁移和失败可解释性的成本，不解决当前地图质量与停车闭环。它们不作为本轮主候选，后续若传感器或业务目标变化再独立调研。

## 7. 项目接口适配与产品闭环

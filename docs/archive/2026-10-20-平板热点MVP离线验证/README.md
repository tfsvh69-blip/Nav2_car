# 平板热点MVP离线验证证据

对应NET-001及APP-UI-20261020，当前结论统一[测试记录](../../测试记录.md#net-001平板热点中介与180秒回原网2026-10-20)，完整有效命令只在[操作手册33.19](../../操作手册.md#tablet-wifi-mvp)。

- `integration_before.gtest.xml`：首次完整包回归的原始JUnit，13项集成用例中2项失败，历史不改写。失败均为浏览器脚本正常退出后，C++立即查询HTTP缓存仍读到armed=true。原日志随后已出现门控disconnect/armed=false，说明夹具没有等待异步状态传播。
- 修正只让上述两处夹具有界等待撤使能，并保留/增加输出为零的检查；未修改控制代码、速度、运动超时或断连保护。最终回归结果归档为各自的 `*_after.gtest.xml`。
- `integration_second.gtest.xml`：第二次原始结果，异步撤使能检查通过，80ms单程延迟下挂起归零观察仍失败。旧1200ms固定观察窗紧贴当前1000ms收包租期、上行在途包及状态发布/HTTP缓存总时长；测试改为读取门控租期（仍硬限制不得超过1000ms），加注入上行时延和250ms观测传播预算。突发断流也在网络恢复前、租期加传播预算后读取；没有改车端期限或控制逻辑。
- 网络工具的离线测试使用替身后端，验证检查点/记录先于切换、失败处置及客户端配置。没有实际热点、串口或网络配置操作；不能据此声称NetworkManager真实回滚、平板锁屏或客户端互访已通过。
- 前端文字核对时8081服务未运行；按安装目录核对首页与assets资源。未为文字验证启动巡检或硬件，归档原页面不作全局替换。

最终5个CTest目标、71项C++用例全部通过（127.82秒），`test_*_after.gtest.xml`为原始结果。车端只读状态仍为“小泽”/192.168.5.11/24、无检查点；尚未进行真实热点切换或创建系统网络备份。巡检前端5项及生产构建通过；两轮既有失败按上述原文保留。

## 2. 论文与成熟实现比较

### 2.1 MCL、Mixture-MCL与Nav2 AMCL

Thrun、Fox、Burgard、Dellaert的《Robust Monte Carlo Localization for Mobile Robots》，Artificial Intelligence 128，99–141，2001，使用带权位姿假设表示定位后验；Mixture-MCL将运动模型生成的样本与观测驱动的样本结合，研究全局定位、绑架恢复及动态干扰。本轮阅读作者提供的完整论文，并核对出版信息。[作者论文PDF](https://robots.stanford.edu/papers/thrun.robust-mcl.pdf)、[出版方及DOI](https://www.sciencedirect.com/science/article/pii/S0004370201000698)

Fox的《KLD-Sampling: Adaptive Particle Filters》，NeurIPS 2001，依据分布占据状态分箱数及统计误差要求调整粒子数量。它解决的是有限粒子表示后验分布的近似质量与计算预算；“KLD采样”不是从一圈激光中挑选回波点，不能与本项目180束预算混为一谈。[会议原文PDF](https://papers.neurips.cc/paper_files/paper/2001/file/c5b2cebf15b205503560c4e8e6d1ea78-Paper.pdf)

Nav2 `nav2_amcl` 1.1.20已实现KLD自适应MCL；其`pf_resample_limit()`依据分箱数量、`pop_err`和`pop_z`确定粒子上限，并保持`min_particles`／`max_particles`约束。相关实现已在当前Humble链路内，无需另引粒子滤波框架。[1.1.20包说明](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_amcl/package.xml)、[粒子重采样源码](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_amcl/src/pf/pf.c#L403)

本项目当前旁路使用`likelihood_field_prob`。1.1.20上游也会按角序步长抽取激光束，再忽略NaN和最大量程束；这是一种概率模型的计算预算，并不附带本项目独立几何验证的“至少50点”规则。上游行为不能直接证明本地硬门槛前丢弃有效输入合理，也不能据此声称上游AMCL存在同一种缺陷。[对应传感器模型源码](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_amcl/src/sensors/laser/likelihood_field_model_prob.cpp#L61)

**适配结论：** 保留AMCL候选生成与独立验证的分工，先修本项目验证器的有效束选择及检查状态。未经对照，不增加粒子数、不修改`max_beams`、不放宽匹配门槛。提高粒子数能更好表示复杂分布，却不能凭空增加未观测几何；这是由上述方法推得的适用边界，不是论文对本车的实验结论。

### 2.2 Karto相关匹配与SLAM Toolbox

当前SLAM Toolbox版本2.6.10建立在修改过的Karto上，支持保存及重载位姿图。`ScanMatcher::MatchScan()`先做粗相关搜索，再细化；`CorrelateScan()`在给定平移和角度窗口搜索，输出响应、位姿与协方差；偏离先验的惩罚也在对应实现中明确存在。[2.6.10包说明](https://raw.githubusercontent.com/SteveMacenski/slam_toolbox/2.6.10/package.xml)、[MatchScan与CorrelateScan源码](https://raw.githubusercontent.com/SteveMacenski/slam_toolbox/2.6.10/lib/karto_sdk/src/Mapper.cpp#L537)

现有恢复初值已经复用了Karto只读相关匹配，并由AMCL及独立几何／多帧验证继续审查。该组合可以保持现有图档、坐标和恢复事务；其有限搜索窗口仍要求合理先验。相关匹配响应高、局部残差小，均不能单独作为全局车位唯一的证明。关于SLAM Toolbox自身的定位模式，官方也说明需要针对机器人调参和高质量里程计，不能认为更换模式就无条件优于AMCL。[2.6.10官方定位说明](https://raw.githubusercontent.com/SteveMacenski/slam_toolbox/2.6.10/README.md#localization)

**适配结论：** 保留Karto、Ceres、可信检查点和旁路验证，不替换SLAM核心；统一有效束处理可复用本项目已部署的回环复核思路。独立验证门槛、失败冻结和原图证据仍保留。

### 2.3 Cartographer：高效搜索思想可参考，整栈替换不适合本轮

Hess、Kohler、Rapp、Andor的《Real-Time Loop Closure in 2D LIDAR SLAM》，ICRA 2016，1271–1278，DOI `10.1109/ICRA.2016.7487258`，使用扫描对局部子图匹配形成约束，再进行全局优化；多分辨率预计算与branch-and-bound减少回环候选搜索。本轮阅读了Google原文PDF，并核对开源`FastCorrelativeScanMatcher2D::BranchAndBound()`的候选上界剪枝及递归细化。调研时官方master读回为`877157a0d91788a7700221d87232d412cb3c1ef4`，提交日期2024-01-05，关键实现链接固定到该提交。[论文原文](https://research.google.com/pubs/archive/45466.pdf)、[关键实现](https://raw.githubusercontent.com/cartographer-project/cartographer/877157a0d91788a7700221d87232d412cb3c1ef4/cartographer/mapping/internal/2d/scan_matching/fast_correlative_scan_matcher_2d.cc#L314)

这套方法解决较大搜索空间的效率，并不保证对称环境一定产生唯一正确匹配。若引入整栈，需要适配子图、Lua配置、图档、ROS封装、恢复和现有校验事务；官方仓库还明确说明主项目不再积极维护、ROS分支维护能力有限。[官方维护说明](https://github.com/cartographer-project/cartographer#a-note-for-ros-users)

**适配结论：** 可把多分辨率预计算和有界候选搜索作为将来真实搜索瓶颈的参考；本轮不迁移Cartographer，也不以论文中的实时结果代替本车性能验收。

### 2.4 真退化：关注“哪些方向被约束”，而非只看点数和残差

Zhang、Kaess、Singh的《On Degeneracy of Optimization-based State Estimation Problems》，ICRA 2016，809–816，DOI `10.1109/ICRA.2016.7487211`，通过约束系统的特征值／特征向量区分良好约束方向与退化方向，再对不同方向分别处理。该论文的示例与实验是优化估计与视觉／激光六自由度系统，不能直接把其阈值移植到本车二维Karto。[作者原文PDF](https://frc.ri.cmu.edu/~zhangji/publications/ICRA_2016.pdf)

对本车的推论是：大量点如果都落在相似平行墙上，仍可能缺少沿走廊方向的约束；两个相距较远但结构相似的车位又可能各有很小残差。前者是局部可观测性问题，后者是分离的多模态假设，二者需要不同证据。一个3米局部视野也不能因为整张历史地图看上去清楚，就被认为具有充分的当前位置约束。这些是方法适配判断，不是本轮已证实环境退化。

如修复采样后仍失败，应依次核验有效束角度分布与测距覆盖、参考图覆盖、扫描时间与TF／轮式对齐、局部匹配曲面和真正竞争假设，再考虑测距范围对照、可观察地标或独立里程计约束。本轮不引入IMU姿态／线加速度融合，不擅自扩大已确认3米建图范围；每项变化另设可比数据和独立验收。

## 3. 手动防撞：复用局部安全分层，避免无界几何碎片

Nav2 Collision Monitor 1.1.20从原始传感器收集车体系中的点，以停止区、减速区或预测碰撞时间过滤速度，独立于代价图和规划器。官方明确它运行于普通CPU，不能据此声称硬实时安全认证。[官方README](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_collision_monitor/README.md)

其实现按有限传感器源和保护区域执行，点位判断直接遍历输入点；approach模式以配置的时间跨度和步长投影足迹、检查碰撞。[处理主循环](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_collision_monitor/src/collision_monitor_node.cpp#L315)、[区域与碰撞时间计算](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_collision_monitor/src/polygon.cpp#L153)

本车已经使用Collision Monitor，另有更严格的方向扫掠覆盖检查：除碰撞点外，还要求新增扫掠区域有真实激光视线证明，NaN、缺束或盲区不能自动视为空地。现有慢路径逐束裁剪尚未覆盖的多边形，碎片增长和反复容器分配会增加工作；8毫秒使用墙钟时间，还会受调度影响。**本轮已证实发生预算拒绝，尚未将几何计算、抢占延迟各占多少作出测量结论。** [当前手动几何实现](/home/jetson/luhao/my_nav_carcar_return_nearby_release/src/carcar_mapping_autonomy/include/carcar_mapping_autonomy/manual_motion.hpp:9)

### 3.1 本轮候选的几何加速边界

候选沿用原始扫描的三角形视线证明与凸多边形裁剪，采用两种局部加速，原逐束精确路径继续作为后备：

- **盲区反例优先拒绝。** 只在新增扫掠区内取少量候选点，并核验它们是否被任意有效观测覆盖。存在一个确定未覆盖点即可拒绝；没有找到反例仍需完整审查，不能把有限点采样用于放行。点支持判断采用原三角形的覆盖超集，边界不确定、非普通多圈或特殊角步长应回到精确路径，避免漏掉相邻束／其他观测提供的支持。
- **连续有效束保守预裁剪。** 同一观测中连续有效且角区间相接的一小组原三角形，共享激光原点；取所有原半径的最小值形成更宽的内接三角形，先从待证明区域减去该保守子集。候选限制每组最多32束、展开角跨度小于`π/3`，无效束立即断组、负角增量排序两端、半径向内留数值裕量，不跨观测原点合并。原始回波碰撞检测在这些加速之前完成。

保守预裁剪的几何依据是本项目适配推导：在共同原点、连续角区间和总角跨度小于`π`时，半径最小值所在圆的宽弦位于各子弦内侧；宽三角形按各原束角楔分割后的部分，均包含在该束原三角形中，因此属于原观测并集。该论证不能推广到跨缺束、取最大回波、角序因浮点失真而不连续或不同原点的情况。实现仍需真实输入、双边无预算几何对照、短回波／盲区反例和8毫秒下的时延验证，不把数学充分条件直接当作本车已验收结论。

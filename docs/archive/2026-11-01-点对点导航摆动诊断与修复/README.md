## 可证伪假说与成熟机制

1. 调向指令与后级制动／反馈不匹配：只改变调向速度或RPP内部角加速度，若闭环反复越过对准方向显著减少，支持该机制；仅历史模式改变不足以证明闭环修复。
2. 速度缩放前视点引起门槛反复跨越：固定前视距离，其余不变，对比模式及轨迹；仍须检查弯道与近边界切角。
3. 周期重规划／短起点接线改变路径首段：固定同一路径，与1Hz重规划对照；固定路径仍摆动则此项不能单独解释。
4. SLAM的 `map→odom` 校正参与触发：固定地图变换、保留轮式积分与控制反馈，比较重复摆动。

当前RPP每个周期以实际前视点方向判断是否原地对准，正式阈值0.10rad约5.73°。该参数由历史45°收紧是为了保住近边界短接线的0.22米净空；旧45°在原安全反例第5个50毫秒虚拟步越界，不能作为直接恢复项。Smac本身已经包含路径平滑，不预设缺少平滑器就是根因。

已核对本机Nav2 1.1.20与对应官方机制：

- [RPP实现](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_regulated_pure_pursuit_controller/src/regulated_pure_pursuit_controller.cpp)：前视点、每周期调向、角加速度和停止角限制；原碰撞与曲率／代价约束优先复用。
- [RotationShim实现](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_rotation_shim_controller/src/nav2_rotation_shim_controller.cpp)：可复用进入／解除角滞回，但每次setPlan会重新审查、短路径存在采样边界，且不能同时让primary RPP独立调向；不是无需验证的替换方案。
- [SmacPlanner2D实现](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_smac_planner/src/smac_planner_2d.cpp)：已有平滑和正式规划器接口，优先以相同地图与目标对照，不重写全局规划器。

本轮参数对照已满足既定软件反例，采用现有RPP单参数适配；未引入RotationShim组合或自定义Controller插件，未安装依赖或替换系统Nav2库。后两种方案职责与版本维护代价更高，当前没有证据需要扩大实现范围。

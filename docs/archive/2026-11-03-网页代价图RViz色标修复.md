# NAV-018-COSTMAP-001 网页代价图 RViz 色标修复

2026-11-03。用户反馈网页大片红色且调大膨胀半径后缺少梯度，要求 RViz 显示效果；随后授权正常结束任务后更新8080，并明确通知任务已取消。

## 事实与根因

正式网页订阅 `/global_costmap/costmap`、`/local_costmap/costmap` 的 OccupancyGrid。原 `NavigationView::grid` 对1～98只改变紫／橙色透明度，将99和100合并为同一高不透明度红色。网页不是RViz色标。

只读现场快照：map坐标系，234×248格，每格约0.05米。58,032格中0为2,096格，1～98为12,148格（43个等级），99为0格，100为43,788格，未知为0格。故原图75.45%的均匀红块确实是固定100，不能用虚构渐变掩盖。全局 known-space KeepoutFilter 将未知／净空不足等规划禁入区域并入最终代价图；仅凭最终100无法区分实体障碍与禁入来源。膨胀半径／递减系数影响软代价，不解除硬禁入。

## 修复范围与参考

在当前研发工作区 `/home/jetson/luhao/my_nav_carcar_live_tuning_20261103` 修复，不从根旧源整包覆盖。1～98采用蓝→紫→红，99青色，100紫红色；全局alpha=102/255（0.40），局部140/255（约0.55），对齐项目 navigation_lite.rviz。零和未知保持透明，让SLAM底图承担未知显示；这是与RViz直接绘制未知灰绿不同的有意保留。图层开关、导航参数、原图、路径和控制链路不变。图例及帮助说明同步。

色标依据 [RViz Humble官方实现](https://github.com/ros2/rviz/blob/humble/rviz_default_plugins/src/rviz_default_plugins/displays/map/palette_builder.cpp)。该项目BSD-3-Clause；本轮仅依据颜色规范独立实现数值映射，没有引入依赖或复制第三方模块。不同背景、底图透明度、图层叠加和采样时刻仍影响最终外观；同色标不保证整幅截图像素相同。

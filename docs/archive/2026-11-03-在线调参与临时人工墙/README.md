## 关键实现边界

原始`/map`仅由SLAM维护；派生`/mapping/navigation_map`叠加本轮墙，供探索、已知空间掩膜、全局规划、路径及扫掠检查。局部墙先进入原生StaticLayer，再参与膨胀，最后由KeepoutFilter保留硬约束。软膨胀有颜色不等于禁止通行；失败原因仍需区分选点、规划、局部跟踪与最终保护。

在线参数使用真实ROS 2参数服务。每批绑定任务及导航代次，局部衰减与RPP按保守过渡顺序同步；仅参数读回不算完成，还需两个膨胀层确认本代次全图更新完成。迟到写入由插件代次屏障拒绝。显式保存默认只写操作者配置，不改冻结发行参数，也不保存墙。

初始化时，调参或约束地图尚未就绪只保留自动启动请求、显示等待原因并保持零输出；两者就绪后才进入原启动预检。操作者halt／pause／manual均可取消等待，随后READY不得自行重启，手动速度仍需完整健康、参数与墙保护。启动调参原请求若超时，仍记录failed／error／rolled_back；只有新鲜停稳、新revision回退、三节点真实读回、两个实际完整膨胀周期，以及最终四项参数与RPP因子／距离均满足原启动请求时，才独立恢复ready资格。saved defaults不同或RPP不满足时继续FAILED，不能把回退当作默认应用成功。

回环／恢复后，有墙时先验证原图定位及连续新扫描，允许操作者在车辆冻结、停稳时复核墙；再等待派生图、掩膜、导航缓存及提交门槛。人工复核累计预算300秒，原有60／65秒恢复预算只扣除已验证的人工等待时间；扫描新鲜度及提交前5秒几何检查没有放宽。

手动旁路需要当前遥控持有者显式开启，限0.05米/秒与0.10弧度/秒；断连、交接或持有者变化会撤销并停车。退出后须重新检查定位，不能直接恢复自动。

## 官方发布模式的版本兼容与限制

本机使用Fast DDS 2.6.12、rmw_fastrtps 6.2.10。对应[participant.cpp第191～213行](https://github.com/ros2/rmw_fastrtps/blob/6.2.10/rmw_fastrtps_shared_cpp/src/participant.cpp#L191)仅在 `RMW_FASTRTPS_USE_QOS_FROM_XML` **字面等于`1`** 时启用XML QoS覆盖；字面`0`会得到false并继续读取 `RMW_FASTRTPS_PUBLICATION_MODE`。本轮Launch显式设置`0`，再为应用子进程设置`ASYNCHRONOUS`；不能把“存在一个非空的0字符串”误认为true。

该官方模式同时覆盖[普通话题发布](https://github.com/ros2/rmw_fastrtps/blob/6.2.10/rmw_fastrtps_cpp/src/publisher.cpp#L253)、[服务请求writer](https://github.com/ros2/rmw_fastrtps/blob/6.2.10/rmw_fastrtps_cpp/src/rmw_client.cpp#L359)及[服务回复writer](https://github.com/ros2/rmw_fastrtps/blob/6.2.10/rmw_fastrtps_cpp/src/rmw_service.cpp#L362)，因此action目标确认所用的服务链路也受影响。发包可交由后台线程，有望减少调用线程的同步传输占用；同时增加队列／线程开销，仍可能受资源和调度影响，不保证实时性。服务回复写入前的reader匹配等待仍同步，见[对应版本回复实现](https://github.com/ros2/rmw_fastrtps/blob/6.2.10/rmw_fastrtps_shared_cpp/src/rmw_response.cpp#L129)。

该设置没有改变SHM／UDP、ROS域、QoS可靠性、队列深度或健康1秒请求期限／2秒真实ACTIVE有效期／调参单步3秒期限，也没有使用ACTIVE诊断替代健康许可。严格localhost分支会在XML加载后追加UDP与SHM，常见“只列UDP transport”的XML不能移除它；本轮未采用未经验证的UDP locator限制方案，也未清理SHM或修改系统环境。Native工具按实际PID出生时刻及PPID树认定evaluator、唯一ROS launcher和应用后代，再分别检查环境；不能按Mode倒推角色，也不要求无ROS职责的Chrome内部进程保留ROS变量。`/proc`环境读回证明配置范围，不冒充独立测量DDS内部writer QoS。

# carcar 四轮麦克纳姆导航巡检小车

最后更新：2026-10-11

面向 ROS 2 Humble (Ubuntu 22.04 LTS) 的四轮麦克纳姆室内巡检小车。第一版采用 A + C：导航时固定相机角度，到点停稳后抬起相机拍 RGB 照片、本地保存并排队上传云端；导航深度与巡检照片分开处理，不做门状态或危险识别。应用拟采用行为树编排。当前只完成[巡检设计](../../src/carcar_inspection/README.md)，运行框架尚未实现；深度接入完整 Nav2 与实车移动仍待验证。

当前进度、最新结论与唯一下一步请以 [项目现状与路线](../项目现状与路线.md) 为准；所有实机构建、启动、观察与应急停止命令统一收敛于 [操作手册](../操作手册.md)。

本次版本里程碑为 **V2.4：D435接入Nav2的STVL基础障碍识别与局部代价地图**。保留原生宽视场深度点云，通过TF、距离/高度及时间确认筛选接入STVL，生成三维障碍体素和二维代价地图；补充感知健康联锁、静止取证、跨机RViz点云/三图参照与100刷新配置。用户现场评价基本障碍识别和局部地图视觉效果较好。这里的局部地图供导航规划使用，完整Nav2规划/控制与实车移动验收仍待；分项实测、空地误标及历史失败以NAV-016-R2为准，不能将视觉认可等同全部通过。当前入口见[手册31.16](../操作手册.md#3116-94档近平视与100刷新率的静止stvl验收)。

## 核心技术选型与当前状态

* **计算平台**：NVIDIA Jetson Orin NX，Ubuntu 22.04 LTS，ROS 2 Humble。
* **运动模型**：四轮麦克纳姆轮底盘，因带载重载静摩擦大，软件层正式锁定为**非全向差速模型**（`holonomic=false`，禁用横移）；精度与重复性仍按场景验收。
* **底盘控制**：Rosmaster 控制板板载闭环 PID，四轮编码器已有标定记录；参数、接线和停车保护的证据边界见[硬件台账](../硬件台账.md)与[测试记录](../测试记录.md)，不把主机命令超时保护等同独立硬件失联停车。
* **里程计基线**：四轮累计编码器纯轮式里程计（1 m 直行与 360° 原地自转实测通过，静止零漂移）。严格遵循状态估计推进规范，IMU 虽已完成 REP-103 驱动校正，但当前**保持纯轮式里程计独立输入，暂不接入滤波融合**。
* **建图与导航**：
  * SLAM Toolbox 异步建图、地图保存及 C++ 重载校验已有实机记录。
  * Nav2 使用 AMCL 与差速运动约束，已有 Smac 2D + DWB 实验基线。足迹、膨胀和传感器覆盖仍按场景验证，不能仅凭参数推断真实净空得到保证。
  * 状态监控与会话归档：Groot 1 与桥接监视器已正式停用并默认关闭；全面改由 C++ `nav_event_logger` 提供 1 Hz 终端中文摘要、阶段流转即时告警，并在 `log/nav_sessions/` 自动生成含 1 GiB 分卷 rosbag2 的完整会话包（带 10 GiB 与磁盘 <2 GiB 保护）；配套 C++ 工具 `nav_log_tool` 提供会话清单、时序时间线与纯离线零发布回看。
  * 当前下一步为分阶段验证深度接入完整 Nav2 的地图消费、健康联锁及低速运动；既有 NAV-012 恢复失败与待复测项保留，具体安排只见项目路线。

## 软件架构与分层

```text
硬件串口 (/dev/myserial, /dev/ttyUSB0)
        ↓
rosmaster_vendor       原厂底层通信封装（第三方驱动）
        ↓
carcar_base            电机动力学、纯轮式里程计、底层安全看门狗
        ↓
carcar_description     URDF/Xacro 模型、实车物理尺寸与静态 TF 树
        ↓
carcar_lidar           RPLIDAR A1 雷达驱动编排与点云滤波
        ↓
carcar_camera          D435 RGB/深度、导航点云处理与健康监督
        ↓
carcar_navigation      SLAM 建图、AMCL 定位、Nav2 导航参数、nav_event_logger (状态与会话录包)、nav_log_tool 分析工具、XML Launch
        ↓
carcar_algorithms      感知与特征提取通用算法（规划中）
        ↓
carcar_inspection      任务管理、应用行为树、固定点RGB采集、本地保存与补传（仅设计）
        ↓
carcar_bringup         整车启动编排
```

以上表示职责层次，不是严格串行的数据链。`carcar_bt_monitor` 已停用，保留作历史测试对照；两份未构建的导航草稿已移入[历史源码目录](停用代码/2026-10-10/README.md)。现有底层测试、导航入口与录包证据保留。

### 生命周期丢应答导致启动无限等待（局部兼容入口）

两轮完整软件启动出现`bt_navigator/change_state`发送应答timeout，管理器无限等候；独立GetState实际读回bt_navigator、controller、planner均为inactive，collision_monitor仍unconfigured。节点已完成配置而应答丢失，并非探索目标失败。原始结果保留在`corridor-grid-pilot.log`、`corridor-v2-1.log`；调试器因主机ptrace策略未能附加，未修改系统策略。Humble默认LifecycleServiceClient单参数change_state调用无限等待，[上游6556](https://github.com/ros-navigation/navigation2/issues/6556)提出同类问题，尚不能称为上游已修复。

新增`mapping_lifecycle_manager`只为实验XML使用，继续实例化本机官方LifecycleManager并保留Bond、生命周期管理接口和顺序；在该可执行文件内以同签名定义把默认change_state调用改为5秒应答等待，超时后用2秒GetState核对明确期望状态，已达到才继续，否则拒绝，绝不盲目重发。正常应答还检查success，故障心跳门槛不变。CMake精确要求nav2_lifecycle_manager 1.1.20以限制ABI范围；没有更改系统库或设置LD_PRELOAD，其他导航入口仍使用系统管理器。新增运行依赖仅是本机已有Nav2导出库和lifecycle_msgs。替代方案是升级整套ROS或自写管理器，范围和兼容风险过大，暂不采用。该包装是项目局部修复，最终以真实官方管理器的丢包/正常/未过渡测试及完整启动结果验证。

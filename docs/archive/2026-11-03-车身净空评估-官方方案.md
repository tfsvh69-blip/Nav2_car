# 车身净空评估：Nav2 Humble 官方方案核对

日期：2026-11-03。范围为只读研究；未修改正式足迹、禁入、安全检查、控制器或导航参数，未启动实车。用户给出的28×26厘米用于几何分析，不替代对轮胎、支架、线缆等整车最大外廓及坐标原点的核实。

## 官方源码结论

1. **SmacPlanner2D不做带朝向的矩形搜索。** Humble的`Node2D::isNodeValid`调用仅带栅格index的碰撞检查；该重载直接读取中心格代价，以`>=INSCRIBED(253)`判碰撞。因此配置了矩形footprint并不等于2D搜索已经逐姿态验证矩形边缘。规划器通过膨胀／外部禁入限制获得中心点可行空间。[Node2D](https://github.com/ros-navigation/navigation2/blob/humble/nav2_smac_planner/src/node_2d.cpp)、[碰撞检查重载](https://github.com/ros-navigation/navigation2/blob/humble/nav2_smac_planner/src/collision_checker.cpp)。

2. **Hybrid与Lattice把朝向纳入碰撞检查。** Hybrid传入x/y/角度bin；Lattice检查运动基元终点并检查部分中间姿态。共享碰撞检查器支持按朝向预旋转多边形，必要时调用footprint检查。Hybrid的Dubins/Reeds-Shepp运动模型带转弯半径约束，不能只因支持多边形就视为本车最佳替代。Lattice的运动基元、角度量化、碰撞采样和控制器跟踪均需适配；二者都不等于连续几何或实车可靠性的证明。[Hybrid](https://github.com/ros-navigation/navigation2/blob/humble/nav2_smac_planner/src/node_hybrid.cpp)、[Lattice](https://github.com/ros-navigation/navigation2/blob/humble/nav2_smac_planner/src/node_lattice.cpp)、[多边形碰撞检查](https://github.com/ros-navigation/navigation2/blob/humble/nav2_smac_planner/src/collision_checker.cpp)。

3. **足迹padding和膨胀影响不同。** Humble的`padFootprint`按每个顶点x/y的符号分别加padding。对于轴对齐28×26厘米矩形，padding为p时边长变成28+2p、26+2p厘米；它不是“只画更宽色带”。Inflation围绕障碍生成代价场；内切半径以内为253，外侧指数衰减。软代价适合引导路线远离障碍，不能代替对真实车身包络和误差的碰撞检查。[足迹实现](https://github.com/ros-navigation/navigation2/blob/humble/nav2_costmap_2d/src/footprint.cpp)、[Inflation公式](https://github.com/ros-navigation/navigation2/blob/humble/nav2_costmap_2d/include/nav2_costmap_2d/inflation_layer.hpp)。

4. **原地转向也要检查扫掠空间。** Humble RPP可为路径／终点方向原地旋转，并对预测姿态调用footprint碰撞检查；RotationShim也会预测转向后的footprint。当前项目实际使用自定义MappingRotationShim及RPP，不能拿“26厘米宽、能直行进入”推导“进入后能转向或最终对准”。[RPP](https://github.com/ros-navigation/navigation2/blob/humble/nav2_regulated_pure_pursuit_controller/src/regulated_pure_pursuit_controller.cpp)、[RotationShim](https://github.com/ros-navigation/navigation2/blob/humble/nav2_rotation_shim_controller/src/nav2_rotation_shim_controller.cpp)。

以上使用明确Humble分支，不把新版文档中的能力直接套到当前环境；无新依赖或第三方代码引入。

## 本项目推断与核对

本地`SubcellSmacPlanner`继承`SmacPlanner2D`，在搜索外独立执行原图0.22米圆检查，并计算“Nav2足迹外接圆+0.02米”的实时障碍圆包络。28×26厘米的几何外接圆半径约0.19105米，动态包络约0.21105米。两者与规划禁入使用的`0.22+√2×resolution`分别属于不同检查点，不能只改其中一个就宣称通行能力已改变。代码入口：当前研发目录`src/carcar_mapping_autonomy/src/subcell_smac_planner.cpp`、`include/carcar_mapping_autonomy/map_geometry.hpp`。

几何上，保持正向直行的理想车宽是26厘米；允许任意朝向的圆包络直径约38.21厘米。两者都没有计入外廓误差、定位、地图、跟踪和动态制动误差。当前44厘米基础圆比纯几何旋转直径多约5.79厘米；规划圆再增加两侧合计约14.14厘米的栅格余量，形成约58.14厘米的连续几何名义值。实际离散地图通行阈值还受墙落格、格心和方向影响。不能把58.14厘米当实车测定的最小通道宽度。

## 建议顺序（评估建议，非已批准降低阈值）

1. 保留现有未知区拒绝、基础停车和实时障碍保护，先量化整车外廓、车体原点、典型直行横向误差及转向误差；地图误差与真实位置误差必须用独立量测辨别。
2. 优先审计额外`√2×5cm`规划余量的具体失效反例及其与精确圆—栅格相交、连续路径检查是否重复。离线比较多种墙落格／朝向、拐角、起步、终点转向和恢复路径，先回答“能否在保留0.22米基础审查时减少过度拒绝”。不要仅看直走通道截图通过。
3. 若圆形模型确实限制目标场景，再评估统一的带朝向多边形／运动扫掠检查，并同步覆盖规划、连接段、跟踪、原地旋转、返程和恢复。此项属于架构改动，不建议为缩窄通道直接替换整个规划器。
4. 在已有实测误差形成边界后，才设计限速、受看护、可停车的窄道现场验收。当前证据不能给出一个可以直接部署的更小安全半径。

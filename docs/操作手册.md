## 1. 四路编码器 A/B 对调后的连续键盘控制（MOTOR-015）

当前 M1=左前、M2=左后、M3=右前、M4=右后，用户已将四台电机各自的编码器 A/B 线全部
交换。当前改用 `chassis_direct_keyboard` 像普通遥控一样连续控制：按一次方向键后持续运行，
按空格或 `k` 停车，按 `q` 停车退出。本流程不写 PID、不写 Flash、不刷固件。由于改线前
曾出现持续升速，第一次启动仍必须架空观察几秒；确认不会升速且能停车后，才允许落地控制。

### 1.1 构建

用途：只构建底盘厂商库和 `carcar_base`，确认当前测试入口可运行。它只读取源码并更新工作
区的 `build/`、`install/`、`log/` 构建产物，不访问串口、不驱动电机、不修改控制板。预期
两个包构建成功；若失败，停止在此处，不进行硬件动作。

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
/usr/bin/colcon build --symlink-install \
  --packages-select rosmaster_vendor carcar_base
source install/setup.bash
```

### 1.2 启动板载 PID 驱动

风险与恢复：四轮先可靠架空，轮胎附近不得有人、线缆或松动物体，不得带电插拔 A/B 线。
12 V 电机开关必须始终可立即触及。突然升速、持续加速、抖动、尖叫、反向或软件停车无效
时，立即关闭 12 V 电机主电源；关闭电源可中止硬件运动，之后保持断电并退出两个节点。

终端 1 独占串口并启动板载 PID 驱动。启动会重复发送零速度；命令超过 `0.3 s` 未刷新也会
停车。命令会先检查设备存在和串口未被其他进程占用，异常时不会启动。

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
test -e /dev/myserial || { echo "控制板未连接，停止启动"; exit 1; }
if fuser /dev/myserial >/dev/null 2>&1; then
  echo "串口已占用，请正常关闭其他驱动后重试"
  exit 1
fi
ros2 launch carcar_base board_closed_loop_test.launch.py
```

### 1.3 连续键盘控制

终端 2 启动连续键盘。方向键为：`i` 前进、`,` 后退、`j` 左移、`l` 右移、`u` 逆时针
旋转、`o` 顺时针旋转、空格或 `k` 停车、`q` 停车退出。数字 `1～5` 可在停止或运动中
切换速度档；运动中换挡会立即按新速度继续当前方向。命令会持续发布车体速度并改变电机
运动状态，但不修改固件或 PID 参数。

| 档位键 | 直线/横移 | 旋转 |
|---|---:|---:|
| `1` | `0.03 m/s` | `0.10 rad/s` |
| `2` | `0.05 m/s` | `0.20 rad/s` |
| `3` | `0.08 m/s` | `0.30 rad/s` |
| `4` | `0.10 m/s` | `0.40 rad/s` |
| `5` | `0.15 m/s` | `0.50 rad/s` |

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run carcar_base chassis_direct_keyboard --ros-args \
  -p linear_speed:=0.02 -p angular_speed:=0.10 -p command_rate:=10.0
```

首次只按 `i`，架空观察约 2～3 秒后按空格：预期四轮前进、转速稳定而不是继续爬升，并且
立即停车。若正常，再按 `,` 短暂检查后退并停车。两项都正常后，先按 `q`，终端 1 按
`Ctrl+C`，关闭 12 V，将小车放到空旷平整地面；重新按 1.2、1.3 启动后即可按上述键位正常
低速控制。地面首次仍先前进一小段并停车，再逐项检查后退、横移和旋转，禁止靠近台阶。

正常结束顺序是：终端 2 按 `q`，终端 1 按 `Ctrl+C`，最后关闭 12 V。异常时顺序相反：
先断 12 V，再退出程序。请反馈架空和地面时是否还会持续升速、各方向是否正确、空格停车
是否有效；在这些结论确认前不进入里程计或导航测试。

### 1.4 提速后的首次地面验收

用途：架空连续运行和停车正常后，允许直线/横移最高 `0.15 m/s`、旋转最高
`0.50 rad/s`，在空旷平地分级判断板载 PID 的带载起步、稳速、直行和停车。首次键盘仍只
发送 `0.10 m/s` 和 `0.30 rad/s`；通过后才提高到上限。新配置不写控制板 PID 或 Flash；
它只改变 ROS 驱动允许发送的速度上限。原
`board_closed_loop_test.yaml` 保留，异常时可重新使用 1.2、1.3 恢复到低速入口。

先按 1.1 重新构建，使新增配置安装到工作区。随后关闭所有旧键盘和底盘驱动，把小车放在
平整地面，前后至少留出 1 m 空间，远离台阶；12 V 开关保持可立即触及。终端 1 使用地面
配置启动唯一串口驱动：

```bash

  echo "串口已占用，请关闭其他底盘驱动"

fi
ros2 launch carcar_base board_closed_loop_test.launch.py \
  params_file:=$(ros2 pkg prefix carcar_base)/share/carcar_base/config/board_closed_loop_ground_test.yaml
```

终端 2 启动连续键盘；这些参数与驱动上限一致：

```bash

conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
```

首次只按 `i` 前进约 1～2 秒，然后按空格停车。正确现象是：起步后速度稳定、不继续爬升，
四轮均使车体前进，车体没有明显原地偏转，空格后可靠停车。轻微瞬时左右差可以记录，不能
把明显持续跑偏当作通过。突然满速、越跑越快、反向、剧烈抖动、尖叫或空格无效时立即断开
12 V，保持断电并退出，不测试其他方向。前进正常后才依次短测后退、左右横移和旋转，每次
动作之间先停车。`0.10 m/s` 全部正常后，才可把终端 2 的 `linear_speed` 改为 `0.15`、
`angular_speed` 改为 `0.50` 重启键盘，重复同样顺序。正常结束仍为终端 2 按 `q`、终端 1
按 `Ctrl+C`、关闭 12 V。

### 1.5 RQT 在线临时调节板载 PID

用途：控制板当前运动 PID 为全局一组 `Kp/Ki/Kd`，不是四轮分别调节。RQT 中编辑
`motion_kp`、`motion_ki`、`motion_kd` 只会暂存；必须先停车，再把
`motion_pid_apply` 从 `false` 切为 `true` 才会发送。驱动固定使用
`forever=False`，不写 Flash；控制板重启会恢复 Flash 持久参数。允许范围为
`0≤Kp≤10、0≤Ki≤10、0≤Kd≤10`（与 Rosmaster_Lib 硬件限制一致）。

当前 Flash 基准（2026-09-08 实机调参确定并写入）：

```
Kp=8.0   Ki=1.2   Kd=0.8
```

风险与恢复：PID 会直接改变电机闭环响应。调参前四周保持至少 1 m 空间，12 V 开关可立即
触及；每次只改变一个增益，先停车再应用。突然加速、振荡、抖动、尖叫或停车无效时立即
关闭 12 V。恢复方法是保持断电，退出节点，重新给控制板上电；临时 PID 不会保留。

终端 3 启动 RQT 参数界面。它只通过 ROS 参数服务读写正在运行的驱动，不直接打开串口；
预期左侧能选择 `/board_closed_loop_test_driver`，并看到四个 `motion_pid_*` 参数：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run rqt_reconfigure rqt_reconfigure
```

每轮固定顺序：终端 2 按空格或 `k`；在 RQT 填完三项；确认
`motion_pid_apply=false`；再切为 `true`。终端 1 必须显示“已临时应用”及回读值；然后把
`motion_pid_apply` 切回 `false`，为下一次提交做准备。运动中提交会被驱动拒绝。

终端 4 启动四路原始编码器速度曲线。它只订阅 ROS 话题，不控制电机、不改参数；纵轴单位
是 `count/s`，用于比较响应和四轮一致性，尚不能当作已标定的 `m/s`：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run rqt_plot rqt_plot \
  '/chassis_motion_test/encoder_rates/data[0]' \
  '/chassis_motion_test/encoder_rates/data[1]' \
  '/chassis_motion_test/encoder_rates/data[2]' \
  '/chassis_motion_test/encoder_rates/data[3]'
```

当前 Flash 基准 `Kp=8.0, Ki=1.2, Kd=0.8` 已由用户实机调参确定并写入 Flash。后续微调仍使用
RQT 临时写入，确认满意后可使用独立脚本更新 Flash。

导航前希望看到：相同档位重复响应接近；速度上升后能稳定而非周期摆动；正常地面负载下
能恢复到相近编码器速度；直行四路曲线差异可重复且车体无明显持续偏航；零命令可靠停车。
全局 PID 无法修复单独一轮的机械阻力或电机差异，若只有一路长期偏低，应先检查该轮。

### 1.6 将调优后的 PID 写入控制板 Flash

用途：在 RQT 在线调参确认满意后，将最终 PID 写入单片机 Flash 持久保存，使控制板掉电重启后默认使用该参数。

前提与安全：
1. 必须先退出正在运行的底盘驱动（终端按 `Ctrl+C`），确保串口 `/dev/myserial` 独占。
2. 12 V 开关可随时断开。

完整命令：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true

# 确认串口无进程占用
if fuser /dev/myserial >/dev/null 2>&1; then
  echo "串口仍被占用，请先关闭底盘驱动"
  exit 1
fi

python3 scripts/write_pid_to_flash.py
```

预期输出：
- 打印连接成功；
- 打印写入前的 PID 值；
- 执行 `forever=True` 写入；
- 回读并打印写入后的 PID 值；
- 提示 `✓ Flash 写入成功！重启控制板后仍然生效。`。
- 写入后若需继续测试底盘，重新执行 1.2 或 1.4 节启动驱动即可。

### 1.8 纯轮式编码器 Odom 首次标定（ODOM-001）

用途：为四轮麦克纳姆底盘建立纯轮式 `odom -> base_footprint`。新驱动只会把四路**累计编码器**
转换为位姿；不会采用控制板速度遥测来积分。它需要每轮输出轴的实测 `count/rev`、编码器正负号、
轮径、轴距和轮距。轮径 `0.060 m`、轴距 `0.120 m`、轮距 `0.185 m` 已知；四轮 `count/rev`
和计数方向还未测定，所以默认配置故意保持 `wheel_odometry_enabled=false`，不会发布伪造 Odom 或
TF。该流程不改 PID、不写 Flash、不刷固件。

风险与恢复：第一阶段只会由驱动重复发送零速度，电机不应主动转动；但控制板串口必须独占，四轮
仍需可靠架空，12 V 总开关必须可立即关闭。手转轮子时不得把手伸入轮子和车架之间，也不得带电
插拔编码器线。任何异常转动、持续输出或串口报错都立刻关闭 12 V，终端按 `Ctrl+C`，保持断电后
再检查接线。正常结束时先退出键盘，再退出驱动，最后关闭 12 V。

#### 1.8.2 四轮输出轴 10 圈计数与方向

用途：确定每个物理轮在“使车体前进”的方向手转 10 圈时，原始累计编码器变化的带符号 `Δ` 与
`abs(Δ)/10`。这一步只读取编码器；键盘数字键会额外发送零速度，绝不发送非零运动指令。数值将
用于填写 `wheel_counts_per_revolution`；`Δ>0` 对应该端口 `wheel_encoder_signs=+1`，`Δ<0` 对应
`-1`。

终端 1 独占串口并启动标定驱动。它会发送零速度、发布 `/wheel/encoders` 和诊断，但因 Odom 尚未
启用，不发布 `/wheel/odometry`。设备不存在或串口被占用时命令会停止，不能强行启动第二个驱动。

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
test -e /dev/myserial || { echo "控制板未连接，停止标定"; exit 1; }
if fuser /dev/myserial >/dev/null 2>&1; then
  echo "串口已被其他进程占用；先正常退出旧驱动"
  exit 1
fi
ros2 launch carcar_base wheel_odometry.launch.py
```

终端 2 启动只用于计数的键盘。待出现帮助后，按 `1` 记录 M1/左前起点；沿使车体前进的方向手转
该轮**恰好 10 圈**，再按 `1` 记录终点。随后按相同方式完成 `2`=M2/左后、`3`=M3/右前、
`4`=M4/右后，最后按 `p` 打印四行结果。不要按 `i/j/u`，也不要来回补圈；按 `x` 可废弃当前轮
的起点重新开始，按 `q` 安全退出。

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
```

结果应包含四行 `start`、`end`、带符号 `Δ` 和 `count/rev`，其余三个通道应基本不变。请把四行
完整日志反馈回来；不要用猜测值填入
[`wheel_odometry.yaml`](../src/carcar_base/config/wheel_odometry.yaml)。收到实测值后再启用 Odom。

停止与恢复：终端 2 按 `q`，终端 1 按 `Ctrl+C`，最后关闭 12 V。以下只读命令用于确认两个节点
已经退出、串口已释放；它不改文件、不访问电机，预期不再显示底盘进程或串口占用。若仍有占用，
不要拔线或重复启动，先记录进程号并正常停止它。

```bash

conda deactivate 2>/dev/null || true

```

#### 1.8.3 填入实测值后的 Odom 验收

前提：四行 10 圈日志已复核并写入 `wheel_odometry.yaml`，`wheel_odometry_enabled` 已改为 `true`，
且 `wheel_encoder_signs` 已按带符号 `Δ` 填写。此时启动驱动会发布 `/wheel/odometry` 与
`odom -> base_footprint`，但不会接入 IMU、EKF、建图或导航。先将车辆放在空旷平地、在地面贴好

#### RQT：实时调整导航速度上限

用途：在导航链路启动后，以 RQT 修改 DWB 与速度平滑器的**下一条**速度限制。它不直接写控制板 PID、不写 Flash，也不改变底盘看门狗；但参数提交后会立即参与后续导航指令。只在小车静止、周围留有足够空地且 12 V 电机开关可触及时调节。小车出现意外加速、跑偏或即将接触障碍物时，立即关闭 12 V 电机主电源；随后在终端 4 按 `Ctrl+C` 停止导航节点。

打开现有 RQT 的 Parameters 页面，按下列节点和字段成组修改。默认永久值为表中数值，保存源配置后重启导航仍会恢复该组；试验中的临时 RQT 改动不写回 YAML。

| RQT 节点 | 参数 | 默认值 | 作用 |
|---|---|---:|---|
| `/controller_server` | `FollowPath.max_vel_x` | `0.18` | DWB 前进候选速度上限（m/s） |
| `/controller_server` | `FollowPath.max_speed_xy` | `0.18` | DWB 平面速度总上限（m/s），必须不小于 `max_vel_x` |
| `/controller_server` | `FollowPath.max_vel_theta` | `0.36` | DWB 旋转候选速度绝对值上限（rad/s） |
| `/velocity_smoother` | `max_velocity` | `[0.18, 0.0, 0.36]` | 最终前进、横移、逆时针速度上限 |
| `/velocity_smoother` | `min_velocity` | `[0.0, 0.0, -0.36]` | 最终前进、横移、顺时针速度下限 |

每次调整线速度时，同时改 `FollowPath.max_vel_x`、`FollowPath.max_speed_xy` 和 `max_velocity[0]`；每次调整旋转速度时，同时改 `FollowPath.max_vel_theta`、`max_velocity[2]` 和 `min_velocity[2]`（负值）。保持 `max_accel=[0.20,0.0,0.40]` 与 `max_decel=[-0.20,0.0,-0.40]` 不变，先单独观察提高上限后的起步、停车和旋转方向。

### 8.5 短距离单点到点任务（阶段二）

在已知平整空闲区域执行直线到点与转向到点，每类连续执行 3 次并记录指标：

#### 8.5.1 直线到点（约 1.0 m）
在终端 6 发送前进 1.0 m 目标（或在 RViz 使用 **2D Goal Pose** 工具）：

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: 'map'}, pose: {position: {x: 1.00, y: 0.00, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}}}}"
```

观察要点：
- 全程横向速度 `/cmd_vel_nav.linear.y == 0`，`/cmd_vel.linear.y == 0`；
- 前向线速度不超过 `0.18 m/s`，角速度绝对值不超过 `0.36 rad/s`；
- 到达目标后平稳制动停车，Action 状态为 `STATUS_SUCCEEDED`；
- 用卷尺测量地面标线实际误差，核验直线欧氏距离误差 $\le 0.15\text{ m}$，航向角偏差 $\le 10^\circ$。

#### 8.5.2 转向到点（含约 90° 转角）
在终端 6 发送需要拐弯的目标（例如左前上方目标）：

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: 'map'}, pose: {position: {x: 0.80, y: 0.60, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.707, w: 0.707}}}}"
```

观察要点：
- DWB 自行规划前向弧线或原地旋转调头，不倒车、不横移；
- 连续 3 次到点稳定，无持续偏航或震荡。

#### 8.5.3 旋转方向异常的最小复现与判别

用途：在小车已静止、周围 `0.5 m` 内无障碍物时，记录 DWB 选择的旋转指令与实际车身方向。此检查只订阅话题，不会发送新的导航目标、修改参数或直接驱动电机；仅在已有目标正在使小车原地旋转时运行。预期是：ROS 中 `angular.z > 0` 为逆时针，`angular.z < 0` 为顺时针；从当前航向到目标方向的夹角小于 `180°` 时，应优先采用该较短方向。若车身异常转动，立即切断 12 V 电机主电源，再在发送目标的终端取消任务。

```bash

conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
```

### 8.6 停车与超时安全检查（阶段三）

#### 8.6.2 速度源中断与看门狗超时

2. 发送运动目标使轮子平稳转动；

### 8.7 障碍阻断安全停车（阶段四）

1. 在已知可通行路径正前方预先摆放能被雷达平面（离地 217 mm）稳定探测的高大障碍物（纸箱或挡板），确保彻底阻断全部可行通道。
2. 保持障碍物静止，在障碍物后方发送目标点。
3. 预期行为：
   - 全局/局部代价地图立即刷新出致命障碍与膨胀区；
   - 全局规划器无法生成穿越障碍的无碰撞路径，或者控制器检测到前方路径被阻断；
   - **行为树严格禁止自动脱困自转、倒车或清除代价地图**；
   - 规划/控制失败后，Nav2 Action 直接宣告 `STATUS_ABORTED` 并主动发送零速度停车；
   - 小车全程保持停止或在障碍前安全刹停，严禁与障碍物发生任何物理接触。

### 8.8 正常停机顺序

1. **终端 6**：确认无活动中的导航 action；
2. **终端 5**：按 `Ctrl+C` 停止 rosbag 录制；
3. **终端 4**：按 `Ctrl+C` 退出导航节点（`navigation.launch.xml`）；
4. **终端 3**：按 `Ctrl+C` 退出定位与 RViz（`localization.launch.xml`）；
5. **终端 2**：按 `Ctrl+C` 退出雷达（`lidar.launch.py`，确认雷达停转）；
6. **终端 1**：按 `Ctrl+C` 退出底盘驱动（`robot.launch.py`）；
7. **硬件电源**：立即关闭小车 12 V 电机主电源开关。
- **数据与日志保留**：若出现异常中断，保留现场已生成的 `log/${RUN_ID}_bag`、`log/${RUN_ID}_poses.log` 及不完整地图文件作为故障排查证据；禁止在同一轮次中现场随意更改参数。
- **串口占用**：若启动报错提示串口占用，使用 `fuser -v /dev/myserial` 定位残留进程 PID 并用 `kill <PID>` 结束。

## 9. NAV-004：扩大建图与新地图重载

**目的**：在现有 SLAM Toolbox 链路基础上建立覆盖更大路线的新地图，存为带时间戳的独立文件对，验证独立重载通过后方可用于定位。
**读写内容**：写入 `src/carcar_navigation/maps/` 下新地图 YAML 和 PGM 文件；不修改旧地图。
**硬件影响**：需启动底盘驱动和雷达，操作人员低速遥控小车建图；建图期间禁止启动 AMCL 和 Nav2 防止多节点抢占 `map→odom`。

**退出停车**：键盘控制节点按 `q` 停车退出；再 `Ctrl+C` 退出底盘驱动。
**紧急断电**：异常运动时立即关闭 12 V 电机主电源。

### 12.1 实验边界与当前约束

实验入口的 AMCL 只在扫描、轮式里程计和扫描时刻 TF 新鲜时允许恢复。定位健康由静态地图端点
命中率、粒子数量/离散度及连续样本共同决定；协方差变小不单独作为通过条件。数据过期会终止当前
导航动作并保持停车，不会请求全局重定位。

正常 DWB 始终只前进和旋转。恢复顺序为等待 2 秒、最多 90° 转向、后方净空检查通过才后退；后退
最多 `0.15 m`、`0.05 m/s`、6 秒。恢复动作也发布到 `/cmd_vel_nav`，再经速度平滑器输出。

| 项目 | 稳定对照 | 本节实验值/行为 |
|---|---|---|
| AMCL 更新与随机恢复 | `0.10 m / 0.10 rad`，恢复系数为零 | `0.05 m / 0.05 rad`，`fast=0.1`、`slow=0.001` |
| 控制器频率与 TF 容限 | DWB `20.0 Hz`，TF 容忍 `0.2 s` | DWB `10.0 Hz`，TF 容忍 `0.3 s`（与 10Hz 雷达/5Hz 地图匹配） |
| 代价膨胀 | 全局关闭、局部 `0.18 m / 10.0` | 全局 `0.30 m / 5.0`，局部 `0.15 m / 5.0`（车身包络 `0.28×0.26m`） |
| DWB | `BaseObstacle`，最高 `0.18 m/s` | `ObstacleFootprint`，最高 `0.15 m/s`，`sim_time=2.5 s` |
| 无进展 | 仅平移、`0.05 m / 60 s` | 位移或转角、`0.05 m / 0.2 rad / 20 s` |
| 恢复预算 | 无恢复树 | 静止更新 10 秒；一次全局重定位再给 20 秒；恢复节点总尝试最多 3 次 |

其它仍生效的边界：控制计算连续失败容忍 `2 s`；平滑器输入超时 `0.30 s`；底盘命令超时 `0.30 s`；

3. 自动随节点启动 `nav_event_logger`，在控制台每秒输出 1 行清晰的中文状态摘要，并在阶段切换（等待定位、规划、路径跟随、重规划、恢复等待、转向、后方检查、倒车、到达、取消、失败）时即时输出告警与流转信息；
4. 自动在后台创建 `log/nav_sessions/时间_PID/` 会话目录，写入 `session_info.json`、`active_config.yaml`、行为树 XML、`events.jsonl`、`events.log`，并启用 rosbag2 自动按 1 GiB 分卷录制关键数据链路（设 10 GiB 与磁盘 <2 GiB 保护限额）。

**终端 5：导航全链路只读观察与状态诊断**

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash && source install/setup.bash
# 运行扩展后的全链路状态诊断工具（检查 5 个导航节点生命周期状态、定位健康门控）
ros2 run carcar_navigation check_nav_link
```

> [!TIP]
> 终端 5 仅用于 `check_nav_link` 链路诊断、`nav_log_tool` 会话与故障分析或监听 `/rosout`。只有在确认所有导航组件全部 `active` 且 `/localization_monitor/ready` 为 `TRUE` 时，方可在 RViz 中使用 **2D Goal Pose** 发送目标。

### 12.4.1 导航会话分析、时间线与离线回看工具 (nav_log_tool)

导航实验启动后，后台 `nav_event_logger` 节点自动在 `log/nav_sessions/` 下记录完整多维度会话包。
操作员可在任意终端使用 `nav_log_tool` 查询会话、排查阻断原因或纯离线回看（**零驱动输出声明：本工具为只读分析工具，绝不向 ROS 网络发布指令**）：

```bash
cd /home/jetson/luhao/my_nav_carcar
source /opt/ros/humble/setup.bash && source install/setup.bash

# 1. 列出历史上所有导航会话、开始时间、目标数、事件数与录包大小
ros2 run carcar_navigation nav_log_tool --sessions

# 2. 呈现指定会话的完整事件时序流转时间线
ros2 run carcar_navigation nav_log_tool --timeline <会话ID>

# 3. 汇总指定会话的所有故障、阻断与拒绝原因 (含 RearClear 结构化拒绝与 DWB 淘汰)
ros2 run carcar_navigation nav_log_tool --failures <会话ID>

# 4. 纯离线终端时序回看 (直接读取本地 JSONL 与日志，不向 ROS 网络发布任何消息)
ros2 run carcar_navigation nav_log_tool --replay-session <会话ID>

# 5. 对已完成结束的会话打包归档 (.tar.gz)
ros2 run carcar_navigation nav_log_tool --export <会话ID> [可选输出路径]

# 6. 【旧目标命令提取】提取历史受阻目标点的一键重放命令（仅生成文本命令，不作日志回看）
ros2 run carcar_navigation nav_log_tool --replay 1
```

### 12.6 验收顺序和停止/回退

定位先测约 `0.3 m/10°` 与 `1 m/30°` 初始偏差、途中人为错位、扫描中断、TF 过期和恢复超时；
每项记录成功率、恢复耗时和残差。绕障在前进路线上放置静止垃圾桶（保持单侧 ≥0.6 米空旷通道），
左、右各重复五次，并增加完全封路、障碍撤走、掉头、后方受阻；不把一次成功写为稳定通过。
观察终端 4 实时刷新的“正在跟随 + 正在重规划”及绕障表现。

正常停止顺序：先在发送 action 的终端按 `Ctrl+C` 取消目标；再停止终端 4 实验导航（自动安全停录会话包并生成总结）、
实验定位、雷达和底盘。最后关闭 12 V 电机主电源。异常运动、碰撞风险或软件失去响应时，顺序反过来：
**立即关闭 12 V**，再逐个 `Ctrl+C` 退出。恢复稳定对照时，停止实验终端后按第 8 节分别启动
`localization.launch.xml` 与 `navigation.launch.xml`；实验 YAML、地图和无恢复行为树均保留不覆盖。

## 1. 四路编码器 A/B 对调后的连续键盘控制（MOTOR-015）

当前 M1=左前、M2=左后、M3=右前、M4=右后，用户已将四台电机各自的编码器 A/B 线全部
交换。当前改用 `chassis_direct_keyboard` 像普通遥控一样连续控制：按一次方向键后持续运行，
按空格或 `k` 停车，按 `q` 停车退出。本流程不写 PID、不写 Flash、不刷固件。由于改线前
曾出现持续升速，第一次启动仍必须架空观察几秒；确认不会升速且能停车后，才允许落地控制。

### 1.1 构建

用途：只构建底盘厂商库和 `carcar_base`，确认当前测试入口可运行。它只读取源码并更新工作
区的 `build/`、`install/`、`log/` 构建产物，不访问串口、不驱动电机、不修改控制板。预期
两个包构建成功；若失败，停止在此处，不进行硬件动作。

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
/usr/bin/colcon build --symlink-install \
  --packages-select rosmaster_vendor carcar_base
source install/setup.bash
```

### 1.2 启动板载 PID 驱动

风险与恢复：四轮先可靠架空，轮胎附近不得有人、线缆或松动物体，不得带电插拔 A/B 线。
12 V 电机开关必须始终可立即触及。突然升速、持续加速、抖动、尖叫、反向或软件停车无效
时，立即关闭 12 V 电机主电源；关闭电源可中止硬件运动，之后保持断电并退出两个节点。

终端 1 独占串口并启动板载 PID 驱动。启动会重复发送零速度；命令超过 `0.3 s` 未刷新也会
停车。命令会先检查设备存在和串口未被其他进程占用，异常时不会启动。

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
test -e /dev/myserial || { echo "控制板未连接，停止启动"; exit 1; }
if fuser /dev/myserial >/dev/null 2>&1; then
  echo "串口已占用，请正常关闭其他驱动后重试"
  exit 1
fi
ros2 launch carcar_base board_closed_loop_test.launch.py
```

### 1.3 连续键盘控制

终端 2 启动连续键盘。方向键为：`i` 前进、`,` 后退、`j` 左移、`l` 右移、`u` 逆时针
旋转、`o` 顺时针旋转、空格或 `k` 停车、`q` 停车退出。数字 `1～5` 可在停止或运动中
切换速度档；运动中换挡会立即按新速度继续当前方向。命令会持续发布车体速度并改变电机
运动状态，但不修改固件或 PID 参数。

| 档位键 | 直线/横移 | 旋转 |
|---|---:|---:|
| `1` | `0.03 m/s` | `0.10 rad/s` |
| `2` | `0.05 m/s` | `0.20 rad/s` |
| `3` | `0.08 m/s` | `0.30 rad/s` |
| `4` | `0.10 m/s` | `0.40 rad/s` |
| `5` | `0.15 m/s` | `0.50 rad/s` |

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run carcar_base chassis_direct_keyboard --ros-args \
  -p linear_speed:=0.02 -p angular_speed:=0.10 -p command_rate:=10.0
```

首次只按 `i`，架空观察约 2～3 秒后按空格：预期四轮前进、转速稳定而不是继续爬升，并且
立即停车。若正常，再按 `,` 短暂检查后退并停车。两项都正常后，先按 `q`，终端 1 按
`Ctrl+C`，关闭 12 V，将小车放到空旷平整地面；重新按 1.2、1.3 启动后即可按上述键位正常
低速控制。地面首次仍先前进一小段并停车，再逐项检查后退、横移和旋转，禁止靠近台阶。

正常结束顺序是：终端 2 按 `q`，终端 1 按 `Ctrl+C`，最后关闭 12 V。异常时顺序相反：
先断 12 V，再退出程序。请反馈架空和地面时是否还会持续升速、各方向是否正确、空格停车
是否有效；在这些结论确认前不进入里程计或导航测试。

### 1.4 提速后的首次地面验收

用途：架空连续运行和停车正常后，允许直线/横移最高 `0.15 m/s`、旋转最高
`0.50 rad/s`，在空旷平地分级判断板载 PID 的带载起步、稳速、直行和停车。首次键盘仍只
发送 `0.10 m/s` 和 `0.30 rad/s`；通过后才提高到上限。新配置不写控制板 PID 或 Flash；
它只改变 ROS 驱动允许发送的速度上限。原
`board_closed_loop_test.yaml` 保留，异常时可重新使用 1.2、1.3 恢复到低速入口。

先按 1.1 重新构建，使新增配置安装到工作区。随后关闭所有旧键盘和底盘驱动，把小车放在
平整地面，前后至少留出 1 m 空间，远离台阶；12 V 开关保持可立即触及。终端 1 使用地面
配置启动唯一串口驱动：

```bash

  echo "串口已占用，请关闭其他底盘驱动"
  exit 1
fi
ros2 launch carcar_base board_closed_loop_test.launch.py \
  params_file:=$(ros2 pkg prefix carcar_base)/share/carcar_base/config/board_closed_loop_ground_test.yaml
```

终端 2 启动连续键盘；这些参数与驱动上限一致：

```bash

conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
```

首次只按 `i` 前进约 1～2 秒，然后按空格停车。正确现象是：起步后速度稳定、不继续爬升，
四轮均使车体前进，车体没有明显原地偏转，空格后可靠停车。轻微瞬时左右差可以记录，不能
把明显持续跑偏当作通过。突然满速、越跑越快、反向、剧烈抖动、尖叫或空格无效时立即断开
12 V，保持断电并退出，不测试其他方向。前进正常后才依次短测后退、左右横移和旋转，每次
动作之间先停车。`0.10 m/s` 全部正常后，才可把终端 2 的 `linear_speed` 改为 `0.15`、
`angular_speed` 改为 `0.50` 重启键盘，重复同样顺序。正常结束仍为终端 2 按 `q`、终端 1
按 `Ctrl+C`、关闭 12 V。

### 1.5 RQT 在线临时调节板载 PID

用途：控制板当前运动 PID 为全局一组 `Kp/Ki/Kd`，不是四轮分别调节。RQT 中编辑
`motion_kp`、`motion_ki`、`motion_kd` 只会暂存；必须先停车，再把
`motion_pid_apply` 从 `false` 切为 `true` 才会发送。驱动固定使用
`forever=False`，不写 Flash；控制板重启会恢复 Flash 持久参数。允许范围为
`0≤Kp≤10、0≤Ki≤10、0≤Kd≤10`（与 Rosmaster_Lib 硬件限制一致）。

当前 Flash 基准（2026-09-08 实机调参确定并写入）：

```
Kp=8.0   Ki=1.2   Kd=0.8
```

风险与恢复：PID 会直接改变电机闭环响应。调参前四周保持至少 1 m 空间，12 V 开关可立即
触及；每次只改变一个增益，先停车再应用。突然加速、振荡、抖动、尖叫或停车无效时立即
关闭 12 V。恢复方法是保持断电，退出节点，重新给控制板上电；临时 PID 不会保留。

终端 3 启动 RQT 参数界面。它只通过 ROS 参数服务读写正在运行的驱动，不直接打开串口；
预期左侧能选择 `/board_closed_loop_test_driver`，并看到四个 `motion_pid_*` 参数：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run rqt_reconfigure rqt_reconfigure
```

每轮固定顺序：终端 2 按空格或 `k`；在 RQT 填完三项；确认
`motion_pid_apply=false`；再切为 `true`。终端 1 必须显示“已临时应用”及回读值；然后把
`motion_pid_apply` 切回 `false`，为下一次提交做准备。运动中提交会被驱动拒绝。

终端 4 启动四路原始编码器速度曲线。它只订阅 ROS 话题，不控制电机、不改参数；纵轴单位
是 `count/s`，用于比较响应和四轮一致性，尚不能当作已标定的 `m/s`：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run rqt_plot rqt_plot \
  '/chassis_motion_test/encoder_rates/data[0]' \
  '/chassis_motion_test/encoder_rates/data[1]' \
  '/chassis_motion_test/encoder_rates/data[2]' \
  '/chassis_motion_test/encoder_rates/data[3]'
```

当前 Flash 基准 `Kp=8.0, Ki=1.2, Kd=0.8` 已由用户实机调参确定并写入 Flash。后续微调仍使用
RQT 临时写入，确认满意后可使用独立脚本更新 Flash。

导航前希望看到：相同档位重复响应接近；速度上升后能稳定而非周期摆动；正常地面负载下
能恢复到相近编码器速度；直行四路曲线差异可重复且车体无明显持续偏航；零命令可靠停车。
全局 PID 无法修复单独一轮的机械阻力或电机差异，若只有一路长期偏低，应先检查该轮。

### 1.6 将调优后的 PID 写入控制板 Flash

用途：在 RQT 在线调参确认满意后，将最终 PID 写入单片机 Flash 持久保存，使控制板掉电重启后默认使用该参数。

前提与安全：
1. 必须先退出正在运行的底盘驱动（终端按 `Ctrl+C`），确保串口 `/dev/myserial` 独占。
2. 12 V 开关可随时断开。

完整命令：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true

# 确认串口无进程占用
if fuser /dev/myserial >/dev/null 2>&1; then
  echo "串口仍被占用，请先关闭底盘驱动"
  exit 1
fi

python3 scripts/write_pid_to_flash.py
```

预期输出：
- 打印连接成功；
- 打印写入前的 PID 值；
- 执行 `forever=True` 写入；
- 回读并打印写入后的 PID 值；
- 提示 `✓ Flash 写入成功！重启控制板后仍然生效。`。
- 写入后若需继续测试底盘，重新执行 1.2 或 1.4 节启动驱动即可。

### 1.8 纯轮式编码器 Odom 首次标定（ODOM-001）

用途：为四轮麦克纳姆底盘建立纯轮式 `odom -> base_footprint`。新驱动只会把四路**累计编码器**
转换为位姿；不会采用控制板速度遥测来积分。它需要每轮输出轴的实测 `count/rev`、编码器正负号、
轮径、轴距和轮距。轮径 `0.060 m`、轴距 `0.120 m`、轮距 `0.185 m` 已知；四轮 `count/rev`
和计数方向还未测定，所以默认配置故意保持 `wheel_odometry_enabled=false`，不会发布伪造 Odom 或
TF。该流程不改 PID、不写 Flash、不刷固件。

风险与恢复：第一阶段只会由驱动重复发送零速度，电机不应主动转动；但控制板串口必须独占，四轮
仍需可靠架空，12 V 总开关必须可立即关闭。手转轮子时不得把手伸入轮子和车架之间，也不得带电
插拔编码器线。任何异常转动、持续输出或串口报错都立刻关闭 12 V，终端按 `Ctrl+C`，保持断电后
再检查接线。正常结束时先退出键盘，再退出驱动，最后关闭 12 V。

#### 1.8.2 四轮输出轴 10 圈计数与方向

用途：确定每个物理轮在“使车体前进”的方向手转 10 圈时，原始累计编码器变化的带符号 `Δ` 与
`abs(Δ)/10`。这一步只读取编码器；键盘数字键会额外发送零速度，绝不发送非零运动指令。数值将
用于填写 `wheel_counts_per_revolution`；`Δ>0` 对应该端口 `wheel_encoder_signs=+1`，`Δ<0` 对应
`-1`。

终端 1 独占串口并启动标定驱动。它会发送零速度、发布 `/wheel/encoders` 和诊断，但因 Odom 尚未
启用，不发布 `/wheel/odometry`。设备不存在或串口被占用时命令会停止，不能强行启动第二个驱动。

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
test -e /dev/myserial || { echo "控制板未连接，停止标定"; exit 1; }
if fuser /dev/myserial >/dev/null 2>&1; then
  echo "串口已被其他进程占用；先正常退出旧驱动"
  exit 1
fi
ros2 launch carcar_base wheel_odometry.launch.py
```

终端 2 启动只用于计数的键盘。待出现帮助后，按 `1` 记录 M1/左前起点；沿使车体前进的方向手转
该轮**恰好 10 圈**，再按 `1` 记录终点。随后按相同方式完成 `2`=M2/左后、`3`=M3/右前、
`4`=M4/右后，最后按 `p` 打印四行结果。不要按 `i/j/u`，也不要来回补圈；按 `x` 可废弃当前轮
的起点重新开始，按 `q` 安全退出。

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash

ros2 run carcar_base chassis_motion_keyboard --ros-args \
```

结果应包含四行 `start`、`end`、带符号 `Δ` 和 `count/rev`，其余三个通道应基本不变。请把四行
完整日志反馈回来；不要用猜测值填入
[`wheel_odometry.yaml`](../src/carcar_base/config/wheel_odometry.yaml)。收到实测值后再启用 Odom。

停止与恢复：终端 2 按 `q`，终端 1 按 `Ctrl+C`，最后关闭 12 V。以下只读命令用于确认两个节点
已经退出、串口已释放；它不改文件、不访问电机，预期不再显示底盘进程或串口占用。若仍有占用，
不要拔线或重复启动，先记录进程号并正常停止它。

```bash

conda deactivate 2>/dev/null || true

```

#### 1.8.3 填入实测值后的 Odom 验收

前提：四行 10 圈日志已复核并写入 `wheel_odometry.yaml`，`wheel_odometry_enabled` 已改为 `true`，
且 `wheel_encoder_signs` 已按带符号 `Δ` 填写。此时启动驱动会发布 `/wheel/odometry` 与
`odom -> base_footprint`，但不会接入 IMU、EKF、建图或导航。先将车辆放在空旷平地、在地面贴好

#### RQT：实时调整导航速度上限

用途：在导航链路启动后，以 RQT 修改 DWB 与速度平滑器的**下一条**速度限制。它不直接写控制板 PID、不写 Flash，也不改变底盘看门狗；但参数提交后会立即参与后续导航指令。只在小车静止、周围留有足够空地且 12 V 电机开关可触及时调节。小车出现意外加速、跑偏或即将接触障碍物时，立即关闭 12 V 电机主电源；随后在终端 4 按 `Ctrl+C` 停止导航节点。

打开现有 RQT 的 Parameters 页面，按下列节点和字段成组修改。默认永久值为表中数值，保存源配置后重启导航仍会恢复该组；试验中的临时 RQT 改动不写回 YAML。

| RQT 节点 | 参数 | 默认值 | 作用 |
|---|---|---:|---|
| `/controller_server` | `FollowPath.max_vel_x` | `0.18` | DWB 前进候选速度上限（m/s） |
| `/controller_server` | `FollowPath.max_speed_xy` | `0.18` | DWB 平面速度总上限（m/s），必须不小于 `max_vel_x` |
| `/controller_server` | `FollowPath.max_vel_theta` | `0.36` | DWB 旋转候选速度绝对值上限（rad/s） |
| `/velocity_smoother` | `max_velocity` | `[0.18, 0.0, 0.36]` | 最终前进、横移、逆时针速度上限 |
| `/velocity_smoother` | `min_velocity` | `[0.0, 0.0, -0.36]` | 最终前进、横移、顺时针速度下限 |

每次调整线速度时，同时改 `FollowPath.max_vel_x`、`FollowPath.max_speed_xy` 和 `max_velocity[0]`；每次调整旋转速度时，同时改 `FollowPath.max_vel_theta`、`max_velocity[2]` 和 `min_velocity[2]`（负值）。保持 `max_accel=[0.20,0.0,0.40]` 与 `max_decel=[-0.20,0.0,-0.40]` 不变，先单独观察提高上限后的起步、停车和旋转方向。

### 8.5 短距离单点到点任务（阶段二）

在已知平整空闲区域执行直线到点与转向到点，每类连续执行 3 次并记录指标：

#### 8.5.1 直线到点（约 1.0 m）
在终端 6 发送前进 1.0 m 目标（或在 RViz 使用 **2D Goal Pose** 工具）：

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: 'map'}, pose: {position: {x: 1.00, y: 0.00, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}}}}"
```

观察要点：
- 全程横向速度 `/cmd_vel_nav.linear.y == 0`，`/cmd_vel.linear.y == 0`；
- 前向线速度不超过 `0.18 m/s`，角速度绝对值不超过 `0.36 rad/s`；
- 到达目标后平稳制动停车，Action 状态为 `STATUS_SUCCEEDED`；
- 用卷尺测量地面标线实际误差，核验直线欧氏距离误差 $\le 0.15\text{ m}$，航向角偏差 $\le 10^\circ$。

#### 8.5.2 转向到点（含约 90° 转角）
在终端 6 发送需要拐弯的目标（例如左前上方目标）：

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: 'map'}, pose: {position: {x: 0.80, y: 0.60, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.707, w: 0.707}}}}"
```

观察要点：
- DWB 自行规划前向弧线或原地旋转调头，不倒车、不横移；
- 连续 3 次到点稳定，无持续偏航或震荡。

#### 8.5.3 旋转方向异常的最小复现与判别

用途：在小车已静止、周围 `0.5 m` 内无障碍物时，记录 DWB 选择的旋转指令与实际车身方向。此检查只订阅话题，不会发送新的导航目标、修改参数或直接驱动电机；仅在已有目标正在使小车原地旋转时运行。预期是：ROS 中 `angular.z > 0` 为逆时针，`angular.z < 0` 为顺时针；从当前航向到目标方向的夹角小于 `180°` 时，应优先采用该较短方向。若车身异常转动，立即切断 12 V 电机主电源，再在发送目标的终端取消任务。

```bash

conda deactivate 2>/dev/null || true

source install/setup.bash
```

### 8.6 停车与超时安全检查（阶段三）

#### 8.6.2 速度源中断与看门狗超时

### 8.7 障碍阻断安全停车（阶段四）

1. 在已知可通行路径正前方预先摆放能被雷达平面（离地 217 mm）稳定探测的高大障碍物（纸箱或挡板），确保彻底阻断全部可行通道。
2. 保持障碍物静止，在障碍物后方发送目标点。
3. 预期行为：
   - 全局/局部代价地图立即刷新出致命障碍与膨胀区；
   - 全局规划器无法生成穿越障碍的无碰撞路径，或者控制器检测到前方路径被阻断；
   - **行为树严格禁止自动脱困自转、倒车或清除代价地图**；
   - 规划/控制失败后，Nav2 Action 直接宣告 `STATUS_ABORTED` 并主动发送零速度停车；
   - 小车全程保持停止或在障碍前安全刹停，严禁与障碍物发生任何物理接触。

### 8.8 正常停机顺序

1. **终端 6**：确认无活动中的导航 action；
2. **终端 5**：按 `Ctrl+C` 停止 rosbag 录制；
3. **终端 4**：按 `Ctrl+C` 退出导航节点（`navigation.launch.xml`）；
4. **终端 3**：按 `Ctrl+C` 退出定位与 RViz（`localization.launch.xml`）；
5. **终端 2**：按 `Ctrl+C` 退出雷达（`lidar.launch.xml`，确认雷达停转）；
6. **终端 1**：按 `Ctrl+C` 退出底盘驱动（`robot.launch.xml`）；
7. **硬件电源**：立即关闭小车 12 V 电机主电源开关。
- **数据与日志保留**：若出现异常中断，保留现场已生成的 `log/${RUN_ID}_bag`、`log/${RUN_ID}_poses.log` 及不完整地图文件作为故障排查证据；禁止在同一轮次中现场随意更改参数。
- **串口占用**：若启动报错提示串口占用，使用 `fuser -v /dev/myserial` 定位残留进程 PID 并用 `kill <PID>` 结束。

## 9. NAV-004：扩大建图与新地图重载

**目的**：在现有 SLAM Toolbox 链路基础上建立覆盖更大路线的新地图，存为带时间戳的独立文件对，验证独立重载通过后方可用于定位。
**读写内容**：写入 `src/carcar_navigation/maps/` 下新地图 YAML 和 PGM 文件；不修改旧地图。
**硬件影响**：需启动底盘驱动和雷达，操作人员低速遥控小车建图；建图期间禁止启动 AMCL 和 Nav2 防止多节点抢占 `map→odom`。

**退出停车**：键盘控制节点按 `q` 停车退出；再 `Ctrl+C` 退出底盘驱动。
**紧急断电**：异常运动时立即关闭 12 V 电机主电源。

### 12.1 实验边界与当前约束

实验入口的 AMCL 只在扫描、轮式里程计和扫描时刻 TF 新鲜时允许恢复。定位健康由静态地图端点
命中率、粒子数量/离散度及连续样本共同决定；协方差变小不单独作为通过条件。数据过期会终止当前
导航动作并保持停车，不会请求全局重定位。

正常 DWB 始终只前进和旋转。恢复顺序为等待 2 秒、最多 90° 转向、后方净空检查通过才后退；后退
最多 `0.15 m`、`0.05 m/s`、6 秒。恢复动作也发布到 `/cmd_vel_nav`，再经速度平滑器输出。

| 项目 | 稳定对照 | 本节实验值/行为 |
|---|---|---|
| AMCL 更新与随机恢复 | `0.10 m / 0.10 rad`，恢复系数为零 | `0.05 m / 0.05 rad`，`fast=0.1`、`slow=0.001` |
| 控制器频率与 TF 容限 | DWB `20.0 Hz`，TF 容忍 `0.2 s` | DWB `10.0 Hz`，TF 容忍 `0.3 s`（与 10Hz 雷达/5Hz 地图匹配） |
| 代价膨胀 | 全局关闭、局部 `0.18 m / 10.0` | 全局 `0.30 m / 5.0`，局部 `0.15 m / 5.0`（车身包络 `0.28×0.26m`） |
| DWB | `BaseObstacle`，最高 `0.18 m/s` | `ObstacleFootprint`，最高 `0.15 m/s`，`sim_time=2.5 s` |
| 无进展 | 仅平移、`0.05 m / 60 s` | 位移或转角、`0.05 m / 0.2 rad / 20 s` |
| 恢复预算 | 无恢复树 | 静止更新 10 秒；一次全局重定位再给 20 秒；恢复节点总尝试最多 3 次 |

其它仍生效的边界：控制计算连续失败容忍 `2 s`；平滑器输入超时 `0.30 s`；底盘命令超时 `0.30 s`；
全局重规划约 `1 Hz`；未知区域禁止全局规划。局部地图 `5 Hz` 更新、`2 Hz` 显示，全局地图 `1 Hz`
更新和显示。普通膨胀格是软代价，致命障碍、内切膨胀格、未知格才淘汰轨迹。RearClear 后方净空话题

2. **Groot 监视器与桥接已默认停用关闭**（参数 `start_bt_monitor=false`、`start_groot=false`），彻底避免窗口弹窗抢占与桥接维护负担；
3. 自动随节点启动 `nav_event_logger`，在控制台每秒输出 1 行清晰的中文状态摘要，并在阶段切换（等待定位、规划、路径跟随、重规划、恢复等待、转向、后方检查、倒车、到达、取消、失败）时即时输出告警与流转信息；
4. 自动在后台创建 `log/nav_sessions/时间_PID/` 会话目录，持续写入会话状态、配置、行为树、事件和终端摘要。默认 `record_raw_bag=false`，原始 rosbag 未启用，文本日志仍正常记录；可选录包限制见第 16 节。

## 14. NAV-012：墙角绕行、进展停滞识别与有序脱困实验 (套餐 B + 进阶恢复)

2026-09-17 修订：本节描述早期实验设计。2026-09-16 实机暴露了恢复回调与抢占机制缺陷；当前实现、边界与操作以[第 18 节](#18-nav-012-回调恢复监督与速度联锁修复)为准。旧离线通过不能当作实机恢复通过。

### 14.1 适用范围、核心机制与安全边界

本流程用于解决小车在墙角、狭窄通道或动态障碍受阻时，由于局部速度过小/原地微晃导致的“伪进展”卡死，以及倒车误判数据过期与无限重试问题：
1. **墙角绕行 (RotationShimController 包裹 DWB)**：
   - 航向误差超过 `0.60 rad` (约 34°) 且离路径采样点超过 `0.30 m` 时，触发原地旋转对齐路径方向（旋转角速度 `0.30 rad/s`）。
   - 航向误差收敛至 `0.25 rad` (约 14°) 时退出旋转，平滑切换回主 DWB 巡航。
   - 原地转向阶段执行完整多边形包络扫掠检查，遇阻即刻安全停止。
2. **进展停滞识别 (ProgressGuard)**：
   - 5.0 秒内直线行驶位移不足 `0.03 m`，或 5.0 秒内转向航向误差未收敛缩减超过 `0.10 rad`，判定为无有效进展（单次转向总预算上限 `15.0 s`）。
   - 识别出停滞后主动中断跟随，交由行为树进入恢复分支。
3. **有序受控递进脱困 (Sequential Recovery)**：
   - 第一级（后方安全倒车）：`RearClear` 校验雷达新鲜度与倒车新进入体积的致命障碍 (254/255)。当前包络已贴住前方障碍时，只要后方扫掠干净仍允许后撤 `0.10 m`（速度 `0.05 m/s`）。单次受阻累计最大倒车限额 `0.30 m`；正常巡航行驶超过 `0.20 m` 自动重置额度。
   - 第二级（受控朝向路线转向）：若倒车不可用或额度用尽，执行 `ControlledSpin` 转向路径前进切线方向（最大转角 `90°`，预算 `10 s`）。
   - 第三级（原地观察等待）：若仍无法脱困，停在原地观察等待最长 `30 s`（`ParkAndObserve`），每秒轮询前方通道与定位健康。
   - 第四级（终末安全退出）：观察超时或 6 次递进重试全部失败后，标记目标失败，停止输出并报警，禁止原地无限循环。
4. **纯轮式里程计基线保持**：不接入 IMU 姿态或加速度融合，状态估计源严格保持为纯轮式 Odom。

## 16. 导航状态观测与多维停车阻断归因诊断（NAV-013）

### 16.1 适用范围与核心能力

在导航巡航或受阻调试期间，无需在分散话题与终端滚屏中盲猜停机原因。本项目提供一体化导航状态观测、只读聚合诊断与多维阻断归因工具：
1. **只读聚合诊断话题 `/navigation/status`**：
   - 周期性（2 Hz）发布当前导航会话 ID、目标点 UUID（兼容单目标与多目标导航）；
   - 当前行为树所处导航阶段（`PLANNING`, `FOLLOW_PATH`, `REAR_CLEAR`, `BACKUP`, `CONTROLLED_SPIN`, `PARK_AND_OBSERVE` 等）；
   - 实时双层下发速度对比（导航规划速度 `/cmd_vel_nav` 与底盘实际接收速度 `/cmd_vel`）；
   - 纯轮式里程计测速与运动状态（基于静止判据 `<0.01 m/s` & `<0.02 rad/s` 持续 1.0 s 判为 `STILL`；数据超过 0.6 s 未更新判为 `DATA_EXPIRED`）；
   - 最近停车事件触发原因与多维归因评级。
2. **多维停车归因定级原则**：
   - **确定归因 (CERTAIN)**：有明确直接机制证据（例如障碍物近距切断、ProgressGuard 停滞超时、激光雷达断流过期、目标成功抵达）；
   - **关联线索 (CORRELATED)**：底盘看门狗动作、上层下发零速或路径规划失败。**严格禁止将看门狗或零速直接判定为唯一根本原因**，必须作为联动现场的关联证据记录；
   - **线索不足 (INSUFFICIENT)**：传感器或节点缺失关键线索时如实报告，严禁编造推测。
3. **历史会话兼容性保障**：
   - 工具自动兼容旧版会话（无 `NAVIGATION_STOP` 结构化事件的旧录包），能够平滑提取历史阻断与终态时间点，不报错、不崩溃。

### 16.4 轻量化日志与按需录包配额控制

1. **默认轻量化模式**：
   - 导航启动时默认 `record_raw_bag:=false`，不产生大型 rosbag 文件（每会话通常占用 < 2 MB）。

   - 内存维护 5 Hz 滑动状态环形缓冲（容量 100 帧），在停车事件触发时保留前后（前 10s、后 5s）关键证据窗口，并自动合并重叠停车事件。
   - 重规划成功事件每 30 秒汇总一次 (`REPLANNING_SUMMARY`)，避免控制台刷屏；失败事件即时记录；重复告警维护首次时间、末次时间与计数。

2. **按需开启原始录包 (双限额保护)**：
   若需录制原始 rosbag2 供深度离线重放，可在启动导航时显式传入 `record_raw_bag:=true`：
   ```bash
   ros2 launch carcar_navigation navigation_experimental.launch.xml record_raw_bag:=true
   ```
   - **配额限制**：自动限制为最长 **120 秒** 或最大 **约 256 MiB**，且当磁盘剩余空间低于 **2 GiB** 时自动触发保护。
   - **平滑分流**：达到任一限制后，原始 rosbag 自动优雅停止并关闭文件，轻量化事件监控与状态摘要继续运行，彻底避免磁盘占满风险。
   - 默认停止保存高频轨迹话题 `/evaluation` 与 `/trajectories`，专注保留感知、TF、里程计与控制核心链路。

## 17. 导航声光提示与停车原因诊断系统（NAV-014）

### 17.1 适用范围与核心能力

本系统让现场人员无需手持电脑或监视终端话题即可直观回答三件事：**现在执行到哪一步、为什么停下、是否仍在尝试恢复**。

1. **分层声光指示架构**：
   - **状态判断与时钟调度**：由独立 C++ 节点 `navigation_indicator` 实现，订阅 `/navigation/status` 聚合诊断，输出 `/hardware/indicator/command`（`carcar_interfaces/msg/IndicatorCommand`）。内部阶段码与停车原因仍写入终端摘要和 `/navigation/status`，灯光只映射为下面 5 种操作员模式。
   - **底层转发与安全看门狗**：在现有 Python 底盘节点 `rosmaster_node.py` 中实现最小隔离转发，负责独占调用控制板蜂鸣器与 RGB 驱动，提供 1.0s 超时灭灯和零自主运动保证。
   - **亮度**：默认 `indicator_brightness:=85`。青色按 (0,255,255) 的 1/3 显示为 **(0, 85, 85)**；失败红灯按同一亮度标尺为 (85, 0, 0)。慢闪 1 Hz，快闪 2 Hz。
2. **操作员可见灯光只有 5 种**，不按 RotationShim、ProtectedBackUp、ProgressGuard、RearClear 或各 cause 码分色。
3. **声音几乎静音**：规划、跟随、恢复阶段切换不鸣叫；到达 SUCCESS 短鸣一次，失败/锁定停车短鸣一次；`mute_audio:=true` 关闭全部蜂鸣。无循环鸣叫、无原因/阶段交替音频。
4. **通信看门狗保护**：若连续 2.0 秒未收到有效 `/navigation/status`，指示灯切换为 **LOST_FLASH（紫色快闪 2 Hz）**，蜂鸣器静音。
5. **操作员灯光对照**：

| 操作员模式 | 标识符 | RGB 显示 | 声音 | 现场含义 |
|---|---|---|---|---|
| **关闭** | `OFF` | 全灭 | 无 | 导航未运行、进程退出或预关闭灭灯 |
| **导航运行** | `NAV_CYAN` | 青色常亮 (0, 85, 85) | 到达时 1 短声 | 定位就绪或正在规划/跟随；待命、规划、跟随对操作员看起来相同 |
| **恢复或等待** | `NAV_CYAN_SLOW_FLASH` | 青色慢闪 1 Hz | 无 | 恢复、等待定位、停车观察；提醒注意，不是失败 |
| **失败锁定** | `FAIL_RED` | 红色常亮 (85, 0, 0) | 1 短声 | 中止、锁定停车、取消未确认、停稳未确认、恢复额度耗尽 |
| **通信超时** | `LOST_FLASH` | 紫色快闪 2 Hz | 无 | 超过 2.0 s 未收到 `/navigation/status` |

### 17.5 独立底盘驱动安全隔离与转发规范（特例说明）

依据项目协作约定（[AGENTS.md](AGENTS.md) 一点六），后续新增逻辑统一使用 C++ 实现，但已有 Python 底层测试资产按“底层测试资产只增不删”规则保留。由于控制板串口 `/dev/myserial` 具有排他锁保护，底盘运动与板载声光不可同时由两个进程打开。经用户明确同意，在现有 Python 底盘节点 `rosmaster_node.py` 中增加最小声光转发逻辑作为特例。

该转发逻辑具备以下严格的底层安全保证：
1. **零自主运动保证**：
   - 声光指令接收回调仅在互斥锁 `with self._io_lock:` 保护下调用 `self._bot.set_beep()` 与 `self._bot.set_colorful_lamps()`。
   - 接收声光指令绝不修改时间戳 `_last_command_ns`，绝不触碰或清除底盘看门狗标志 `_watchdog_stopped`，绝不产生任何轴向位移或转动。
2. **硬件参数校验与常鸣禁止**：
   - 严禁下发危险的持续长鸣指令（`beep_time_ms == 1` 会被驱动层严格拦截拒绝）。
   - 蜂鸣器时长强制截断在 0 或 10～3000 ms（控制板协议要求 10 ms 倍数，超出自动向下取整到 10 的倍数）。
   - RGB 各通道分量强制限制在 0～255。
3. **1.0 秒超时自动关停保护**：
   - 底盘主循环实时监控最后一次接收到声光指令的时间。若超过 1.0 秒未收到任何声光指令，自动将板载 RGB 灯带熄灭（`0xFF, 0, 0, 0`）并关闭蜂鸣器（`0`）。
4. **启停强制零输出**：
   - 驱动初始化阶段与节点退出 `stop()` 时，强制下发 `set_beep(0)` 与 `set_colorful_lamps(0xFF, 0, 0, 0)`，防止因意外中止导致蜂鸣器长鸣或灯带常亮。

### 17.6 异常排查与急停恢复

1. **蜂鸣器异常长鸣**：若发生程序异常导致蜂鸣器持续长鸣，在独立终端执行一键关闭命令：
   ```bash
   ros2 launch carcar_hardware rosmaster_indicator_test.launch.xml real_hardware:=true action:=off
   ```
2. **紧急断电**：控制板旁侧的 12 V 主开关与 USB 连接线随时可直接切断或拔下。
3. **串口冲突**：若启动报错串口被占用，执行 `fuser /dev/myserial` 排查并退出残留进程。

## 18. NAV-012 回调、恢复监督与速度联锁修复

### 18.1 范围、流程与边界

本修复针对 2026-09-16 恢复链路失败；离线结果见测试记录 NAV-012-R1，实车验收仍待现场反馈。没有改变固件、系统配置、IMU 融合、硬件尺寸、稳定导航入口和底层测试资产。转向误差为何扩大仍需独立验证，不能用恢复流程能结束代替转向性能验收。

传感器、定位门控 `/localization_monitor/ready` 与 `/localization_monitor/recovery_allowed`、以及 AMCL 服务客户端共用 `RecoveryRuntime` 的互斥回调组和既有 NodeThread；tick 只读带锁快照，不再在叶节点里 `spin_some()`。Action 适配器继承本机 Nav2 `BtActionNode`，保存 UUID、执行代次和结果状态；只取消自己发出的目标，晚到目标响应仍会被取消。同一 FollowPath 会话的路径位姿更新不会因旧目标提交时刻超时把当前代次判成 `PREVIOUS_RESULT_MISSING`，仅戳记变化不重发。卸载树时保留待结束请求，停止导航时先关闭许可、停止执行线程，再释放回调状态。`/recovery/status` 的 `bt_tick_age_s` 为距最近一次 RecoverySupervisor tick 的秒数，树停止 tick 后该年龄会增长。

两棵实验树均使用 `RecoverySupervisor`：关闭许可 → 取消旧运动并等待终态 → 重新累计轮式里程计停稳证据 → 执行最新目标。它同时比较导航 UUID 和完整目标内容，覆盖朝向与多目标，不依赖 `GoalUpdated` 的 IDLE 基准。连续目标更新只替换待执行目标，不刷新取消期限、受阻总时限或倒车额度。Humble 的 navigator muxer 不允许两种导航 Action 同时占用机器人；切换单目标/多目标入口前先取消当前导航。

恢复顺序为一次有限重规划、后方检查与短倒车、重试跟随、受控转向、重试跟随、停车观察。每个受阻周期只尝试一段倒车，之后进入转向阶段；累计额度仍保守限制在 0.30 m。提交时预留额度，取消或结果不明不退款，只有明确拒绝且未运动才退款。净前向轮式里程计进展达到 0.20 m 才重置额度；后退扣减累计前向进展，侧移不充能。定位或必要数据失效只允许停车和定位恢复，不能落入运动恢复。

速度链为：`controller_server / behavior_server → /cmd_vel_nav → velocity_smoother → /cmd_vel_smoothed_raw → navigation_motion_gate → /cmd_vel → 底盘`。

联锁启动默认关闭，BT 持续授权、运动 Action 已接受且输入新鲜时才放行。关闭、超时或动作代次变化会清空缓存，重新授权后必须收到新指令。实验链路只有联锁发布最终速度；不要同时启动键盘、稳定导航或其他直接发布 `/cmd_vel` 的工具。正常退出前发送零速，进程异常退出由底盘既有 0.30 s 看门狗兜底。

| 边界 | 实验默认值 / 配置位置 |
|---|---|
| Action 发现、目标响应 | 各 1 s，跨 tick 等待；YAML `recovery.response_timeout` |
| 转向 | 最大 90°，服务器 10 s、客户端额外 1 s；实验 XML |
| 倒车 | 0.10 m、0.05 m/s、服务器 4 s、客户端额外 1 s；实验 XML |
| 取消终态确认 | 1 s；YAML `recovery.cancel_timeout`；受理取消不等于动作已结束 |
| 停稳 | 动作结束后，新鲜轮式里程计连续 1 s 满足平移速度模长 <0.01 m/s、角速度绝对值 <0.02 rad/s；最多等待 2 s |
| 授权 / 速度有效期 | 0.20 s / 0.30 s；实验 Launch 联锁参数 |
| 重规划 | 每次最多 5 s；实验 XML |
| 观察 | 最多 30 s，每秒检查，重入不刷新观察期限 |
| 一次受阻总预算 | 90 s，包含交接、重规划和重试；YAML `recovery.total_timeout` |
| 新鲜度 | 同时检查消息时间戳和本地接收时间，默认 0.5 s |
| 进展守卫 | 保留 5 s / 0.10 rad 与 15 s 转向总预算，停车时间不进入下一段窗口 |

取消无法确认、无法确认停稳或受阻预算耗尽时锁定停车并明确失败。此时继续点击不会解锁；正常停止导航并保留会话，排除原因后再重启。重启会建立新运行上下文，不能把重启当成绕过受阻额度的方法。

几何检查把世界坐标包络和扫描时刻激光变换到车体坐标，复用 Nav2 包络、栅格轮廓碰撞及内部填充。未知、越界、数据失效均拒绝；倒车执行中持续检查。倒车扫掠忽略当前包络已经压住的前方致命格，只拦新进入的后方体积；后方有障、未知格或越界仍拒绝。路径参考从最近路径段向前采样，终点使用目标朝向，多目标使用最后一个剩余目标。多目标树复用 Nav2 `RemovePassedGoals`（实验半径 0.20 m）删除已到达的途经点，避免重新规划时折返；该内部前缀删除不触发新任务抢占。诊断包含参考航向、车体航向、实际角速度、路径代次、动作 UUID/代次、等待余量、取消状态、BT 心跳年龄及订阅计数。

## 19. Ubuntu 主机 RViz 联调

用途：车上继续跑底盘、雷达、定位和导航；Ubuntu 22.04 电脑只显示地图并点初始位姿/目标。不改固件、不改串口、不在 Jetson 上启动 `rviz2`。V2.0 是主机改为 Ubuntu 开发之前的最后一次快照；此后按本节联调。

### 19.1 必须对齐的环境

| 项目 | 车上现在的值 | 电脑上也要一样 |
|---|---|---|
| 系统 | Ubuntu 22.04 | Ubuntu 22.04 |
| ROS | Humble | Humble |
| Wi‑Fi | `小泽` | 同一 Wi‑Fi，不要用手机热点另一张网 |
| 车 IP | `192.168.5.11` | 电脑应是 `192.168.5.x` |
| ROS 域 | `ROS_DOMAIN_ID=31` | `export ROS_DOMAIN_ID=31` |
| 本机隔离 | `ROS_LOCALHOST_ONLY=0` | 同样设为 0，或干脆不设 |
| DDS | 默认 Fast DDS | 先不要改 `RMW_IMPLEMENTATION` |

车上 `~/.bashrc` 已写入域号 31 和 `ROS_LOCALHOST_ONLY=0`，无需再改系统服务。电脑每个新终端先：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=31
export ROS_LOCALHOST_ONLY=0
```

可写进电脑的 `~/.bashrc`，避免忘。域号不一致时，`ros2 topic list` 是空的。

### 19.2 电脑上最少安装

不要一上来克隆整车工程。先装桌面版 Humble 和 RViz：

```bash
sudo apt update
sudo apt install ros-humble-desktop ros-humble-rviz2 ros-humble-nav2-msgs
```

`ros-humble-desktop` 已含 RViz、常用消息和 TF。点目标和看地图够用。

### 19.3 车上怎么开（不要再起 RViz）

底盘、雷达、实验导航仍按[第 12.3～12.4 节](#123-实车启动前安全检查)和[第 18.3 节](#183-启动与只读观察)。定位必须显式关闭板上 RViz：

```bash
cd /home/jetson/luhao/my_nav_carcar
source /opt/ros/humble/setup.bash && source install/setup.bash
export ROS_DOMAIN_ID=31
export ROS_LOCALHOST_ONLY=0
ros2 launch carcar_navigation localization_experimental.launch.xml \
  map:=$(pwd)/src/carcar_navigation/maps/nav004_20260914_093032.yaml \
  use_rviz:=false
```

Jetson 上不要再开 `rviz2`，也不要用 VNC 看三维窗口。声光、倒车、联锁仍在车上；终端 4 的一行中文摘要仍可在车上或 SSH 里看。

### 19.4 电脑上确认连通并打开轻量 RViz

电脑和车都上电、导航起来后，在电脑：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=31
export ROS_LOCALHOST_ONLY=0
ros2 topic list
```

应能看到至少：`/scan`、`/map`、`/tf`、`/amcl_pose`、`/goal_pose`。再：

```bash
ros2 topic echo /localization_monitor/ready --qos-durability transient_local --once
```

`data: true` 后再点目标。

把轻量配置拷到电脑（在电脑上执行，按提示输入车上密码）：

```bash
scp jetson@192.168.5.11:/home/jetson/luhao/my_nav_carcar/src/carcar_navigation/rviz/navigation_lite.rviz ~/navigation_lite.rviz
rviz2 -d ~/navigation_lite.rviz
```

Fixed Frame 选 `map`。用 **2D Pose Estimate**（`/initialpose`）和 **2D Goal Pose**（`/goal_pose`）。不要拷完整的 `navigation.rviz`（双代价地图 + 全 TF），电脑也会卡，还占 Wi‑Fi。

### 19.5 若电脑上看不到话题

按这个顺序查：

1. 电脑 `ip a` 是否也是 `192.168.5.x`，能否 `ping 192.168.5.11`
2. 两边 `echo $ROS_DOMAIN_ID` 都是 `31`
3. 暂时关掉两边防火墙：`sudo ufw disable`（通了再按需打开）
4. 电脑不要开 VPN
5. 车上 `ros2 node list` 里应有 `/amcl`、`/bt_navigator`，且没有第二个 RViz

列表仍是空的时，把电脑 IP 和 `ros2 topic list` 输出发回即可。

### 19.6 远程桌面还能否连车上 GNOME

可以。车上 `x11vnc.service` 仍在监听 `192.168.5.11:5901`，开机自启，密码见桌面文档 [`/home/jetson/Desktop/系统配置维护记录.md`](file:///home/jetson/Desktop/系统配置维护记录.md)。电脑换成 Ubuntu 22.04 后：

```bash
sudo apt install tigervnc-viewer
xtigervncviewer 192.168.5.11:5901
```

或打开自带的 Remmina，协议选 VNC，服务器填 `192.168.5.11:5901`。这只用来看板上桌面、终端或紧急操作。日常点目标用本节的本机轻量 RViz，不要经 VNC 画三维窗口。

# 项目现状与路线

最后更新时间：2026-09-06

## 产品目标

本项目只围绕一个明确目标推进：四轮麦克纳姆小车在室内完成建图、定位和多点导航巡检；
电量不足或任务结束时，使用 Intel RealSense D435 识别充电桩并自主回充；最终提供适配
手机的 Web 页面，用于遥控、任务下发、地图/位置和设备状态查看。

不再为了“测试底层而测试底层”。已有电机、编码器和串口结论达到下一层输入要求后，
只保留故障回归入口，不重复做相同的逐轮实验。

## 当前可用能力

| 模块 | 已确认结论 | 当前用途 |
|---|---|---|
| 底盘 | 四轮麦克纳姆；轮径 60 mm、轮宽 31 mm、轴距 120 mm、轮距 185 mm | 可建立运动学和机器人描述 |
| 电机映射 | M1=左前、M2=右后、M3=右前、M4=左后；机械正转命令符号 `[+1,-1,+1,-1]` | 可进入四轮组合运动 |
| 编码器 | 四路累计计数和通道独立反馈可用，约 25 Hz | 可用于轮速和里程计；精确每圈计数仍需标定 |
| 控制板 | `set_car_motion(vx, vy, wz)`、IMU、电池电压回传均已接入 ROS | 可作为当前最小可用底盘接口 |
| 安全 | 启动零输出、命令超时停车、正常退出停车已经验证 | 保留硬件断电作为最终急停 |
| 雷达 | RPLIDAR A1 在 Humble 下可稳定发布 `/scan`；当前有效范围 0.10～3.00 m | 足够先做室内 2D 建图和避障 |
| TF/模型 | 四轮几何和 TF 树离线通过 | 雷达、IMU、D435 位姿仍是临时值 |

## 尚未完成且会阻塞导航的事项

1. 尚未测量底盘最大外廓，以及 `imu_link`、`laser_frame`、D435 安装基准相对
   `base_link` 的真实六自由度位姿。
2. 尚未验证四轮组合的车体前进、横移和原地旋转方向，也没有完成地面尺度标定。
3. 当前 `/wheel/odometry` 是控制板车体速度积分，尚未形成独立验收的四轮轮式里程计基线。
4. D435 尚未在当前 Jetson/Humble 工作空间完成接入测试；充电桩机械触点、充电电路和
   “已经开始充电”的检测信号也未确认。
5. Nav2 配置目前是预置初值，footprint 仍不是实车外廓，不能直接作为导航验收配置。

## 成熟方案选型

| 需求 | 采用方案 | 版本/许可证状态 | 本项目适配 |
|---|---|---|---|

| 多点巡检 | Nav2 `Waypoint Follower` | Humble/Nav2，Apache-2.0 | 点位任务插件只实现拍照、等待、状态上报等业务动作 |
| D435 | RealSenseAI `realsense-ros` | 接入时固定与 Humble/librealsense 兼容的发布版本，Apache-2.0 | 驱动自己发布相机内部 TF；本项目只维护 `base_link -> camera_link` 安装外参 |
| 充电桩视觉定位 | ROS 2 `apriltag_ros` + AprilTag 36h11 | 接入时固定提交；MIT/BSD-2-Clause | 标签固定在充电桩，输出桩相对相机位姿；D435 深度作距离校验和近场安全辅助 |

## 下一步顺序

### P0：本轮先完成实体描述和 TF

测量并回填底盘最大长/宽/高、雷达、IMU 和 D435 安装位姿；然后更新
`carcar.urdf.xacro`、RViz 模型和 Nav2 footprint。验收只看三件事：TF 无重复发布、
雷达点云方位与实物一致、相机图像/光学坐标符合驱动定义。

### P1：完成最小四轮底盘闭环

只做三条低速地面动作：前进、左横移、逆时针原地旋转。每条动作确认方向、停车和
编码器符号即可；不再新增逐轮测试。随后接入标准麦克纳姆控制器，完成直线 1 m、横移
1 m、旋转 360° 的尺度校正，先由纯轮式里程计生成唯一
`odom -> base_footprint`。这一阶段 IMU 只发布和观察，不参与融合。

### P1.5：稳定后再评估 IMU（后置可选）

只有纯轮式里程计和基础导航稳定后，才建立第一版 `robot_localization` 配置，并且只融合
四轮里程计与经过零偏、单位、坐标轴和符号校正的 `gyro_z`；IMU 姿态、全部线加速度和
磁力计输入保持关闭。首次 IMU 调试依次执行：水平静止统计
`angular_velocity.z` 的均值/标准差；逆时针旋转确认 `gyro_z > 0`；水平静止确认
`ax≈0`、`ay≈0`、`az≈+9.81 m/s²`。任何轴向问题先修驱动映射或安装 TF，不用 EKF
参数补救。只有该链路稳定且有明确收益需求时，才把线加速度、Madgwick 和磁力计作为
三个独立实验逐项评估；二维地面导航默认不融合线加速度。

### P2：建图、定位和多点巡检

先使用当前 0.10～3.00 m 雷达范围完成单层室内地图，再验收定位重启、单目标导航和
避障；最后使用 Waypoint Follower 串联巡检点。D435 不承担基础 2D 定位，避免把回充
视觉问题混入导航主链路。

### P3：D435 自主回充

先验证 D435 彩色/深度话题和相机 TF，再验证 AprilTag 桩位姿；随后完成“导航至预停靠
点 → 视觉精对准 → 接触 → 检测充电开始 → 失败后退重试”。控制板可读电池电压，但
电压百分比、低电阈值和充电成功判据必须按实际电池与充电器标定。

### P4：产品化 Web

在导航和回充稳定后再做 Web。第一版只包含低速按住遥控、急停、在线状态、电池电压、
当前位置、任务开始/暂停/取消和相机低码率预览。第二版再加地图点位编辑、巡检记录、
用户权限、HTTPS、日志和断线重连。

## 当前完成标准

本项目不追求实验数量，而按产品能力关闭阶段：能稳定执行三自由度运动并停车、能提供
连续里程计和完整 TF、能重复完成多点巡检、能从低电状态返回并确认充电、手机端在断线
时不会留下持续运动命令。达到这些结果即可进入下一层，历史底层测试只在回归故障时使用。

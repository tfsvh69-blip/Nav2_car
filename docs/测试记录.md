## DRV-001：CH340/CH341 串口稳定性与固定别名

### 测试目的

确认 CH341 内核驱动能够识别 CH340，`brltty` 不再抢占设备，并建立稳定的 `/dev/myserial` 别名。

### 原始故障特征

```text
ch341-uart converter now attached to ttyUSB0
usbfs: interface 0 claimed by ch341 while 'brltty' sets config #1
ch341-uart ttyUSB0: ch341-uart converter now disconnected from ttyUSB0
```

### 已执行的处理命令

没有使用盲文设备的前提下卸载 `brltty`：

```bash
sudo apt remove --purge brltty -y
sudo udevadm control --reload-rules
sudo udevadm trigger
```

拔掉 CH340，等待两秒后重新插入，然后检查：

```bash
ls -l /dev/ttyUSB*
sudo dmesg | grep -iE "ch341|ttyUSB|brltty" | tail -30
```

稳定别名规则：

```udev
SUBSYSTEM=="tty", KERNEL=="ttyUSB*", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523", MODE:="0666", SYMLINK+="myserial"
```

规则文件维护命令：

```bash
sudo nano /etc/udev/rules.d/99-myserial.rules
sudo chmod 644 /etc/udev/rules.d/99-myserial.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

再次拔插后验证：

```bash
ls -l /dev/ttyUSB*
ls -l /dev/myserial
udevadm info --query=property --name=/dev/ttyUSB0 | \
  grep -E 'ID_VENDOR_ID|ID_MODEL_ID|DEVLINKS'
```

串口用户组配置：

```bash
sudo usermod -aG dialout "$USER"
```

修改用户组后需要注销重新登录，或重启系统：

```bash
sudo reboot
```

### 预期结果

```text
/dev/ttyUSB0
/dev/myserial -> ttyUSB0
```

最新内核日志中存在 `converter now attached to ttyUSB0`，不再出现 `brltty` 抢占后导致的 `converter now disconnected`。

### 实际结果

- 日期：2026-09-02
- 结果：`/dev/ttyUSB0` 稳定存在，`/dev/myserial -> ttyUSB0`。
- 结论：通过。
- 备注：第三方 `.ko` 的模块签名警告当前未影响设备识别；后续升级内核时需重新验证模块兼容性。

## MOTOR-001：M1/M2 低速键盘点动

### 测试目的

只验证控制板 M1、M2 能否正转、反转和及时停车。不验证底盘运动学、里程计、TF 或导航。

### 当前硬件范围

- M1：已连接电机。
- M2：已连接电机。
- M3、M4：未连接；测试节点每次明确写零。
- M1/M2 对应车体位置和机械正方向尚未确认。

### 安全条件

1. 将车轮可靠架空。
2. 轮胎周围不得有手、衣物、线缆或松动物体。
3. 控制板电源开关应在伸手可及的位置。
4. 不得同时启动 `carcar_bringup robot.launch.py` 或其他串口节点。
5. 首次测试保持默认 20% PWM，不延长 0.6 秒超时时间。

### 构建命令

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
colcon build --symlink-install \
  --packages-select rosmaster_vendor carcar_base
source install/setup.bash
```

### 启动前检查

```bash
ls -l /dev/ttyUSB0
ls -l /dev/myserial
groups
fuser /dev/ttyUSB0 /dev/myserial 2>/dev/null || true
```

如果 `fuser` 输出进程号，先确认并停止占用串口的旧 ROS 节点，不能同时打开串口。

### 终端 1：启动二电机测试节点

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch carcar_base motor_test.launch.py
```

预期启动日志：

```text
Rosmaster Serial Opened! Baudrate=115200
M1/M2 test mode active on /dev/myserial: PWM limited to 20%; M3/M4 forced to zero
```

### 终端 2：启动键盘话题发布器

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

按键定义：

- `i`：发布正向 `linear.x=+0.5`。
- `,`：发布反向 `linear.x=-0.5`。
- `k` 或其他非控制键：发布零速。
- `Ctrl+C`：退出键盘节点并发布零速。

每次按键只发布一帧。本项目测试节点在 0.6 秒内没有收到新指令时，自动将 M1～M4 全部写零。

### 终端 3：观察 ROS 接口

查看话题是否存在：

```bash
ros2 topic list | sort
ros2 topic info /cmd_vel --verbose
```

观察键盘实际发布的消息：

```bash
ros2 topic echo /cmd_vel
```

查看节点和参数：

```bash
ros2 node list
ros2 param list /two_motor_test
ros2 param get /two_motor_test max_pwm_percent
ros2 param get /two_motor_test command_timeout
```

### 不使用键盘时的话题点动命令

以下命令只用于车轮已经架空的情况。每条命令仅发布一帧，测试节点会在 0.6 秒后自动停车。

正向：

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.5}, angular: {z: 0.0}}"
```

反向：

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: -0.5}, angular: {z: 0.0}}"
```

立即停车：

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.0}, angular: {z: 0.0}}"
```

## LIDAR-001：RPLIDAR A1 从 Jazzy 迁移至 Humble 并进行 RViz 测试

### 测试目的与适用范围

验证 V1.0 中已在 Ubuntu 24.04、ROS 2 Jazzy 上运行的 RPLIDAR A1 驱动，能否在当前 NVIDIA Jetson、Ubuntu 22.04、ROS 2 Humble 上完成构建、串口通信、`/scan` 发布、TF 变换和 RViz 显示。本测试只覆盖雷达层，不启动底盘、电机、建图或 Nav2。

### 当前硬件前提和安全条件

- 雷达转接板为 CP2102，USB ID `10c4:ea60`，当前对应 `/dev/ttyUSB1`。
- 底层控制板为 CH340，USB ID `1a86:7523`，当前对应 `/dev/ttyUSB0` 和 `/dev/myserial`。
- 优先使用雷达的 `/dev/serial/by-id/usb-Silicon_Labs_CP2102_USB_to_UART_Bridge_Controller_0001-if00-port0`。
- 串口同一时间只能由一个进程打开；不得将底层板串口传给雷达节点。
- 不使用 `sudo` 启动 ROS 节点。雷达卡转、异响、冒烟或过热时立即拔掉雷达 USB。

### 完整构建命令

```bash
cd /home/jetson/luhao/my_nav_carcar
unset PYTHONHOME PYTHONPATH
export PATH="/usr/bin:/bin:${PATH}"
source /opt/ros/humble/setup.bash
colcon build --symlink-install \
  --packages-up-to carcar_lidar \
  --cmake-clean-cache \
  --cmake-args \
    -DPython3_EXECUTABLE=/usr/bin/python3
source install/setup.bash
```

### 端口检查命令

1. `sllidar_ros2` 和 `carcar_lidar` 在 Humble 下构建成功。

# D435 接入 STVL 的依据与适配边界

调研日期：2026-10-06。用途：记录本轮选择 STVL 的来源、固定版本行为与本项目适配约束。本文不是当前启动入口，不保存完整操作命令，也不代表实机验收通过。当前设备、外参和实机结论分别以[硬件台账](../硬件台账.md)、[项目路线](../项目现状与路线.md)、[测试记录](../测试记录.md)为准；构建、启动、观察、停止与恢复统一维护在[操作手册](../操作手册.md)。

## 1. 决策与证据等级

本轮优先采用 **Humble STVL 2.3.4 的线性时间衰减**作为深度障碍记忆方案，先用于独立实验入口。首版同一 source 使用 `marking:true`、`clearing:false`，先验证纯时间记忆，不启用视锥加速。二维雷达保留标准 ObstacleLayer，深度单独使用 STVL，膨胀层放在障碍层之后，传感器失效停车仍由独立健康门控制。该选择针对“历史三维体素等待清除射线，不能稳定退出”的能力缺口；它不替代 TF、数据新鲜度和可靠停车。

### 2.1 本轮实际依赖与接口适配

2026-10-06 本地接入发现：Humble 2.3.4 官方 deb 包含共享库与生成的服务接口，但缺少插件公开 C++ 头文件。固定源码的 CMakeLists 只有 `ament_export_include_directories(include)`，没有安装上游 `include/` 的规则，因而薄诊断适配层不能直接依赖 deb 获得类声明。[固定 CMakeLists 的安装与导出](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/CMakeLists.txt#L121)

本项目在 `src/carcar_navigation/vendor/stvl_2_3_4/` 原样保留固定提交 `92896fe9ea994260bf34f1fa7b7735f3804cfc6f` 的八个 include 文件和完整 LICENSE，并记录来源；不复制上游 `.cpp` 算法。薄诊断适配层调用上游初始化、更新边界和更新代价函数，算法仍动态链接官方 `libspatio_temporal_voxel_layer_core.so`。头文件、STVL 二进制与 OpenVDB vendor 必须保持版本匹配，升级时同步核验类布局、依赖与集成测试。[本地来源清单](../../src/carcar_navigation/vendor/stvl_2_3_4/来源.md)、[本地构建适配](../../src/carcar_navigation/CMakeLists.txt)、[薄诊断适配实现](../../src/carcar_navigation/src/monitored_stvl_layer.cpp)

本轮代理会话没有可用的 sudo 权限，因此把 STVL 与 openvdb_vendor 两个官方 deb 解包到用户目录，使用独立前缀 `/home/jetson/.local/share/carcar_stvl_humble/opt/ros/humble`。该方式没有将包安装到系统 ROS 前缀，也没有执行系统 ROS 升级；构建与运行都需要按手册加载该前缀，使库、ament 索引和 OpenVDB vendor 一致可见。用户前缀与头文件适配属于本地依赖接入事实，不证明 D435 撤障、真实障碍保持或故障停车已经实机通过。

补充构建适配：该二进制的生成接口导出不能代替核心库链接，本项目显式链接 `libspatio_temporal_voxel_layer_core.so` 并启用链接期未解析符号检查。OpenVDB vendor 的 CMake 查找前先加载完整 TBB targets，避免不同查找模块重复建立部分 targets。保留的八个上游头文件按各自文件头为 BSD-3-Clause，根 LICENSE 与 STVL 核心库按 LGPL-2.1 记录，不能把两者混为同一许可。

感知与行为树适配：`recovery.require_perception_health` 在STVL入口启用。行为树的感知等待先取消当前控制动作、确认停稳，保留仍有效的外部导航任务；恢复后重新规划并重新授权。等待暂停普通输入和运动恢复预算，但取消/停稳确认失败仍沿用原有锁停，外部取消/抢占也继续生效。速度心跳联锁独立执行，覆盖行为树或监督器无法继续运行时的停车。

## 3. D435 为什么能标障，却未必能清掉

### 3.1 深度未知不是自由空间

D435 属于 D400 立体深度相机。它根据左右红外图像匹配推算视差与深度，投射器帮助提供纹理，并非逐像素保证有激光式“无回波最大距离”。远处超出可测范围、弱纹理、反光、遮挡等情况可能得不到可信深度；SDK 对无法确定深度的像素使用深度值 0。这样的像素表示未知，不能直接转换成“沿此方向到最大距离全部无障碍”。[D400 官方数据手册](https://realsenseai.com/wp-content/uploads/2025/09/Intel-RealSense-D400-Series-Datasheet-October-2025.pdf)、[RealSense SDK 2.0 官方投影说明](https://dev.realsenseai.com/docs/projection-in-realsense-sdk-2-0/)

物体移走后，原方向可能没有有效远处终点；即使地面持续有有效点，其射线也可能从旧高处体素下面经过。两个机制都能造成旧三维占用没有被标准 VoxelLayer 清除。输入过滤、时间确认或增加邻居阈值可以减少误标，但不能生成原本没有测得的自由空间证据。补洞和时间滤波也不能据此当作清除证明。[RealSense 官方后处理说明](https://dev.realsenseai.com/docs/depth-post-processing-for-intel-realsense-depth-camera-d400-series/)

### 3.2 标准 VoxelLayer 的链路

Humble 1.1.20 的链路为：PointCloud2 接收 → observation 缓存与 TF 变换、高度过滤 → 从传感器原点向有效终点做三维 raytrace clearing → 对标障点设置体素占用 → 按垂向计数生成二维障碍 → 合并层与膨胀 → 规划和控制读取二维 costmap。[ObservationBuffer](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/src/observation_buffer.cpp)、[VoxelLayer](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/plugins/voxel_layer.cpp)

清除只有实际射线穿过的体素生效；增大 `raytrace_max_range` 不会为没有终点的方向制造射线。`observation_persistence` 管理 observation 缓存，不是栅格 TTL；PointCloud2 也不能直接套用 LaserScan 的 `inf_is_valid` 语义。标准体素列使用 `> mark_threshold`，值 1 要求超过一个垂向体素，而三维命中位可以已经存在，所以三维残留与二维致命格必须分别看。[ObstacleLayer 点云处理](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_costmap_2d/plugins/obstacle_layer.cpp)、[原生 VoxelGrid](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_voxel_grid/include/nav2_voxel_grid/voxel_grid.hpp)

TF 会同时影响命中位置、射线原点和方向。能标障只能说明某些点经过了变换，并不能证明清障原点在体素地图内、射线几何正确、时间变换连续或原高度格被穿过。真实移动测试必须有可信的 `odom → base_footprint`；以 `base_footprint` 为固定地图参考且没有里程计时手动转动车体，不能作为导航移动清障验收。

## 4. STVL 改变了什么

STVL 使用 OpenVDB 保存稀疏三维体素和标记时间，把仍保留的体素投影为二维 costmap。线性模型按“距离最近标记已经过了多久”让记忆到期，因此旧格不再完全依赖射线穿过才退出。它改变的是地图记忆，不会提高 D435 的原始测距能力。[底层体素实现](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_grid.cpp#L73)

视锥 clearing 根据传感器位姿、FOV 和近远界构造几何视锥，对其中的旧体素加速衰减；2.3.4 没有依据每个深度像素执行遮挡可见性判断。清除源为 `clearing:true, marking:false` 时，缓存甚至直接跳过点云内容。因此“在视锥中到期”不能表述成“相机确认这格是空地”。[视锥构造](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_grid.cpp#L120)、[clear-only 分支](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/measurement_buffer.cpp#L135)

收益是残留退出时间可控、稀疏三维表示可扩展；代价是被遮挡、离开视野或传感器暂时测不到的真实障碍也会逐渐被忘记。短 TTL 降低残留，长 TTL 增加记忆，两端都需实物验证。固定设施由静态地图和雷达提供互补，未知深度仍然保持未知；不能靠扩大视锥、伪造远点或定时清空全图来掩盖数据失效。

## 5. Humble 2.3.4 的精确接入边界

### 5.1 `enabled` 两个内部字段不同步

初始化第 93～95 行把参数读到 `_enabled`，再赋给 Nav2 基类字段 `enabled_`；`updateCosts`、`updateBounds` 分别在第 677、739 行检查 `_enabled`。动态参数回调第 939 行却只修改 `enabled_`，没有修改 `_enabled`。从 `enabled:false` 启动后再设为 true，参数响应成功也不能证明内部更新已启动。这一代码行为已与 bloom Humble `2.3.4-1` 发布源码交叉核验；未找到明确对应的已修复上游 issue，不声称实机已复现。[初始化与更新](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_layer.cpp#L93)、[动态回调](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_layer.cpp#L912)、[固定发布源码](https://github.com/SteveMacenski/spatio_temporal_voxel_layer-release/blob/eb871019866ea2eb0faa50898ecf2e818db53891/src/spatio_temporal_voxel_layer.cpp#L939)

本项目约束：层启动即 `enabled:true`，健康停车许可独立判断；不直接复用标准 VoxelLayer 监督器的“层先禁用，健康后动态启用”逻辑，也不为此重写网格算法。具体数据源订阅控制与恢复流程要通过真实点云和地图更新验收。

### 5.2 参数设置成功不等于内部算法改变

此版本动态回调只处理部分 source 高度/视锥参数、层 `enabled` 与整数 `mark_threshold`；没有为 `voxel_decay`、`decay_model`、`voxel_size` 等实现运行中重新构造内部网格。调这些量采用启动配置与重新启动后核验，不能仅记录参数服务返回成功。[完整参数回调](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_layer.cpp#L810)

STVL 投影使用 `>= mark_threshold`，不同于标准 VoxelLayer 的严格 `>`。值 1 在 STVL 中可以由一个体素形成二维障碍，不能宣称沿用旧值后低障碍筛选语义不变。阈值是垂向体素计数，不能当作同一体素内点数去噪阈值。[STVL 投影比较](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_layer.cpp#L717)

### 5.3 线性、指数与视锥加速

线性模型 `decay_model:0` 返回 `voxel_decay - elapsed`，剩余量小于 0 后清除；指数模型返回正的 `voxel_decay × exp(-elapsed)`，视锥外同样采用小于 0 判定，因此不能把指数配置说明成保证在固定秒数后退出的 TTL。本轮优先线性模型。[时间公式](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_grid.cpp#L320)、[清除条件](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_grid.cpp#L167)

视锥加速量与 `acceleration_factor × elapsed³ / 6` 有关，还会改变保存的标记时间，所以残留时长不能简单写成固定 `voxel_decay`。先明确纯时间衰减行为，再判断是否需要加速；若配置使用加速，验收必须直接测退出时间、遮挡误清与重新标记情况。[加速公式](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_grid.cpp#L334)、[更新保存时间](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_grid.cpp#L176)

`min_z/max_z` 为传感器视锥近远界，不能与全局坐标中 `min_obstacle_height/max_obstacle_height` 混同。D435 的 FOV、近远界与原点要来自本机实际模式、内参、有效距离和外参，不复制教程的 R200/Astra 示例；`sensor_frame` 留空时使用点云头的 frame，显式指定时必须表达真实传感器测量原点和朝向。[缓存几何参数](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/measurement_buffer.cpp#L97)

### 5.4 observation 缓存与断流恢复

`observation_persistence:0` 只保留最新一条 reading，并不自动删除它；如果不消费后清空，旧 marking 数据会在后续地图循环重复标记，刷新网格中的当前标记时间，影响到期。`clear_after_reading:true` 会在读取后删除对应 buffer 内 reading；它不能替代外部监控点云接收间隔、时间戳年龄和诊断状态。[reading 缓存](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/measurement_buffer.cpp#L193)、[读取后清缓存](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_layer.cpp#L513)

clear-only source 还有固定版本边界：第 135～137 行提前返回，跳过第 188 行的 `_last_updated` 更新，也没有把传入 cloud 内容和时间戳填入 reading。`MeasurementReading` 默认构造已经分配空 PointCloud2，因此这里保留空云和默认时间戳；非零 persistence 分支按这个默认云时间戳判断陈旧，非零 `expected_update_rate` 又受未更新的 `_last_updated` 影响。若后续引入独立清障 source，必须另行核验这两项行为，不能据此替代健康门。本轮单 D435 保持 `marking:true`、`clearing:false`、persistence 为 0、读取后清缓存，视锥方案留到后续独立对照。[完整缓存实现](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/measurement_buffer.cpp#L90)、[reading 默认构造](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/include/spatio_temporal_voxel_layer/measurement_reading.h#L63)

每 source 的 SetBool 服务由 `source + "/toggle_enabled"` 构造，不能照抄 README 中旧 ROS 1 层 namespace 的服务路径。禁用某个 source 时调用 `ResetGrid()`，清空的是整个 STVL 历史体素，并非仅该 source；因此雷达与深度分层，失效先停车，再处理订阅/重置，恢复前等待有效新帧和地图周期。[服务构造](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_layer.cpp#L346)、[禁用与全层重置](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_layer.cpp#L447)

### 5.5 地图、体素尺寸与停车链

STVL 输出仍然受 `voxel_size` 量化；关闭输入 PCL 下采样不会恢复原始深度图的连续表面。最小 2 cm 目标需要核验体素落格、地面阈值和标障稳定性，不能仅因论文采用 5 cm 就照搬；缩小体素须同时量化 CPU、内存和更新耗时。[体素缩放](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/92896fe9ea994260bf34f1fa7b7735f3804cfc6f/spatio_temporal_voxel_layer/src/spatio_temporal_voxel_grid.cpp#L83)

Nav2 Humble 1.1.20 Collision Monitor 的失效源处理与新版文档不完全相同：source 缺失、过期或 TF 失败可以返回而不贡献点；不能仅依靠新版“source timeout 自动停车”的说明撤销本项目独立健康门。碰撞监测是速度链中的附加保护，地图衰减与保护停车须分别验收。[本机版本 Source](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_collision_monitor/src/source.cpp)、[本机版本主处理](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_collision_monitor/src/collision_monitor_node.cpp)

## 7. 与其他方案的取舍和验收指标

| 方案 | 工作方式 | 本轮取舍 |
|---|---|---|
| 标准 VoxelLayer | 有效终点射线穿过才清历史占用 | 保留旧实验入口和原始证据，用作同场景对照 |
| STVL | 稀疏体素加可控时间记忆，视锥可加速 | 优先：直接覆盖残留退出能力缺口，保留单相机短时记忆，复用 Nav2 插件 |
| NVL 2.3.1 | 每周期重建自己的层，再用 marking observations 标记 | 仅对照：记忆更弱，窄视野或短时测不到可能更快丢失真实障碍；仍需处理旧 observation 缓存和健康失效 |

NVL 重建图并不自动删除父类中的最新缓存点云；`observation_persistence:0` 时仍可重复使用旧数据。因此它不能直接被解释成“相机断流后地图会安全自动清空”。[NVL 固定实现](https://github.com/SteveMacenski/nonpersistent_voxel_layer/blob/4fbc4cb9a158e25a7d8199220e67d9984a653ce0/plugins/nonpersistent_voxel_layer.cpp)

本项目采用配置适配与现有健康门衔接，必要的自研只处理本机版本缺少的数据新鲜度、恢复状态和运动许可接口；薄诊断适配插件委托上游计算，不重写标障、衰减或体素存储算法。旧滤波、时间确认、标准 VoxelLayer 与底层测试入口保留；首轮不同时更换外参、传输模式、输入滤波与衰减模型，避免效果无法归因。

验收采用相同相机姿态、外参、时间域、障碍、速度限制与场景，分别记录：

- 撤障后最后一次新标记到三维体素、二维致命格、合并 costmap 清空的时间。
- 真实静止障碍持续保持率；短时深度无效、遮挡、视野外时的误清时长；重新可见后的标记延迟。
- 最小目标与细结构保留、空地误标频次；阈值改变不能只以黄点减少评价。
- 点云年龄和接收间隔、失效停车与恢复条件；地图变空不等于允许继续运动。
- STVL 更新时间、CPU、内存、发布延迟；点云可视化与实际二维地图分开评估。
- 移动车体时 TF/里程计连续性；没有合法 Odom 的手动移动不作为闭环导航结果。

调研与配置可用性属于离线证据，实物识别、真实障碍误清、撤障时长、掉线停车和闭环导航均须现场结果确认后，再决定是否提升为正式默认。


## 8. 现场测试前重复回归发现的生命周期竞争

2026-10-06 NAV-016-R1重复回归发现原导航预算用例在销毁RecoveryRuntime时卡住；固定同一用例重复执行，在GDB下第127轮复现，主线程等待NodeThread析构join，后台SingleThreadedExecutor仍等待ROS消息。该证据不指向STVL衰减算法。

本机Humble Nav2 1.1.20的[NodeThread固定源码](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_util/src/node_thread.cpp)构造启动spin线程，析构直接cancel后join；[本机rclcpp 16.0.21的spin实现](https://github.com/ros2/rclcpp/blob/16.0.21/rclcpp/src/rclcpp/executors/single_threaded_executor.cpp)进入spin时把spinning重新置true。如果取消先于spin启动，随后启动会丢失取消状态。这是结合线程栈与源码作出的本项目根因判断，不称为所有Nav2生命周期场景的通用结论。

适配仅在RecoveryRuntime构造返回前等待executor实际进入spinning，沿用上游执行器、取消和线程管理，不修改系统库。新增 `test_recovery_runtime_lifecycle_stress` 复用原真实对象用例连续200轮构造/销毁，30秒自动超时，隔离域215；结果归档NAV-016-R1。

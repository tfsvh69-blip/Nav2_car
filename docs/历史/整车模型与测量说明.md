## 一、当前模型覆盖范围

`carcar_description` 已依据 4 张实车照片、用户实测尺寸和 5 个毫米制 STL 建立完整的可运行整车结构，包含：

1. 下层金属双层底盘、四个电机、支柱、控制板和电池包。
2. 四个白色麦克纳姆轮，使用既有 Apache-2.0 开源网格并按实测尺寸缩放。
3. 蓝色顶板、两侧围护件和前部梯形保护罩，视觉使用用户导出的精确 STL。
4. Jetson 计算平台、保护壳、散热器、接口面和两根天线。
5. RPLIDAR A1 本体、底板、四根支柱和顶板固定件。
6. RealSense D435 系列本体、四个前部窗口和蓝色固定支架。
7. 用于运行的碰撞几何，以及 `base_footprint`、`base_link`、四轮、IMU、雷达和相机 TF。

模型文件按职责拆分：

| 文件 | 职责 |

| `src/carcar_description/urdf/carcar.urdf.xacro` | 整车组装入口 |
| `src/carcar_description/urdf/carcar_dimensions.xacro` | 全部确认尺寸和临时尺寸 |
| `src/carcar_description/urdf/carcar_materials.xacro` | RViz 材质 |
| `src/carcar_description/urdf/carcar_chassis.xacro` | 底盘、车体、Jetson 和四轮 |
| `src/carcar_description/urdf/carcar_sensors.xacro` | IMU、RPLIDAR、RealSense 和支架 |

## 二、数据来源与精度分级

### 已确认实测值

| 项目 | 数值 |
|---|---:|
| 轮子直径 | `60 mm` |
| 轮子宽度 | `31 mm` |
| 前后轮心距 | `120 mm` |
| 左右轮心距 | `185 mm` |
| 整车最大长度 | `235 mm` |
| 整车最大宽度 | `213 mm`；与轮组推导值 `216 mm` 有 `3 mm` 差异 |
| 整车最大高度 | `230 mm` |
| 最小离地间隙 | `10 mm` |
| 蓝色顶板 | `220 × 130 × 10 mm` |
| 蓝色顶板顶面离地高度 | `140 mm` |
| 雷达扫描中心（相对 `base_footprint`） | `(-50, 0, 217) mm` |
| RealSense 左红外中心（相对 `base_footprint`） | `(130, 33, 170) mm` |

`base_link` 比 `base_footprint` 高 `30 mm`，因此写入 URDF 的雷达坐标为
`(-0.050, 0, 0.187) m`，相机坐标为 `(0.130, 0.033, 0.140) m`。宽度冲突复核前，
碰撞/导航包络采用较保守的 `216 mm`，不删除用户的 `213 mm` 实测记录。

### 厂家机械资料

- Intel/RealSense D435、D435i 外壳尺寸为 `90 × 25 × 25 mm`；本体参数来自
  [D400 系列数据表](https://cdrdv2-public.intel.com/841984/Intel-RealSense-D400-Series-Datasheet.pdf)。
- RealSense ROS 驱动规定 `camera_link` 原点位于左红外相机（Infra1），坐标为 X 前、
  Y 左、Z 上；相机内部静态 TF 由驱动发布，依据
  [realsense-ros 官方说明](https://github.com/realsenseai/realsense-ros/blob/ros2-master/README.md)。
- RPLIDAR A1 Dev Kit 最大外廓采用 `96.8 × 70.3 × 55 mm`，资料入口及厂家 STL/IGS 下载见
  [SLAMTEC 官方支持页](https://www.slamtec.com/en/support)。厂家 CAD 未发现明确再分发许可，
  因此仓库只按机械尺寸自建轻量几何，不复制该 CAD。
- Jetson P3768 参考载板采用 `100 × 79 mm`；照片里的蓝色外壳、散热器和安装位仍按临时值
  表示，不把载板规格等同于实车外壳尺寸。

### 仍待确认的参数

IMU 原点和轴向、雷达 yaw、相机 roll/pitch/yaw、Jetson 外壳细节，以及所有质量、重心和
惯量仍是临时值。它们集中写在 `carcar_dimensions.xacro`，不得用于以下结论：

- Nav2 footprint 和 inflation 半径验收；
- 雷达点云前后/左右方位验收；
- D435 点云、AprilTag 位姿或自主充电标定；
- IMU 轴向、重心、惯量、动力学或仿真验收。

## 三、SolidWorks 源文件与 STL 接入结论

用户提供的 5 个 `.SLDPRT` 是重要设计源文件，原件保持不变：

- `深度相机底部支架.SLDPRT`
- `深度相机直接架子.SLDPRT`
- `激光雷达底板.SLDPRT`
- `英伟达的下置底板.SLDPRT`
- `顶部激光雷达和深度相机的支架.SLDPRT`

当前 Linux 环境不能可靠展开 `.SLDPRT` 的高熵封装内容。用户随后从原设计软件导出了 5 个
Binary STL；已验证它们是有效三角网格、单位为毫米，并复制到
`src/carcar_description/meshes/vehicle/`：

| 安装文件 | 三角面数 | STL 外廓/mm |
|---|---:|---:|
| `carcar_upper_structure.stl` | 3918 | `218 × 130 × 130` |
| `lidar_mount_plate.stl` | 1966 | `163.959 × 5 × 69.5` |
| `camera_lower_mount.stl` | 1560 | `69 × 60 × 50` |
| `camera_direct_mount.stl` | 9574 | `85 × 20 × 60` |
| `jetson_lower_mount.stl` | 188 | `120 × 22 × 110` |

STL 只替换对应 `<visual>`，碰撞体继续使用轻量 box/cylinder；本轮未改写用户设计源文件。
当前参考目录可见 5 个中文 STL，SLDPRT 需在用户设计端另行保留。安装变换、原名和 SHA-256 见
`src/carcar_description/meshes/vehicle/README.md`。若以后继续编辑，建议同时导出 STEP
AP214/AP242 用于精确尺寸核对，并记录车头与朝上方向。

## 四、实测坐标基准

1. 车头是蓝色前罩带“前”字、RealSense 镜头所朝的一侧，为 `+X`。
2. 人站在车尾面向车头时，左手侧为 `+Y`，上方为 `+Z`。
3. `base_link` 的 X/Y 原点是前后轮心中线与左右轮心中线的交点，Z=四个轮轴中心高度。
4. `base_footprint` 是 `base_link` 垂直投影到地面的点；已确认其相差 `30 mm`。
5. 所有位置先量到毫米，角度先记到度；写入 Xacro 时再换算为米和弧度。

## 六、IMU 原点与板轴确定方案

位置和轴向必须分开确定：运动数据可以确定轴的排列与符号，但不能反推出芯片在车上的
物理坐标。现有照片中控制板被结构遮挡，也看不清芯片丝印，因此 `imu_xyz=0 0 0.030` 和
`imu_rpy=0 0 0` 继续作为显式临时值。

1. 断开电机电源和整车主电，露出 Rosmaster 控制板；拍一张垂直俯视高清照片，画面同时
   包含 IMU 芯片/板上轴箭头、车头标记和毫米尺。若能看到 `MPU9250` 或 `ICM20948` 丝印，
   一并记录。不要只拍芯片局部，否则无法建立车体方向。
2. 以四轮轮心矩形中心为 X/Y 原点，量“芯片封装中心”向车头的 X、向左的 Y；再量芯片
   封装中心离地高度，减去 `30 mm` 得到相对 `base_link` 的 Z。精度记录到约 `±2 mm` 即可。
3. 按仓库规定首先水平静止 30 秒统计角速度均值/标准差，再手动水平逆时针旋转确认 Z 轴
   正号，随后恢复水平检查 `ax≈0、ay≈0、az≈+9.81`。接着用稳固支撑分别抬高车头、左侧
   约 20～30°并静止采样；车体 X、Y 加速度分量应分别变正，Z 分量仍为正，无须整车竖放。
   使用 Python 标准库统计和现有 ROS 订阅即可满足此次轴向观测，未另引入融合框架。
4. 如果输出落在其他轴或符号相反，根据这四组数据建立唯一的轴置换/符号矩阵；修正在驱动
   映射或 `imu_link` 安装 TF，不在 EKF 中补救。未通过前，IMU 只发布观察，不参与融合。

观察器只统计消息的 `frame_id` 原坐标系，不自动应用 TF。若采用安装 TF 修正，原话题
数值不会随 TF 修改而变化，必须在转换到车体坐标后判断上述期望；加速度与角速度分别
核对，不能用一个旋转掩盖协议中两种数据不一致的符号映射。

厂商库对 MPU9250 和 ICM20948 原始帧存在不同的陀螺仪符号处理，因此不能只照抄芯片手册
推定 ROS 输出方向，必须以这四个实物动作为最终依据。完整执行命令和记录表见
`docs/测试记录.md` 的 `IMU-002`。

## 七、完整构建、启动、观察与停止

构建与离线检查：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
export PATH=/opt/ros/humble/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
source /opt/ros/humble/setup.bash
xacro src/carcar_description/urdf/carcar.urdf.xacro > /tmp/carcar_model.urdf
check_urdf /tmp/carcar_model.urdf
/usr/bin/colcon build --symlink-install --packages-select carcar_description
/usr/bin/colcon test --packages-select carcar_description --event-handlers console_direct+
/usr/bin/colcon test-result --verbose
source install/setup.bash
```

启动模型，不访问串口和执行器：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 node list
ros2 launch carcar_description view_model.launch.py
```

另开终端逐项观察，命令得到稳定输出后按 `Ctrl+C`：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run tf2_ros tf2_echo base_footprint base_link
ros2 run tf2_ros tf2_echo base_link front_left_wheel_link
ros2 run tf2_ros tf2_echo base_link laser_frame
ros2 run tf2_ros tf2_echo base_link camera_link
```

停止时关闭 RViz2并在 launch 终端按 `Ctrl+C`，再确认本入口没有残留进程：

```bash
cd /home/jetson/luhao/my_nav_carcar
conda deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 node list
pgrep -af '[c]arcar_model_rviz|[m]odel_joint_state_publisher|[r]obot_state_publisher' || true
```

本测试不打开串口、不驱动电机，因此没有执行器运动风险；若现场同时在做电机测试，仍应先
完成停车、关闭电机电源，并保证桌面上的 USB/电源线不会缠绕车轮，再进行模型目视比对。

## 现场问题

- 用户重新运行键盘程序后，相机明显转动至140.5°，确认该目标确实平视。底盘驱动旧实现没有发送 S1 初始化命令。“此前未使能”是用户描述；协议没有扭矩/角度反馈，不能确认当时的电气状态。
- 此前 TF 连通检查未先验证实物到达约定平视姿态。地面拟合约-6.49°候选可能包含未初始化姿态的影响，退出当前复测入口，保留文件与证据。恢复140.5°后重新测量。
- 小盒子曾被高度过滤剔除，当时加载俯仰候选后有蓝点及黄色体素；这不证明恢复平视后的外参准确。
- 黄色层曾关闭，现两个独立静止配置均默认启用。黄色体素已实际出现。
- 移走盒子后部分体素约5秒内清除，部分残留；空地还有孤立体素。地面误标、深度噪声及射线覆盖不足均待核查，不能将所有黄色点认定为假障碍。

## 本轮修复与边界

既有 Python 串口适配器在启动零运动后发送 S1 板端94°，对应140.5°目标的既有量化值。原厂函数本项目补丁返回完整串口写入是否成功，失败中止启动；成功不代表 MCU 确认或舵机到位。原独占串口键盘入口保留。

新增 C++ `camera_servo_state` 根据已发送档位发布关节命令估计：`(board-94)×1.5°`。94档为平视零位，95档为低头约1.5°，支架与相机绕现有轴同时转动，光心位置也变化。部分1°按键量化后仍是同一档。模型不模拟实际运动过程；无到位、扭矩或断电反馈。

静止相机查看入口默认开启动态调试；正式导航仍使用平视固定 TF，启动平视命令是前提。预览轮角通过 joint_state_publisher 合并相机估计。动态模型用于静止调试，不能当作移动深度避障验收。

## 下一步

1. 清空支架活动空间，停止地图、导航及旧串口程序，按手册构建与重启。初始化可能使相机大角度转动。
2. 仅启动底盘，确认自动回到平视和已发送档位94；停止底盘后，再用独占键盘入口验证模型加减角与回零。底盘与键盘不能同时占串口。
3. 固定140.5°并等实物停稳，用默认零俯仰外参重测地面、箱子左右与多距离、雷达共同面。暂不使用旧-6.49°候选。
4. 姿态确认后重启静止地图，对照原始、障碍、清障点云与残留体素坐标/时间，并核对二维致命代价值，判断持续误标还是射线没有经过。
5. 重复盒子放置/移除，记录残留数量和消失时间；稳定真实障碍应保留。清障候选参数需在新姿态下重测，之后安排移动测试。

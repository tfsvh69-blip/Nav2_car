# 控制板 V3.6 闭环固件适配

本目录只保存本项目编写的补丁，不包含 Yahboom 的控制板源码、编译产物或可刷写固件。

## 目的

当前实车端口为 M1=左前、M2=右后、M3=右前、M4=左后。原厂麦克纳姆闭环代码把四个
车轮速度按 `L1, L2, R1, R2` 直接写入 M1、M2、M3、M4；这与当前端口顺序及编码器方向
不匹配。补丁在进入板内四路 PID 前，将逻辑轮速转换为当前端口的速度目标：

`M1=-L1, M2=+R2, M3=-R1, M4=+L2`。

这样仍由控制板执行四路编码器 PID；ROS 侧继续只发送 `vx`、`vy`、`wz`。

## 对应厂商包

- 文件：`ROS-Driver-Board-FW-master.zip`
- SHA-256：`3d7a6e1c762bdd42dad81468cd34d6907847ab8ebb03abb16024d888a4f0687e`
- 已读到的控制板版本：`3.6`
- 厂商包中同时提供：`rosmaster_V3.6.5.hex`
- 上游源码：`ros-driver-board-fw/Source/APP/app_mecanum.c` 与
  `ros-driver-board-fw/Source/APP/config.h`

厂商包的许可证尚未在本仓库确认，因此不纳入源码树。厂商文件为 CRLF 换行；补丁前须先
仅将这两个待改文件转换为 LF，再在解压后的 `ros-driver-board-fw` 目录执行 `patch -p1`
应用。该换行转换不改变 C 代码语义。

## 验证和刷写边界

补丁已做静态审查：前进、左横移、逆时针旋转的端口目标分别与已确认的原始编码器符号
`[-,+,-,+]`、`[+,-,-,+]`、`[+,+,-,-]` 一致。尚未用 Keil 编译，也未刷写实车，不能称为
实机通过。

刷写会覆盖控制板程序，且需要可用的 STM32 下载模式、烧录工具和原厂 V3.6.5 `hex` 作为
恢复文件。刷写前必须先完成补丁编译、二进制备份、架空轮测试方案与恢复验证；在这些条件
具备前，不得向控制板刷写本补丁。

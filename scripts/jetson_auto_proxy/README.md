# Jetson本地自动代理

保持本机HTTP入口`127.0.0.1:17892`，C++17实现；不启动ROS或硬件。旧`~/.local/bin/jetson-auto-proxy.py`保留，部署后仅停用其服务入口。

完整构建、测试、部署、观察与回滚统一见[操作手册37.1](../../docs/操作手册.md#jetson-auto-proxy-hardening)。测试证据见NET-002-R1及`log/net002_proxy_20261020/`。源码、配置与测试不读取Codex凭据。

2026-10-30 长连接故障排查及本次稳定性配置、部署和回滚见[操作手册37.2](../../docs/操作手册.md#jetson-auto-proxy-stability-20261030)。

## 行为与边界

- 后台并行探测候选，默认每轮结束15秒后再检查；单次总超时4秒。通过指定HTTP代理完成系统CA与主机名校验，对固定HTTPS地址HEAD，只有200或401算健康。检查没有认证头、不发推理请求、不跟随跳转。403、只回CONNECT200、TLS错误均不算健康。
- 默认检查地址为OpenAI API模型列表。这是联网检查，不是账号权限、真实推理、WebSocket或所有网站的验收。局部目标失败不一定是全局代理故障，业务TLS始终由客户端端到端校验，本工具不解密业务流量。
- `probe_failure_threshold` 默认3，允许1～10；1恢复单次网络探测失败即下线。只有之前经过完整HTTPS验证且仍可用的候选，才容忍连续少于阈值的网络超时、连接失败或TLS握手中断；状态显示`DEGRADED`及失败计数。达到阈值后下线，成功验证清零并恢复。首次未验证、证书/CA校验失败、代理认证失败或意外HTTP状态不享有容忍；实际业务连接建立失败仍立即冷却。该防抖只影响新连接选择，不修复已有连接中断，也不取消客户端证书验证。
- IPv4默认路由网关按metric排序、去重后尝试6880，再按配置顺序保留固定候选。多默认路由重新发现，普通路由器未开放代理会被健康检查排除。不提供IPv6上游、SOCKS转换、自动发现任意局域网代理或认证代理配置。
- 网络探测不持有请求选择锁。启动尚未验出候选、全部失效或结果过期时快速503，不随每个请求重新探测。客户端可自行重试；无直连外网兜底。
- 建立TCP失败或CONNECT建立前的网络失败会将候选按`cooldown_ms`冷却（程序默认15秒，实机值见操作手册37.2），并尝试本次列表里的其他健康候选；旧探测不能覆盖较新的失败。恢复且检查通过后自动恢复原优先级。预期恢复时间取决于当前轮与探测耗时，不承诺瞬时切换。
- 对特定目标CONNECT非200可换候选；407/5xx/无有效状态码同时标记全局冷却，其他4xx只影响本次请求。所有候选失败返回502；不回放已经送出的明文HTTP请求、业务TLS或在途请求。
- TCP转发双向各64KiB有界缓冲、支持背压与半关闭，无180秒空闲断开计时；上游TCP启用keepalive（60/20/3秒）。已有连接无法搬迁到另一个上游，故障时仍可能需要应用重连。对端、网络或应用仍可自行超时。
- 单客户端读请求头最长5秒，头部最多64KiB；最多48个并行客户端，超额立即关闭连接。状态查询也占一个连接。网关最多24个候选，固定候选最多16个。不会无限新增线程或缓冲。
- `--status`读取运行服务的缓存、结果年龄、冷却与当前优先候选；`--probe`是独立新探测，不会修改运行服务缓存。SELECTED表示下一连接的优先候选，不表示所有已有连接都使用它。
- 服务日志为健康变化、短暂降级和冷却事件记录带时区的本机时间戳，便于与应用日志对齐；日志只含代理端点、探测状态与错误码，不记录业务请求内容或认证信息。
- `--no-proxy`根据当前UP网卡生成列表：保留旧明确端点、主机名，加入本机与网关；对RFC1918私网且子网不大于/24的网卡枚举整个子网，兼容不识别CIDR的旧客户端。更大子网只补本机/网关，不枚举海量地址，不声称整段直连。新shell重新计算，旧进程与既有systemd环境不自动改变；用户服务的缓存环境部署时同步，换网后按手册刷新。

## 复用与维护取舍

使用本机Ubuntu包libcurl `7.81.0-1ubuntu1.27`（curl许可，MIT风格）和其系统TLS后端；测试额外使用OpenSSL `3.0.2-0ubuntu1.29`（Apache-2.0）。它们是此次实际构建依赖，不要求锁死系统安全更新。未复制第三方实现；接口按7.81可用能力编写。

调研来源：[libcurl代理配置](https://curl.se/libcurl/c/CURLOPT_PROXY.html)、[证书验证](https://curl.se/libcurl/c/CURLOPT_SSL_VERIFYPEER.html)、[线程约束](https://curl.se/libcurl/c/threadsafe.html)、[curl许可](https://curl.se/docs/copyright.html)、[HAProxy健康检查](https://www.haproxy.com/documentation/haproxy-configuration-tutorials/reliability/health-checks/)。HAProxy是成熟备选，但本机未安装，动态网关候选和旧curl绕过列表仍需额外适配；本次采用小型C++适配层复用系统libcurl，避免增加需安装的常驻服务。代价是本项目需维护选择、转发和边界回归，不将其称为工业认证代理。

修改转发或并发后必须运行C++回归；修改空闲策略后运行185秒本地空闲回归。不能用离线替身通过代替平板锁屏、跨网、重启和真实业务请求验收。

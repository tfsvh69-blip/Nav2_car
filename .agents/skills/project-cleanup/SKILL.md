# 项目清理

目标是减少维护负担并保持功能，不以删除文件数为目标。读取仓库AGENTS和当前项目路线；完整命令唯一入口为[操作手册34节](../../../docs/操作手册.md#34-项目瘦身检查点与恢复maint-001)，现行事实以硬件台账和测试记录为准。

## 1. 保全与范围

- 默认先交报告，不批量删除或大改代码。用户已批准的本次清单直接推进，不重复索要授权；新增范围或不可逆动作单独说明。
- 先检查Git暂存/未暂存/未跟踪及ignored内容、活动进程、可用磁盘。完整快照放仓库外，覆盖未提交文件和必要资源，保存HEAD、二进制patch、文件清单与SHA256；不通过stash/reset/自动commit覆盖用户工作。
- 完成标准：备份可校验，初始状态可还原到新目录；明确符号链接未追随的仓库外资源及正在运行的依赖。

## 2. 扫描报告

- 按同一口径统计文件/链接、源码物理行、当前/历史Markdown、目录占用；上游、生成产物与自有源码分列。记录工具版本、失败和覆盖边界。
- 分类为确定无用、疑似无用、必须保留。可再生不等于当前可删除：install/build可能是活动进程的执行文件或资源链接目标；log可能是失败原始证据。
- 保护地图、标定/TF、URDF/网格、参数/RViz、rosbag、厂商源码/许可证和已用底层测试。日期、candidate、ignored、只被测试调用均不是删除依据。
- 完成标准：每个拟变更对象有具体路径、调用/保留证据、收益、验证与恢复办法。疑似项只提建议。

## 3. ROS调用核实

删除代码前同时检查CMake目标/安装/glob、package.xml、setup.py的console_scripts、XML/旧Python Launch、行为树插件库、pluginlib/class_loader注册、资源索引与参数字符串。全文搜索未命中不足以证明无用；框架回调、虚函数、跨翻译单元与测试宏尤其容易误报。

逐项记录静态分析告警的真实调用关系；工具崩溃、宏解析失败或缺少compile_commands时，标记分析不完整，不登记为通过。完成标准是候选已有可复核结论，未确认项继续保留。

## 4. 文档与小批实施

- 当前文档各司其职：索引、路线/架构/决策、硬件事实、有效操作、测试结论、长期取舍；历史统一docs/archive，保留失败/测量/解决经验，更新相对链接、锚点和原编号入口。
- 合并重复表述前先保留原文或原始结果，验证迁移内容和代码块未丢失。精简AGENTS时给出旧规则到新位置映射，保留安全、语言、机器归属与证据约束。
- 每批只做一个维护目的；优先内部函数/重复工具边界，不同时改变参数、接口、默认值与功能。新逻辑遵守项目C++/XML约定。
- 修改后构建对应包并运行相关测试；工具输出须对照同一输入。缺少原bag、硬件或其他验证前提时保留建议，不删除或伪称行为不变。
- 清缓存按已批准逐文件清单重新核对哈希，只移除匹配项；保留构建/安装/日志。发生清单变化或验证失败，停止依赖该结果的后续批次并保留证据。
- 完成标准：本批清单、回滚路径、实际验证结果明确；无执行器或网络隐式启动。

## 5. 结算

生成前后同口径指标及所有删除/移动/合并/修改路径。证明受保护源码/配置/资源哈希保持或解释批准的差异；区分减少当前阅读负担与减少总磁盘量，不把移动归档或仓库外备份算成“空间节省”。

报告存docs/archive，测试统一登记测试记录，命令维护手册。说明完成、保留、验证、未确认项与下一步；恢复仅解包到新目录，不覆盖当前未提交工作区。

本技能源自2026-10-14用户批准的项目维护流程；具体历史结果见[执行记录](../../../docs/archive/2026-10-14-瘦身执行结果.md)。流程可独立执行，不要求安装外部refactor技能或联网。
